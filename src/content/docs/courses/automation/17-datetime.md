_타임스탬프·시차·기간 계산 — 스케줄링과 로그의 토대._

:::note[학습 목표]
- 타임스탬프를 읽고, 두 시각의 차이(기간)를 계산하고, 시차를 반영해 '내 시간'으로 변환할 수 있다.
:::

> 오전 9시 미팅이 뉴욕에선 몇 시일까? 로그에 찍힌 '2024-06-01T14:30:00Z'는 우리 시간으로 언제일까? 날짜·시간을 다룰 줄 알면 스케줄링, 알림, 기록 분석이 전부 쉬워진다.

## 이 레슨에서 만드는 것

타임스탬프를 읽고, 두 시각의 차이(기간)를 계산하고, 시차를 반영해 '내 시간'으로 변환할 수 있다.

## 핵심 개념

컴퓨터는 시간을 '숫자'로 봐. 특히 UTC(세계 표준시)라는 기준 시계를 하나 정해두고, 각 나라는 거기서 몇 시간 더하거나 빼서 자기 시간을 만들어. 마치 전 세계가 하나의 큰 시계(UTC)를 보면서, 한국은 '+9시간', 뉴욕은 '-4시간' 안경을 쓰고 보는 것과 같아. 그래서 시간을 다룰 땐 항상 '이 시각이 어느 기준(시간대)이냐'를 먼저 확인하는 게 핵심이야.

### 왜 작동하는가

AI는 전 세계 수천만 개의 타임스탬프와 시간대 데이터를 학습해서, UTC 기준을 안경처럼 쓰고 벗으며 계산해줘요. 그래서 당신은 '시각 + 시간대'만 정확히 알려주면, 서머타임까지 챙긴 변환·기간 계산은 AI가 대신 해줍니다.

## 👀 따라하기 예시

서울 본사와 뉴욕 지사가 화상회의를 잡아야 해요. 서울 시간 오전 9시가 뉴욕에서는 몇 시인지, 그리고 로그에 찍힌 '2024-06-01T14:30:00Z'는 우리 시간으로 언제인지 확인해야 하는 상황. 제가 먼저 해볼게요, 눈으로 따라오세요.

### 1. ① 타임스탬프에서 기준부터 찾기

**실제 결과**

```text
2024-06-01T14:30:00Z → 끝의 Z를 보고 '아, 이건 UTC 기준이구나'라고 확인
```

> Z가 없으면 반쪽짜리 정보예요. 항상 기준부터 찾는 게 첫 습관.

### 2. ② AI에게 변환 요청하기(서울 → 뉴욕)

**실제 결과**

```text
'서울 시간 오전 9시는 뉴욕(EDT) 몇 시야?' → AI: '전날 오후 8시입니다(서울이 뉴욕보다 13시간 빠름, 서머타임 적용 중)'
```

> 시간대 이름(EDT)까지 콕 집어 물으면 AI가 서머타임까지 자동 반영해요.

### 3. ③ UTC 로그 시각 변환하기

**실제 결과**

```text
14:30 UTC + 9시간 = 23:30 → '한국 시간 6월 1일 밤 11시 30분입니다'
```

> 더하기만 하면 끝. 대신 24 넘으면 날짜가 넘어가는 거 잊지 않기.

### 4. ④ 결과가 상식적인지 검증하기

**실제 결과**

```text
한국-뉴욕 시차 13~14시간 범위 안에 있나 확인 → '네, 13시간 차이 맞습니다'
```

> AI도 가끔 틀려요. 감으로 한 번 더 체크하는 습관이 진짜 실력.

### 완성 결과

두 도시의 정확한 시차와 변환된 현지 시각. 좋은 결과의 기준: (1) 시간대 이름이 명시돼 있는가 (2) 서머타임 여부가 반영됐는가 (3) 시차가 상식 범위(예: 한-뉴욕 13~14시간) 안에 있는가.

## 단계별 따라하기

### 타임스탬프 읽는 법 익히기

표준 형식 'YYYY-MM-DDTHH:MM:SSZ'를 왼쪽부터 읽어. T는 날짜와 시간을 나누는 구분선, 끝의 Z는 'UTC(세계 표준시) 기준'이란 표시야. Z가 있으면 무조건 UTC.

**복사·실행 예시**

```text
2024-06-01T14:30:00Z → 2024년 6월 1일 오후 2시 30분, UTC 기준
```

### 내 시간대로 변환하기

한국은 UTC+9. 그래서 UTC 시각에 9시간을 더하면 한국 시간이야. 챗GPT나 계산기에 물어봐도 되고, 손으로 더해도 돼. 24를 넘으면 날짜가 하루 넘어감을 기억해.

**복사·실행 예시**

```text
14:30 UTC + 9시간 = 23:30 → 한국 시간 6월 1일 밤 11시 30분
```

### 두 시각의 기간(차이) 계산하기

단, 두 시각이 같은 기준(둘 다 UTC거나 둘 다 한국시간)인지 먼저 확인! 기준이 다르면 하나를 먼저 변환한 뒤 빼야 해. 큰 시각 - 작은 시각 = 걸린 시간.

**복사·실행 예시**

```text
시작 09:00, 끝 11:45 → 2시간 45분 걸림
```

### AI에게 시켜 실수 없이 처리하기

chat.openai.com 또는 gemini.google.com에 접속. 시각 두 개와 각각의 시간대를 알려주고 변환·계산을 요청해. 반드시 '몇 시간대인지'를 명시해야 정확해.

**복사·실행 예시**

```text
'서울 시간 오전 9시는 뉴욕(EDT) 몇 시야?'라고 질문 → 오후 8시(전날) 답변
```

### 결과 검증하기

AI 답이 나오면 '시차가 상식적인가' 한 번 확인해. 한국-뉴욕은 보통 13~14시간 차이. 답이 그 범위를 벗어나면 시간대를 잘못 넣었을 가능성이 커. 다시 물어봐.

**복사·실행 예시**

```text
한국-뉴욕이 3시간 차이로 나오면 → 시간대 지정 오류, 재확인
```

## 흔한 실수와 교정
- **실수:** 시간대를 안 밝히고 '9시'라고만 말함
  - **교정:** 항상 '어느 도시/기준의 9시'인지 붙여라. 시간대 없는 시각은 반쪽짜리다.
- **실수:** 기준이 다른 두 시각을 그냥 빼서 기간 계산
  - **교정:** 먼저 둘을 같은 기준(예: 둘 다 UTC)으로 맞춘 뒤 빼라.
- **실수:** 24시를 넘겨 날짜 바뀌는 걸 놓침
  - **교정:** 더한 결과가 24 이상이면 24를 빼고 날짜 +1일 해라. 밤늦은 시각 변환 시 특히 주의.
- **실수:** 서머타임(여름철 1시간 당김)을 무시
  - **교정:** 미국·유럽은 계절별로 시차가 바뀐다. AI에 물을 때 '여름/겨울 기준'인지 날짜를 함께 줘라.

## 완료 체크리스트

- 각 시각에 시간대(기준)를 명시했는가
- UTC↔한국은 +9시간을 적용했는가
- 기간 계산 전 두 시각의 기준을 통일했는가
- 24시 초과 시 날짜 변경을 반영했는가
- AI 답의 시차가 상식 범위인지 검증했는가

## 도구

- ChatGPT(chat.openai.com) — 시간대 변환·기간 계산 질문
- Google Gemini(gemini.google.com) — 다중 도시 시각 표 정리
- timeanddate.com/worldclock — 세계 각 도시 현재 시각·시차 확인
- 구글 검색창 '9am seoul to new york' — 즉석 시간대 변환

## 참고 답안

03:00 UTC + 9시간 = 12:00 → 서울 시간 12월 25일 낮 12시. 서울 오후 6시(겨울철) → 런던은 서머타임이 끝난 GMT 기준이라 서울보다 9시간 느림 → 오전 9시.
