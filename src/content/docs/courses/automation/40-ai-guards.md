_LLM 자동화의 비용 폭주·품질 저하·환각을 검증·차단하는 안전 게이트._

:::note[학습 목표]
- 이 레슨이 끝나면, 내 LLM 자동화에 비용 상한·품질 검사·환각 차단 3중 가드를 직접 붙여 폭주와 헛소리를 자동으로 막을 수 있습니다.
:::

> 새벽 3시, 잘 돌던 자동화가 무한 루프에 빠져 API 청구서가 하룻밤 새 47만 원이 찍혔다는 이야기는 농담이 아닙니다. LLM 자동화는 '켜두면 알아서'가 아니라 '가드를 걸어둬야 안전'합니다.

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 내 LLM 자동화에 비용 상한·품질 검사·환각 차단 3중 가드를 직접 붙여 폭주와 헛소리를 자동으로 막을 수 있습니다.

## 핵심 개념

LLM 자동화의 사고는 거의 항상 세 갈래로 옵니다. 비용 폭주(루프·재시도·긴 프롬프트로 토큰이 눈덩이처럼 불어남), 품질 저하(모델 응답이 형식을 어기거나 빈 값을 뱉음), 환각(그럴듯하지만 사실이 아닌 내용을 자신 있게 생성). 이 셋은 '사람이 지켜보다 발견'하는 게 아니라, 실행 경로에 자동 게이트를 심어 '통과 못 하면 멈추게' 설계해야 합니다. 예를 들어 콜센터 요약 봇이 없는 통화 내용을 지어내면 고객에게 그대로 나가기 전에 '근거 문장이 원문에 있는가'를 기계적으로 검사해 차단하는 식입니다. 핵심은 신뢰가 아니라 검증입니다.

### 왜 작동하는가

AI 자동화는 브레이크 없는 자동차와 같아요. 액셀(실행)은 잘 밟는데, 멈추는 장치가 없으면 루프 한 번에 비용이 눈덩이처럼 불어나거나 엉뚱한 결과가 그대로 발행돼 버립니다. 그래서 '믿고 맡기기'가 아니라 '숫자로 재고, 형식으로 걸러내고, 원문과 대조'하는 기계적 체크포인트를 실행 경로 중간중간에 심어두는 거예요. 사람이 매번 지켜보지 않아도, 가드가 대신 지켜봐 주는 구조입니다.

## 👀 따라하기 예시

블로그 초안을 자동 생성하는 봇이 있다고 해볼게요. 이 봇에 3중 가드를 붙이는 과정을 제가 처음부터 끝까지 보여드릴게요. 눈으로 따라오세요!

### 1. ① 먼저 비용 상한부터 겁니다

**실제 결과**

```text
if (callCount > 20 || estUsdCost > 2) { throw new Error('BUDGET_GUARD: 상한 초과, 중단'); }
```

> 재시도 루프가 돌아도 20번·2달러에서 강제로 멈추니, 새벽에 무한루프가 나도 청구서 폭탄은 없어요.

### 2. ② 결과물이 제대로 된 형식인지 스키마로 검사합니다

**실제 결과**

```text
const R = z.object({ title: z.string().min(5), body: z.string().min(200) });
const parsed = R.safeParse(output);
if (!parsed.success) sendToReviewQueue(output);
```

> 제목이 없거나 본문이 텅 빈 초안이 그대로 발행되는 대신, 사람 검토 큐로 빠지니 사고를 막아요.

### 3. ③ 핵심 숫자·주장이 원문에 진짜 있는지 대조합니다

**실제 결과**

```text
// 초안에 "매출 3억"이라는 문장이 있다면
if (!/3\s*억|300,?000,?000/.test(원문)) {
  flag = 'UNVERIFIED_NUMBER'; // 발행 전 제거
}
```

> 그럴듯해 보여도 원문에 없는 숫자면 자동으로 걸러지니, '그럴듯한 거짓말'이 독자에게 나가지 않아요.

### 4. ④ 일부러 터뜨려서 가드가 진짜 작동하는지 확인합니다

**실제 결과**

```text
테스트1: 호출 999회 강제 → 20회에서 BUDGET_GUARD 발동 ✅
테스트2: title 빈 값 응답 → 리뷰 큐로 이동 ✅
테스트3: 가짜 "5억" 삽입 → UNVERIFIED_NUMBER 플래그 ✅
```

> 가드는 넣기만 하고 테스트 안 하면 없는 것과 같아요. 실패를 억지로 만들어봐야 진짜 안전한지 압니다.

### 완성 결과

3중 가드(비용 상한·스키마 검증·근거 대조)가 실행 경로에 박혀 있고, 3가지 실패 시나리오를 모두 통과한 자동화 코드. 좋은 결과의 기준: (1) 한도를 넘으면 무조건 멈춘다 (2) 형식이 깨지면 절대 그대로 발행되지 않는다 (3) 원문에 없는 숫자·주장은 자동으로 걸러진다.

## 단계별 따라하기

### 1단계 — 사고 3종을 내 자동화에 대입 (5분)

내가 돌리는(또는 만들려는) 자동화 하나를 종이에 적고, 비용/품질/환각 각각이 '여기서 터지면 어떤 모습일까'를 한 줄씩 쓴다. 최악의 손해액도 숫자로 적는다. 🙋나

**복사·실행 예시**

```text
자동화='블로그 초안 생성 봇'. 비용=재시도 루프로 토큰 10배 → 월 30만원. 품질=제목 없는 빈 초안 발행. 환각=존재하지 않는 통계·논문 인용.
```

### 2단계 — 비용 상한(하드 리밋) 걸기 (10분)

실행마다 토큰/호출 횟수를 세는 카운터를 넣고, 임계치를 넘으면 즉시 throw로 중단하도록 코드 앞단에 가드를 둔다. 동시에 API 제공자 콘솔에서 월 예산 알림·상한도 설정한다. 🤝함께

**복사·실행 예시**

```text
if (callCount > 20 || estUsdCost > 2) throw new Error('BUDGET_GUARD: 상한 초과, 중단'); + OpenAI/Anthropic 콘솔 → Billing → Usage limits에 월 50달러 hard cap.
```

### 3단계 — 출력 스키마 검증으로 품질 게이트 (10분)

모델에 JSON 형식을 강제하고, 받은 결과를 zod/JSON schema로 파싱한다. 필수 필드가 비었거나 형식이 틀리면 1회만 재시도, 또 실패하면 사람 큐로 보낸다(발행 금지). 🤖A로 스키마 코드 생성, 🙋나가 필수 필드 결정

**복사·실행 예시**

```text
const R = z.object({title:z.string().min(5), body:z.string().min(200)}); const p = R.safeParse(out); if(!p.success){ retryOnce() ?? sendToReviewQueue() }
```

### 4단계 — 환각 차단: 근거 대조(grounding) (10분)

요약·추출처럼 원문이 있는 작업은, 모델이 만든 핵심 주장/숫자가 원문에 실제로 있는지 문자열·정규식으로 대조한다. 없으면 그 문장을 버리거나 '원문 미확인'으로 표시한다. 사실 생성 작업은 출처 URL을 함께 뱉게 하고 링크가 200 응답인지 확인. 🤝함께

**복사·실행 예시**

```text
요약에 '매출 3억'이 있으면 원문에서 정규식 /3\s*억|300,?000,?000/ 검색 → 매칭 0건이면 해당 문장 제거 + flag='UNVERIFIED_NUMBER'.
```

### 5단계 — 킬 스위치 + 로그·알림 (10분)

환경변수 하나로 전체 자동화를 즉시 끌 수 있게 하고(AUTOMATION_ENABLED=false면 no-op), 가드가 발동할 때마다 Slack/이메일로 사유·건수를 남긴다. 매일 '차단 몇 건/비용 얼마' 요약을 받는다. 🙋나

**복사·실행 예시**

```text
if(process.env.AUTOMATION_ENABLED!=='true') return; ... catch(e){ notifySlack('GUARD 발동: '+e.message+', 오늘 누적비용 '+todayUsd+'달러') }
```

### 6단계 — 실패 시나리오 3개 직접 터뜨려 검증 (10분)

일부러 무한 루프 입력, 형식 깨진 응답(모킹), 원문에 없는 숫자를 넣어 각 가드가 진짜 멈추는지 확인한다. 하나라도 통과되면 그 가드는 없는 것과 같다. 🙋나

**복사·실행 예시**

```text
테스트1: 재시도 999회 강제 → BUDGET_GUARD에서 20회에 멈춤 O. 테스트2: title 빈 JSON → 리뷰 큐로 감 O. 테스트3: 가짜 '5억' → UNVERIFIED 플래그 O.
```

## 흔한 실수와 교정
- **실수:** '프롬프트를 잘 쓰면 환각은 안 난다'고 믿고 검증을 생략한다.
  - **교정:** 프롬프트는 확률을 낮출 뿐 0으로 못 만든다. 원문 대조·출처 확인 같은 기계적 게이트를 반드시 실행 경로에 넣는다.
- **실수:** 재시도(retry)를 무제한으로 걸어 실패할수록 비용이 폭증한다.
  - **교정:** 재시도는 최대 1~2회로 제한하고, 그래도 실패하면 사람 큐로 보낸다. 실행당 호출 수·비용 하드 상한을 코드에 둔다.
- **실수:** 가드를 코드에 넣고 실제로 발동하는지 테스트하지 않는다.
  - **교정:** 무한 루프·깨진 형식·가짜 숫자를 일부러 주입해 각 가드가 진짜 멈추는지 확인한다. 검증 안 된 가드는 없는 것과 같다.

## 완료 체크리스트

- 내 자동화의 비용·품질·환각 3종 실패 모습과 최악 손해액을 적었다
- 실행당 호출 수/비용 하드 상한과 콘솔 예산 상한을 둘 다 걸었다
- 출력을 스키마로 검증하고 실패 시 재시도 1회 후 리뷰 큐로 보낸다
- 원문 대조 또는 출처 확인으로 환각 문장을 차단/플래그한다
- 킬 스위치와 가드 발동 알림·일일 요약을 붙이고, 실패 3종을 실제로 터뜨려 검증했다

## 도구

- zod (https://zod.dev) — LLM 출력 JSON 스키마 검증

- Anthropic Console (https://console.anthropic.com) — 사용량·비용 상한·알림
- Langfuse (https://langfuse.com) — LLM 호출 비용·품질 추적 및 로깅
