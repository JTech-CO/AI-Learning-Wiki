_자동화 중간에 LLM 호출을 끼워 텍스트 이해·생성·분류를 시키기._

:::note[학습 목표]
- 이 레슨이 끝나면, 구글 시트에 들어온 문의 텍스트를 자동으로 카테고리 분류하고 3줄 요약까지 붙여 주는 무인 자동화를 직접 만들 수 있습니다.
:::

> 매일 쌓이는 고객 문의 100건을 사람이 하나씩 읽고 '환불/배송/칭찬'으로 분류하고 계신가요? 자동화 흐름 딱 한 칸에 LLM 호출을 끼워 넣으면, 그 지루한 판단을 기계가 초당 처리합니다.

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 구글 시트에 들어온 문의 텍스트를 자동으로 카테고리 분류하고 3줄 요약까지 붙여 주는 무인 자동화를 직접 만들 수 있습니다.

## 핵심 개념

자동화 도구(Zapier, Make, n8n)는 '데이터를 옮기고 조건 분기'는 잘하지만 '이 문장이 화난 건지 아닌지', '이 이메일 핵심이 뭔지' 같은 언어 판단은 못 합니다. 바로 그 자리에 LLM API 호출 스텝을 하나 끼워 넣으면, 흐름 중간에서 텍스트를 이해·생성·분류한 결과가 다음 스텝으로 흘러갑니다. 핵심은 '입력 → LLM 호출 → 출력을 다음 스텝이 쓸 수 있는 깔끔한 형태(JSON)로 받기' 이 세 박자입니다. 마치 컨베이어 벨트 중간에 '판단하는 로봇 팔' 하나를 추가하는 것과 같습니다. 이때 LLM이 아무 말이나 뱉지 않고 '정해진 형식'으로만 답하게 만드는 것이 자동화 성공의 90%입니다.

### 왜 작동하는가

LLM은 수억 개의 문장에서 '어떤 말이 화난 건지, 어떤 말이 배송 문의인지'를 이미 학습해 놓은 상태입니다. 그래서 자동화 흐름 중간에 LLM 호출 한 스텝만 끼우면, 사람이 눈으로 읽고 판단하던 일을 AI가 그 자리에서 대신 해줍니다. 당신은 '무엇을 판단시킬지'와 '어떤 형식으로 받을지'만 정하면, 나머지 지루한 분류·요약은 기계가 24시간 처리합니다.

## 👀 따라하기 예시

문의접수 시트에 하루 100건씩 쌓이는 고객 문의를 '환불/배송/칭찬/기타'로 자동 분류하고 3줄 요약까지 붙이는 자동화, 제가 먼저 처음부터 끝까지 만들어볼게요. 눈으로 따라오세요.

### 1. ① 판단 지점을 한 문장으로 정의

**실제 결과**

```text
입력: 고객 문의 원문 텍스트 → 출력: category(환불|배송|칭찬|기타) + summary(한글 3줄)
```

> 입출력을 먼저 못 박아야 프롬프트도, 다음 스텝 연결도 흔들리지 않아요.

### 2. ② 프롬프트를 대화창에서 먼저 손 테스트

**실제 결과**

```text
문의 '결제했는데 물건이 3일째 안 와요'를 넣으니 {"category":"배송","summary":"결제 후 3일간 미배송 상태로 확인 요청함"} 로 정확히 반환됨
```

> 자동화에 넣기 전에 형식이 안정되는지 눈으로 확인하면, 나중에 자동화 안에서 헤매지 않아요.

### 3. ③ Make에서 시트 새 행 감지 → LLM 모듈 연결

**실제 결과**

```text
'Google Sheets - Watch New Rows' 다음에 'Anthropic Claude' 모듈을 놓고, System에 분류 프롬프트, User에 {{1.문의원문}} 변수를 매핑
```

> 컨베이어 벨트 중간에 '판단하는 로봇 팔'을 하나 끼워 넣는 것과 똑같은 원리예요.

### 4. ④ Parse JSON → 시트에 자동 기록 + 실패 대비

**실제 결과**

```text
Parse JSON이 {category:"배송", summary:"..."}를 분해해 B열·C열에 기록. 형식이 깨진 1건은 자동으로 '검토필요'로 표시됨
```

> LLM이 가끔 형식을 어기는 것까지 미리 계획하면, 무인으로 켜 둬도 문의가 조용히 누락되지 않아요.

### 완성 결과

문의가 들어오면 사람 손 없이 category·summary가 자동으로 채워지는 무인 분류 시트. 좋은 결과의 기준: (1) category가 4개 값 중 정확히 하나로만 나온다 (2) summary가 항상 3줄 이내 한글로 나온다 (3) 형식이 깨진 행은 '검토필요'로 남아 누락되지 않는다.

## 단계별 따라하기

### 1단계 — 무엇을 판단시킬지 한 문장으로 정하기 (5분)

자동화 흐름에서 '사람이 눈으로 읽고 판단하던 지점' 하나를 콕 집어 입력·출력을 적습니다. 입력=무슨 텍스트가 들어오는지, 출력=어떤 형태로 나와야 다음 스텝이 쓰는지.

**복사·실행 예시**

```text
🙋나 — 입력: 고객 문의 원문 텍스트 / 출력: category(환불|배송|칭찬|기타) + summary(한글 3줄). 이 둘만 있으면 시트에 자동 기록 가능.
```

### 2단계 — 프롬프트를 먼저 손으로 테스트하기 (10분)

자동화에 넣기 전에 ChatGPT/Claude 대화창에 아래 템플릿1을 붙여 실제 문의 3~4건으로 답이 원하는 JSON 형태로 나오는지 확인합니다. 여기서 형식이 안정되면 자동화에서도 안정됩니다.

**복사·실행 예시**

```text
🤖A — 문의 '결제했는데 물건이 3일째 안 와요'를 넣으니 {"category":"배송","summary":"결제 후 3일간 미배송..."} 형태로 정확히 반환됨.
```

### 3단계 — 자동화 도구에서 트리거+데이터 소스 연결 (10분)

Make(또는 Zapier)에서 새 시나리오를 만들고 첫 스텝으로 'Google Sheets - Watch New Rows'를 넣습니다. 새 문의가 한 줄 추가될 때마다 흐름이 시작되게 합니다.

**복사·실행 예시**

```text
🤝함께 — 시트 '문의접수'의 A열에 문의 원문이 들어옴. Make가 새 행을 감지하면 그 행의 텍스트를 다음 스텝으로 넘김.
```

### 4단계 — 흐름 중간에 LLM 호출 스텝 끼우기 (10분)

두 번째 스텝으로 'OpenAI' 또는 'Anthropic Claude' 모듈을 추가합니다. 시스템 프롬프트에 템플릿1을 붙이고, 유저 메시지 자리에 1단계에서 온 시트의 문의 텍스트 변수를 매핑합니다.

**복사·실행 예시**

```text
🙋나 — Anthropic 모듈 System 칸에 '너는 분류기다. 반드시 JSON만 출력' 프롬프트, User 칸에 {{1.문의원문}} 변수를 드래그로 꽂음.
```

### 5단계 — LLM 출력(JSON)을 파싱해 다음 스텝에 전달 (10분)

LLM이 준 텍스트 답을 'Parse JSON' 모듈에 통과시켜 category와 summary를 분리된 값으로 만듭니다. 그다음 'Google Sheets - Update Row'로 해당 행의 B·C열에 각각 써 넣습니다.

**복사·실행 예시**

```text
🤝함께 — Parse JSON이 {category:"배송", summary:"..."}를 분해 → 시트 B열에 '배송', C열에 3줄 요약이 자동 기록됨.
```

### 6단계 — 실패에 대비하고 무인 실행 켜기 (10분)

LLM이 가끔 형식을 어기므로, Parse JSON 뒤에 에러 핸들러(Make의 Error handler / 'ignore')를 붙여 실패 행은 category를 '검토필요'로 표시하게 합니다. 그다음 시나리오를 ON(스케줄 15분마다)으로 켭니다.

**복사·실행 예시**

```text
🙋나 — 테스트 문의 5건 넣고 실행 → 4건 자동분류, 1건 '검토필요'. 스케줄 15분으로 켜 두니 이후 무인 처리됨.
```

## 흔한 실수와 교정
- **실수:** LLM에게 자유롭게 답하게 두어 '네, 알겠습니다! 이건 배송 문의네요~' 같은 문장이 나와 다음 스텝의 JSON 파싱이 깨진다.
  - **교정:** 프롬프트에 '반드시 JSON 객체 하나만, 설명·인사·코드블록 없이 출력'을 명시하고 정확한 형식 예시를 함께 준다. 가능하면 도구의 JSON/구조화 출력 옵션을 켠다.
- **실수:** category 값을 '배송문의', '배송 관련' 등 매번 다르게 뱉어 시트 필터·분기가 안 걸린다.
  - **교정:** 허용값을 프롬프트에 '환불|배송|칭찬|기타 중 정확히 하나'로 못 박고, 그 외 값은 '기타'로 강제한다. 오타·공백 방지.
- **실수:** LLM이 형식을 어기는 1~2%를 무시하고 켜 두었다가, 실패 행이 조용히 빈칸으로 남아 누락된다.
  - **교정:** 파싱 실패 시 category를 '검토필요'로 남기는 에러 분기를 반드시 두고, '검토필요' 행만 사람이 하루 1번 확인한다.

## 완료 체크리스트

- 판단시킬 지점의 입력·출력을 한 문장으로 정의했다
- 자동화에 넣기 전 대화창에서 프롬프트를 실제 데이터 3건으로 테스트했다
- 자동화 흐름에 LLM 호출 스텝을 끼우고 입력 변수를 매핑했다
- LLM 출력을 JSON으로 파싱해 다음 스텝(시트 기록)에 연결했다
- 형식 위반 대비 에러 분기('검토필요')를 넣고 무인 스케줄을 켰다

## 도구

- Make (make.com) — 노코드 자동화 흐름, LLM 모듈 내장
- Zapier (zapier.com) — 가장 대중적인 자동화, ChatGPT 스텝 지원
- OpenAI/Anthropic API (platform.openai.com / console.anthropic.com) — 흐름 중간에서 호출하는 LLM
- Google Sheets (sheets.google.com) — 입력·출력 저장소 겸 트리거

## 참고 답안

입력: 리뷰 원문 텍스트 / 출력: sentiment(긍정|부정|중립) + rating(1~5 정수). 프롬프트로 '반드시 JSON 객체 하나만, sentiment는 3값 중 하나, rating은 1~5 정수' 명시 → 대화창에서 리뷰 3~4건으로 형식 테스트 → Make에서 '시트 새 행 감지 → LLM 모듈(System=분류 프롬프트, User={{리뷰원문}}) → Parse JSON → 시트 업데이트' 순으로 연결 → 파싱 실패 시 sentiment를 '검토필요'로 남기는 에러 분기 추가.

## 실전 프롬프트

### ① 문의 분류+요약기 (가장 먼저 써보세요)

```text
너는 고객 문의 분류기다. 아래 문의를 읽고 반드시 아래 JSON 형식으로만 답하라. 설명·인사·코드블록 없이 JSON 객체 하나만 출력하라.
형식: {"category": "환불|배송|칭찬|기타 중 하나", "summary": "한글 3줄 이내 핵심 요약", "urgency": "높음|보통|낮음"}

문의: [여기에 고객 문의 텍스트]
```

> 확인된 작성 예시 없음

`eduverse` `llm-in-loop`

### ② 자유 텍스트 → 구조화 데이터 추출

```text
아래 텍스트에서 다음 항목을 뽑아 JSON으로만 답하라. 값이 없으면 null. 다른 말 금지.
형식: {"이름": null, "연락처": null, "희망일자": null, "요청내용": null}

텍스트: [여기에 이메일/메모 원문]
```

> 확인된 작성 예시 없음

`eduverse` `llm-in-loop`

### ③ 감정·긴급도 판정(라우팅용)

```text
다음 메시지의 감정과 긴급도를 판정해 JSON으로만 답하라.
형식: {"sentiment": "긍정|중립|부정", "needs_human": true|false, "reason": "한 문장"}
needs_human은 화가 났거나 즉시 대응이 필요하면 true.

메시지: [여기에 텍스트]
```

> 확인된 작성 예시 없음
