_노코드가 강한 지점과 막히는 지점, 코드 자동화로 전환해야 하는 신호를 판단._

:::note[학습 목표]
- 이 레슨이 끝나면, 내 자동화가 노코드로 충분한지 코드로 넘어가야 하는지 5가지 전환 신호로 스스로 판단하고 결정표에 기록할 수 있습니다.
:::

> "자동화가 잘 돌아가다가 어느 날 갑자기 '이건 노코드로 안 되는데...'라는 벽에 부딪힌 적 있나요? 그 벽이 언제 오는지 미리 알면, 무너지기 전에 갈아탈 수 있습니다."

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 내 자동화가 노코드로 충분한지 코드로 넘어가야 하는지 5가지 전환 신호로 스스로 판단하고 결정표에 기록할 수 있습니다.

## 핵심 개념

노코드 도구(Zapier, Make, 노션 등)는 '표준 블록을 연결하는 일'에 강합니다. A 앱의 데이터를 B 앱으로 옮기고, 조건 분기를 걸고, 알림을 보내는 일은 몇 분이면 됩니다. 하지만 실행량이 많아 비용이 폭증하거나, 도구가 제공하지 않는 세밀한 로직·데이터 가공이 필요하거나, 같은 흐름을 수십 개 복제해야 할 때 노코드는 오히려 느리고 비싸집니다. 핵심은 '노코드 vs 코드'가 선택이 아니라 '지금 내 상황이 어느 쪽 비용이 더 싼가'라는 저울질이라는 점입니다. 대부분은 노코드로 시작해 특정 신호가 켜지면 그 부분만 코드로 갈아타는 하이브리드가 정답입니다.

### 왜 작동하는가

노코드 도구는 남들이 이미 만들어 둔 표준 연결(트리거→액션)을 빌려 쓰는 구조라서, 그 틀 안에서는 몇 분 만에 완성됩니다. 하지만 실행량이 폭증하거나 표준 틀 밖의 세밀한 로직이 필요해지면, 그 틀 자체가 비용과 한계로 돌아옵니다. 그래서 '노코드냐 코드냐'는 취향이 아니라 '지금 이 부분의 비용이 어느 쪽이 더 싼가'를 매번 저울질하는 문제입니다.

## 👀 따라하기 예시

쇼핑몰 주문이 늘어나 월 1만 건이 됐고, 배송사 API로 운송장 번호를 직접 보내야 하는 상황이에요. 제가 먼저 이 흐름을 처음부터 끝까지 판정해볼게요, 눈으로 따라오세요.

### 1. ① 흐름을 한 줄로 적는다

**실제 결과**

```text
'새 주문이 들어오면 → 배송사 API에 운송장 번호를 등록하고 → 슬랙에 알림을 보낸다'
```

> 흐름이 한 문장으로 안 잡히면 신호 체크도 흔들리니, 먼저 뼈대부터 고정해요.

### 2. ② 5가지 전환 신호 체크

**실제 결과**

```text
(1)월 실행량 초과 → 예 / (4)API 직접 호출인데 커넥터 없음 → 예 / 나머지 3개는 아니오 → 총 2개 켜짐
```

> '예'가 2개 이상이면 그 부분만 코드 전환을 검토하는 게 원칙이에요. 여기서 이미 기준을 넘겼죠.

### 3. ③ AI에게 판정과 근거 요청

**실제 결과**

```text
'전면 코드 대신 하이브리드 권장. 트리거·알림은 Make에 그대로 두고, 배송사 API 호출·재시도 부분만 파이썬 스크립트로 분리하세요.'
```

> 전체를 갈아엎지 않고 '병목 한 조각'만 짚어주는 게 AI 판정의 핵심 가치예요.

### 4. ④ 결정표에 기록

**실제 결과**

```text
| 주문알림 | 하이브리드 | 신호 2개 | 배송 API만 코드로 분리 |
```

> 판정은 한 번으로 끝나는 게 아니라 실행량이 또 늘면 재판정할 근거가 되니 표로 남겨둬요.

### 완성 결과

완성물은 '전환 결정표' 한 줄 + 병목 부분만 분리한 최소 스크립트 요청 메시지입니다. 좋은 결과의 기준은: (1) 노코드 부분을 굳이 다 갈아엎지 않았는가 (2) 신호 개수와 이유가 표에 명확히 남았는가 (3) 코드로 옮긴 부분이 '딱 그 병목 한 조각'인가.

## 단계별 따라하기

### 1단계 — 내 자동화 흐름 한 줄로 적기 (5분)

현재 돌리고 있거나 만들려는 자동화를 '무엇이 → 무엇을 하면 → 무엇을 한다' 형식으로 한 문장으로 적는다. 🙋나

**복사·실행 예시**

```text
예: '새 구글폼 응답이 들어오면 → 노션 DB에 행을 추가하고 → 슬랙에 알림을 보낸다'
```

### 2단계 — 노코드가 강한 지점인지 체크 (5분)

흐름을 표준 앱 연결(트리거→액션)로만 그릴 수 있으면 노코드가 강한 영역이다. 앱 간 데이터 이동, 조건 분기, 알림 3가지 안에 들어오는지 확인한다. 🙋나

**복사·실행 예시**

```text
위 예시는 '폼→노션→슬랙' 전부 표준 커넥터로 존재 → 노코드가 압도적으로 유리. 코드로 짜면 오히려 손해.
```

### 3단계 — 5가지 전환 신호로 점수 매기기 (10분)

아래 5개 질문에 예/아니오로 답한다. (1)월 실행량이 많아 노코드 요금제 한도를 넘기는가 (2)도구에 없는 세밀한 계산·문자열 가공·정규식이 필요한가 (3)같은 흐름을 5개 이상 복제·변형해야 하는가 (4)외부 API를 직접 호출해야 하는데 커넥터가 없는가 (5)실패 시 재시도·로그·버전관리가 꼭 필요한가. '예'가 2개 이상이면 코드 전환을 검토한다. 🤝함께

**복사·실행 예시**

```text
쇼핑몰 주문 1만 건/월 + 배송사 API 직접 호출 필요 → (1)예 (4)예 = 2개 → 코드 전환 신호 켜짐
```

### 4단계 — AI에게 판정과 근거 받기 (10분)

아래 첫 번째 템플릿에 내 흐름과 5개 답을 채워 ChatGPT/Claude에 붙여넣는다. '노코드 유지 / 하이브리드 / 전면 코드' 중 하나와 그 이유, 갈아탈 부분을 받는다. 🤖A

**복사·실행 예시**

```text
AI 답 예: '전면 코드 대신 하이브리드 권장. 트리거·알림은 Make에 두고, 배송사 API 호출·재시도 부분만 파이썬 스크립트로 분리하세요.'
```

### 5단계 — 전환 결정표에 기록하기 (5분)

노션이나 구글시트에 열 4개(흐름 이름 / 노코드·코드·하이브리드 / 전환 신호 개수 / 결정 이유)를 만들고 오늘 판정을 한 줄 기록한다. 다음에 실행량이 늘면 이 표를 다시 보고 재판정한다. 🙋나

**복사·실행 예시**

```text
| 주문알림 | 하이브리드 | 신호 2개 | 배송 API만 코드로 분리 |
```

### 6단계 — 갈아탈 부분만 최소 코드로 뽑아보기 (10분)

하이브리드로 결정났다면, 코드로 옮길 그 '한 부분'만 두 번째 템플릿으로 AI에게 최소 스크립트를 요청한다. 전체를 다 코드로 바꾸지 말고 병목 한 조각만 옮긴다. 🤖A

**복사·실행 예시**

```text
'배송사 API에 운송장 번호를 POST하고 실패하면 3번 재시도하는 파이썬 함수'만 받아 Make의 HTTP 모듈이나 서버리스로 연결
```

## 흔한 실수와 교정
- **실수:** 신호가 하나 켜졌다고 전체를 다 코드로 다시 짠다.
  - **교정:** 병목이 된 '그 한 조각'만 코드로 분리하는 하이브리드로 간다. 나머지 표준 연결은 노코드에 그대로 둔다.
- **실수:** '코드가 멋있어 보여서' 처음부터 전부 직접 코딩한다.
  - **교정:** 노코드로 먼저 만들어 흐름을 검증하고, 실제로 전환 신호가 2개 이상 켜졌을 때만 코드로 옮긴다. 검증 안 된 흐름에 코드 시간을 쓰지 않는다.
- **실수:** 실행량·비용이 늘어도 옛날 판정을 그대로 방치한다.
  - **교정:** 전환 결정표를 만들어 실행량이 눈에 띄게 늘면 5가지 신호로 재판정한다. 판정은 한 번이 아니라 주기적 저울질이다.

## 완료 체크리스트

- 내 자동화 흐름을 '무엇이→무엇을 하면→무엇을 한다' 한 문장으로 적었다
- 노코드가 강한 영역(앱 연결·분기·알림)인지 확인했다
- 5가지 전환 신호에 예/아니오로 답하고 '예' 개수를 셌다
- AI에게 판정과 갈아탈 부분을 받아 결정을 내렸다
- 전환 결정표에 오늘 판정을 한 줄 기록했다

## 도구

- Make (https://make.com) — 시각적 노코드 자동화, 복잡한 분기·반복에 강함
- Zapier (https://zapier.com) — 앱 연결 자동화, 커넥터 수가 가장 많음
- ChatGPT (https://chat.openai.com) — 전환 판정·병목 코드 스니펫 생성
- Google Sheets (https://sheets.google.com) — 전환 결정표 기록·재판정 관리

## 참고 답안

(1)월 실행량 한도 초과 → 아니오 (2)세밀한 계산·정규식 필요 → 아니오 (3)흐름 5개 이상 복제 → 아니오 (4)API 직접 호출인데 커넥터 없음 → 예(결제 검증 API) (5)재시도·로그 필수 → 예(결제라서 실패 시 반드시 재시도 필요) → 신호 2개 켜짐 → 결정: 하이브리드. 웰컴 이메일·시트 기록은 노코드 그대로, 결제 검증 API 호출만 코드로 분리.
