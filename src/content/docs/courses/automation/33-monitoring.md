_자동화가 살아있는지 감시하고 실패 시 알림·자동복구._

:::note[학습 목표]
- 내 자동화가 '살아있는지'를 스스로 감시하게 만들고, 죽으면 5분 안에 카톡·이메일로 알림이 오게 세팅할 수 있다.
:::

> 밤새 돌아가는 자동화가 새벽 3시에 조용히 죽어도, 아침에 확인하기 전까지 아무도 모른다. 그 사이 주문 알림·백업·리포트가 통째로 빠진다.

## 이 레슨에서 만드는 것

내 자동화가 '살아있는지'를 스스로 감시하게 만들고, 죽으면 5분 안에 카톡·이메일로 알림이 오게 세팅할 수 있다.

## 핵심 개념

모니터링은 자동화의 '맥박 재기'다. 사람이 병원에서 심전도로 심장이 뛰는지 보듯, 자동화도 정해진 시간마다 '나 살아있어요' 신호(핑, ping)를 보낸다. 이걸 대신 지켜봐 주는 감시원이 헬스체크 서비스다. 감시원은 신호가 제때 안 오면 '얘가 죽었다!'고 판단해 너에게 알림을 쏜다. 헬스체크(health check)란 '건강 확인'이라는 뜻으로, 자동화가 정상인지 주기적으로 점검하는 것이다. 핵심은 '조용한 실패'를 막는 것이다 — 에러 메시지도 없이 그냥 멈춰버리는 게 가장 위험하다.

### 왜 작동하는가

헬스체크 서비스는 "정해진 시간마다 신호가 오는지"만 지켜보는 초단순 감시원이에요. 신호가 제때 안 오면 즉시 이상 신호로 판단해서 알림을 쏘죠. 그래서 당신은 자동화 끝에 주소 하나만 심어두면, "죽었는지 살았는지"는 감시원이 24시간 대신 챙겨줍니다.

## 👀 따라하기 예시

매일 새벽 3시에 도는 재고 자동 백업 시나리오가 있어요. 이게 조용히 멈춰도 아무도 모르는 상황 — 제가 먼저 healthchecks.io로 감시원을 붙여볼게요, 눈으로 따라오세요.

### 1. ① healthchecks.io 가입 후 Add Check 클릭

**실제 결과**

```text
새 체크 생성됨 → 이름 "새벽백업", ping URL: https://hc-ping.com/8f2a-91c3-... 발급
```

> 이 주소 하나가 이 자동화 전용 "생존 확인 전화번호"예요

### 2. ② Period=1 day, Grace=1 hour로 설정

**실제 결과**

```text
대시보드 상태가 회색 "New" → 첫 핑 오기 전 대기 상태로 표시
```

> 주기는 도는 간격, 여유시간은 "이 정도 늦는 건 봐준다"는 안전 마진이에요

### 3. ③ Make 시나리오 맨 마지막에 HTTP 모듈 추가, ping URL 붙여넣기

**실제 결과**

```text
시나리오 실행 완료 → healthchecks.io 대시보드가 회색에서 초록 "Up"으로 바뀜, Last Ping "2분 전"
```

> 맨 마지막에 심어야 "모든 작업이 진짜 끝까지 성공했다"는 뜻이 돼요 — 시작에 심으면 도중에 죽어도 살아있다고 착각해요

### 4. ④ 일부러 핑 모듈을 껐다가 6분 뒤 확인

**실제 결과**

```text
대시보드가 빨간 "Down"으로 바뀌고, 연결해둔 이메일로 "새벽백업 is DOWN" 알림 도착
```

> 감시가 실제로 작동하는지는 반드시 한 번 죽여봐야 확신할 수 있어요 — 이게 진짜 아하 포인트!

### 완성 결과

자동화 끝에 심은 ping URL 1줄 + healthchecks.io 대시보드 하나. 좋은 결과의 기준: (1) 정상 실행 때마다 대시보드가 초록 Up으로 바뀐다 (2) 일부러 끊어보면 실제로 알림이 온다 (3) 여유시간이 내 자동화의 평소 지연폭보다 넉넉하다.

## 단계별 따라하기

### 무료 감시원 가입하기

브라우저에서 healthchecks.io 접속 → 우측 상단 'Sign Up' 클릭 → 이메일과 비밀번호 입력 → 가입. 무료로 20개 감시항목까지 만들 수 있다. (한국어가 아니어도 버튼 위치는 그대로다)

**복사·실행 예시**

```text
gmail로 가입하니 바로 대시보드(감시판)가 뜬다.
```

### 감시항목 만들고 주소 복사

대시보드에서 'Add Check(체크 추가)' 클릭 → 이름 입력(예: '새벽백업') → 'Period(주기)'를 자동화가 도는 간격으로 설정(예: 1 day) → 'Grace(여유시간)'는 늦어도 봐주는 시간(예: 1 hour) → 저장 후 나오는 긴 주소(ping URL)를 복사한다.

**복사·실행 예시**

```text
주소 예: https://hc-ping.com/abc-123... 이걸 복사해둔다.
```

### 자동화 끝에 '생존신호' 심기

내 자동화의 맨 마지막 단계에 '복사한 주소로 접속하기'를 추가한다. Make/Zapier면 마지막에 'HTTP 요청' 액션 추가 후 주소 붙여넣기. n8n이면 'HTTP Request' 노드 추가. 스크립트면 마지막 줄에 curl 명령 추가.

**복사·실행 예시**

```text
Make에서 시나리오 끝에 HTTP 모듈 넣고 URL만 붙여넣음 → 작업 성공할 때마다 핑이 자동 전송됨.
```

### 알림 받을 곳 연결하기

healthchecks.io 좌측 메뉴 'Integrations(연동)' 클릭 → 이메일은 기본 켜져있음 → Slack·Telegram 등 원하는 곳 'Connect' 클릭해 연결. 카톡을 원하면 Telegram이나 이메일→카톡 전달을 쓴다.

**복사·실행 예시**

```text
Telegram 봇 연결하니, 신호 끊기면 텔레그램으로 '새벽백업 down!' 메시지가 온다.
```

### 일부러 죽여서 테스트하기

자동화를 하루 일부러 끄거나 핑 단계를 잠깐 지워본다 → 설정한 주기+여유시간이 지나면 알림이 오는지 확인. 알림이 오면 감시가 제대로 작동하는 것이다.

**복사·실행 예시**

```text
핑을 끄고 주기를 5분으로 짧게 바꿔 테스트 → 6분 뒤 이메일 도착 확인 후 원래대로 복구.
```

## 흔한 실수와 교정
- **실수:** 감시는 걸었지만 알림 받을 곳(이메일/텔레그램)을 안 연결함
  - **교정:** Integrations 메뉴에서 최소 1개는 연결하고, 테스트 알림을 실제로 받아본 뒤 안심한다.
- **실수:** 생존신호를 자동화 '시작'에 심어서, 도중에 죽어도 살아있다고 뜸
  - **교정:** 핑은 반드시 모든 작업이 성공한 '맨 마지막'에 심는다. 그래야 진짜 완료를 뜻한다.
- **실수:** 여유시간(Grace)을 0으로 잡아 1분만 늦어도 오작동 알림 폭탄
  - **교정:** 실제 작업이 늦어질 수 있는 만큼(예: 30분~1시간) 여유시간을 넉넉히 준다.
- **실수:** 테스트를 안 해서, 정작 진짜 죽었을 때 감시도 같이 안 도는 경우
  - **교정:** 가입 직후 일부러 신호를 끊어 알림이 오는지 반드시 한 번 확인한다.

## 완료 체크리스트

- healthchecks.io(또는 UptimeRobot) 가입 완료
- 감시항목의 Period·Grace를 실제 자동화 주기에 맞게 설정
- 생존신호(핑)를 자동화 '맨 마지막'에 심음
- 알림 받을 곳(이메일/텔레그램) 최소 1개 연결
- 일부러 죽여보는 테스트로 알림 실제 수신 확인
- 죽었을 때 다시 살리는 복구 절차를 메모해둠

## 도구

- healthchecks.io — 생존신호(핑) 기반 자동화 감시, 무료 20개까지
- UptimeRobot — 웹사이트·URL이 살아있는지 5분마다 접속 확인
- Make/Zapier — 자동화 끝에 HTTP 요청으로 핑 전송
- n8n — HTTP Request 노드로 핑 심기(자체호스팅 가능)
- Telegram — 무료로 실시간 실패 알림 받기

## 참고 답안

예: "SNS 자동 포스팅"(하루 3번 도는 자동화) → Period=8 hours, Grace=30 min으로 설정 → 시나리오 맨 마지막 스텝에 HTTP 요청 추가, ping URL 붙여넣기 → 정상 실행 확인(대시보드 Up) → 핑 스텝 잠깐 지우고 기다려서 Down 알림 수신 확인 → 다시 복구.

## 실전 프롬프트

### 감시 설계 요청

```text
나는 [Make/Zapier/n8n/파이썬 스크립트]로 [자동화 내용, 예: 매일 새벽 3시 DB 백업]을 돌린다. healthchecks.io로 이 자동화가 죽었는지 감시하고 싶다. 1) 어느 위치에 생존신호(핑)를 심어야 하는지, 2) Period와 Grace 값을 각각 얼마로 잡아야 하는지, 3) 실패 알림을 [텔레그램/이메일]로 받는 방법을 초보자가 따라할 수 있게 단계별로 알려줘.
```

> 확인된 작성 예시 없음

`eduverse` `monitoring`

### curl 핑 명령 만들기

```text
내 리눅스 서버 스크립트 맨 끝에 healthchecks.io로 생존신호를 보내고 싶다. 내 핑 주소는 [https://hc-ping.com/여기]다. 작업이 성공했을 때만 신호를 보내고, 실패하면 실패신호(/fail)를 보내는 명령을 만들어줘. 각 줄이 무슨 뜻인지도 설명해줘.
```

`eduverse` `monitoring`
