_여러 프롬프트를 연결하고 JSON 등 구조화 출력을 강제해 코드로 이어붙이기._

:::note[학습 목표]
- 이 레슨이 끝나면, 여러 프롬프트를 순서대로 연결하고 각 단계 출력을 JSON으로 강제해 파이썬 코드로 이어붙이는 미니 파이프라인을 직접 만들 수 있습니다.
:::

> AI에게 "알아서 잘 해줘"라고 던지면 매번 다른 모양의 답이 나와서 코드로 이어붙일 수가 없습니다. 답의 '모양'을 JSON으로 못 박고 여러 프롬프트를 파이프처럼 연결하면, AI가 갑자기 자동화 부품으로 변합니다.

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 여러 프롬프트를 순서대로 연결하고 각 단계 출력을 JSON으로 강제해 파이썬 코드로 이어붙이는 미니 파이프라인을 직접 만들 수 있습니다.

## 핵심 개념

프롬프트 파이프라인이란 하나의 큰 작업을 '추출 → 변환 → 검증'처럼 작은 단계로 쪼개고, 앞 단계의 출력을 뒤 단계의 입력으로 넘기는 조립 라인입니다. 핵심은 각 단계가 반드시 정해진 JSON 스키마(키 이름과 타입이 고정된 틀)로만 답하도록 강제하는 것입니다. 사람이 읽는 줄글은 예뻐 보여도 코드가 파싱할 수 없지만, {"title": "...", "score": 8} 같은 구조화 출력은 코드가 바로 꺼내 쓸 수 있습니다. 마치 공장에서 각 기계가 규격 맞는 부품만 다음 컨베이어로 넘기는 것과 같아서, 한 단계가 규격을 어기면 즉시 걸러낼 수 있습니다. 이 구조 덕분에 리뷰 100개 요약, 뉴스 자동 분류 같은 반복 작업을 사람 손 없이 돌릴 수 있습니다.

### 왜 작동하는가

AI는 "이 모양의 JSON으로만 답해"라고 스키마를 콕 집어주면, 그 틀에 값을 채워 넣는 건 아주 잘합니다. 그래서 줄글 대신 {"sentiment":"positive"} 같은 고정된 틀을 주면, 코드가 바로 꺼내 쓸 수 있는 부품이 되어 여러 단계를 이어 붙일 수 있는 것이죠.

## 👀 따라하기 예시

고객 리뷰 5개가 뒤죽박죽 쌓여 있어요. "감정 분석 → 불만 카테고리 분류"까지 자동으로 이어지는 파이프라인, 제가 먼저 처음부터 끝까지 만들어볼게요. 눈으로 따라오세요!

### 1. ① 스키마부터 못 박기

**실제 결과**

```text
{"sentiment":"positive|neutral|negative", "complaint":"string 또는 null", "has_complaint": true}
```

> 키 이름과 허용값을 먼저 정해두면 AI 답이 매번 똑같은 모양으로 나와요. 이게 파이프라인의 설계도예요.

### 2. ② 1단계 프롬프트로 리뷰 하나 넣어보기

**실제 결과**

```text
입력: "배송이 너무 늦었어요 3일이나" → 출력: {"sentiment":"negative","complaint":"배송 지연","has_complaint":true}
```

> 프롬프트 끝에 "순수 JSON만, 코드블록·인사말 금지"를 넣으니 AI가 군더더기 없이 딱 스키마대로만 답했어요.

### 3. ③ 1단계 출력을 2단계 입력으로 그대로 넘기기

**실제 결과**

```text
data1 = json.loads(resp1) → 2단계 입력 = data1["complaint"] ("배송 지연") → 2단계 출력: {"category":"배송"}
```

> 이게 파이프라인의 핵심! 앞 단계 출력이 뒤 단계 입력이 되니까, 사람이 중간에서 복붙할 필요가 없어져요.

### 4. ④ 검증 게이트로 이상한 값 걸러내기

**실제 결과**

```text
assert data1["sentiment"] in ("positive","neutral","negative") → 위반 시 error_log에 담고 다음 리뷰로 스킵
```

> 파싱만 믿으면 안 돼요. 값이 허용 범위 안에 있는지 한 번 더 체크해야 뒤 단계가 조용히 오염되지 않아요.

### 완성 결과

리뷰를 넣으면 감정·불만·카테고리가 자동으로 채워진 표 한 줄이 나오는 미니 파이프라인. 좋은 결과의 기준: (1) 같은 입력이면 항상 같은 키 구조로 나온다, (2) 스키마 밖 값은 게이트에서 걸러진다, (3) 실패해도 전체가 멈추지 않고 다음 항목으로 넘어간다.

## 단계별 따라하기

### 1단계 — 파이프라인 설계 종이에 그리기 (5분) 🙋나

자동화하고 싶은 작업 하나를 정하고, 그것을 2~3개의 작은 단계로 쪼개 각 단계의 입력과 출력을 한 줄로 적습니다. 아직 코드나 프롬프트는 쓰지 말고 흐름만 그립니다.

**복사·실행 예시**

```text
목표: 상품 리뷰를 분석한다. 1단계(추출): 리뷰 원문 → {감정, 핵심불만}. 2단계(분류): 핵심불만 → {카테고리: 배송/품질/가격}. 3단계(요약): 여러 결과 → 표 한 줄.
```

### 2단계 — 각 단계의 JSON 스키마 못 박기 (7분) 🤝함께

각 단계마다 출력 JSON의 키 이름·타입·허용값을 정확히 정합니다. AI에게 스키마 초안을 뽑아달라고 한 뒤 내가 키 이름을 다듬습니다. 애매한 자유서술 필드는 최대한 열거형(정해진 보기 중 택1)으로 바꿉니다.

**복사·실행 예시**

```text
1단계 스키마: {"sentiment": "positive|neutral|negative", "complaint": "string", "has_complaint": true}. 🤖A에게 '이 스키마에서 빠진 엣지케이스 알려줘'라고 물어 null 처리 규칙을 추가.
```

### 3단계 — 구조화 출력 프롬프트 작성·테스트 (8분) 🤖A

1단계 프롬프트를 작성합니다. 반드시 '오직 JSON만 출력, 코드블록·설명·인사말 금지'를 명시하고, 원하는 스키마 예시를 프롬프트 안에 붙입니다. ChatGPT/Claude에 리뷰 3개를 넣어 3번 모두 같은 키가 나오는지 확인합니다.

**복사·실행 예시**

```text
프롬프트 끝에: '아래 스키마의 순수 JSON 하나만 출력해. 마크다운 금지. 스키마: {"sentiment":..., "complaint":..., "has_complaint":...}'. 입력 리뷰 3개 → 3번 다 동일 키 확인.
```

### 4단계 — 파이썬으로 두 단계 이어붙이기 (10분) 🤝함께

AI에게 '1단계 JSON을 받아 2단계 프롬프트의 입력으로 넣는 파이썬 코드'를 요청합니다. 핵심은 json.loads()로 파싱하고, 파싱 실패 시 재시도하는 try/except를 넣는 것입니다. API 키가 없으면 출력을 손으로 복붙해 코드 흐름만 검증합니다.

**복사·실행 예시**

```text
resp1 = call_ai(prompt1, review); data1 = json.loads(resp1); if data1['has_complaint']: resp2 = call_ai(prompt2, data1['complaint']); data2 = json.loads(resp2).
```

### 5단계 — 검증 게이트 추가 (7분) 🙋나

파싱 후 필수 키가 다 있는지, 값이 허용된 보기 안에 있는지 체크하는 검사 함수를 넣습니다. 어긋나면 그 항목만 건너뛰거나 재요청하도록 합니다. 이 게이트가 파이프라인이 조용히 망가지는 걸 막습니다.

**복사·실행 예시**

```text
assert data1['sentiment'] in ('positive','neutral','negative'), '스키마 위반'. 위반 시 해당 리뷰를 error_log에 담고 다음으로 진행.
```

### 6단계 — 배치로 10개 돌려보기 (8분) 🤝함께

리뷰 10개를 리스트에 넣고 for 루프로 파이프라인 전체를 돌려 결과를 CSV/표로 모읍니다. 실패한 개수와 성공한 개수를 세어 성공률을 확인하고, 실패 케이스의 원문을 살펴 프롬프트를 한 번 보정합니다.

**복사·실행 예시**

```text
results = []; for r in reviews: try: results.append(run_pipeline(r)) except: fails+=1. 끝에 print(f'성공 {len(results)}건 / 실패 {fails}건') → 실패 리뷰 보고 프롬프트 수정.
```

## 흔한 실수와 교정
- **실수:** 프롬프트에 스키마 예시 없이 'JSON으로 답해'라고만 해서 매번 키 이름이 달라진다.
  - **교정:** 원하는 키·타입·허용값이 채워진 JSON 예시를 프롬프트 안에 직접 붙여 넣고 '이 키 외 추가 금지'를 명시한다.
- **실수:** AI가 ```json 코드블록이나 '네, 여기 있습니다' 같은 말을 붙여서 json.loads가 터진다.
  - **교정:** '마크다운·설명·인사말 금지, 순수 JSON 객체 하나만'을 못 박고, 코드에서도 파싱 전에 코드블록 기호를 벗겨내는 방어 코드를 넣는다.
- **실수:** 파싱 성공만 믿고 값 검증을 건너뛰어, 허용값 밖의 엉뚱한 라벨이 뒤 단계로 넘어가 조용히 오염된다.
  - **교정:** 파싱 직후 필수 키 존재와 허용값 포함을 검사하는 게이트를 두고, 위반 항목은 로그에 남기고 건너뛴다.

## 완료 체크리스트

- 작업을 2~4개 단계로 쪼개 각 단계 입력·출력을 종이에 그렸다
- 각 단계의 JSON 스키마(키·타입·허용값)를 확정했다
- 프롬프트에 스키마 예시를 넣고 '순수 JSON만'을 명시했다
- 같은 입력으로 3번 돌려 동일한 키가 나오는지 확인했다
- 파싱+필수키+허용값 검증 게이트를 코드에 넣었다

## 실전 프롬프트

### 구조화 출력 강제 (가장 유용)

```text
너는 데이터 추출기다. 아래 [입력]을 분석해 오직 순수 JSON 객체 하나만 출력해라. 마크다운 코드블록, 설명, 인사말 절대 금지.
스키마:
{
  "[키1]": "[타입/허용값 예: positive|neutral|negative]",
  "[키2]": "string 또는 null",
  "[키3]": true
}
규칙: 값을 모르면 null. 스키마에 없는 키 추가 금지.
[입력]:
[여기에 원문 텍스트]
```

