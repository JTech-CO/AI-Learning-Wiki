## 이 레슨에서 만드는 것

이 레슨이 끝나면, 파이썬 에러 트레이스백을 스스로 읽고 원인 줄을 찾아 10분 안에 혼자 고칠 수 있습니다.

## 핵심 개념

에러 메시지(트레이스백)는 컴퓨터가 당신을 혼내는 게 아니라, 어디서·왜 멈췄는지 적어준 사건 보고서입니다. 핵심은 딱 두 가지 — 맨 아래 줄(에러 종류와 이유)과, 트레이스백 중 "내 파일·내 줄 번호"입니다. 이건 마치 요리하다 냄비가 넘쳤을 때 "몇 번 불에서 뭐가 넘쳤나"를 확인하는 것과 같아요. 종류(NameError, TypeError 등)만 알아도 원인의 80%가 좁혀지고, AI에게 트레이스백 전체를 붙여넣으면 나머지도 빠르게 뚫립니다. 디버깅은 재능이 아니라 순서를 아는 습관입니다.

### 왜 작동하는가

AI는 지금까지 사람들이 만난 수억 건의 에러 메시지와 그 해결 사례를 학습했어요. 그래서 트레이스백 원문만 통째로 보여주면, 마치 오래된 정비사가 엔진 소리만 듣고 고장 부위를 짚어내듯 원인 유형을 순식간에 매칭해줍니다. 그래서 당신은 ①범인 줄 찾기와 ②원문 그대로 붙여넣기만 하면, 나머지 진단과 수정안은 AI가 대신해줍니다.

## 👀 따라하기 예시

실습용 쇼핑몰 코드를 돌렸더니 결제 함수에서 KeyError: 'price' 가 떴습니다. 제가 먼저 처음부터 끝까지 뚫어볼게요, 눈으로 따라오세요.

### 1. ① 트레이스백 맨 아랫줄부터 읽기

**실제 결과**

```text
KeyError: 'price'  /  File "checkout.py", line 27, in calc_total
```

> 맨 위부터 읽으면 관계없는 내부 함수들에 정신이 팔려요. 맨 아랫줄과 내 파일 줄 번호, 이 두 곳만 먼저 봅니다.

### 2. ② 에러 종류로 원인 좁히기

**실제 결과**

```text
KeyError → 딕셔너리에 그 키가 아예 없다는 뜻. "오타인가? 아니면 API가 다른 이름으로 보냈나?" 두 가지로 후보를 좁힘
```

> 종류 이름만 봐도 원인의 80%가 카테고리로 걸러집니다. 전체 코드를 안 봐도 됩니다.

### 3. ③ 범인 줄 위에 print 찍어 실제 값 확인

**실제 결과**

```text
print('DEBUG item =', item) 실행 결과 → {'cost': 12000, 'name': '티셔츠'}
```

> 딕셔너리 안에 'price'가 아니라 'cost'라는 키로 들어있었다는 게 눈으로 바로 확인됩니다. 감이 아니라 증거로 판단.

### 4. ④ AI에게 트레이스백 전체 + 코드 붙여넣기

**실제 결과**

```text
AI 답변: "item 딕셔너리의 키가 'cost'인데 코드는 'price'로 접근하고 있어요. item['cost'] 로 바꾸거나, item.get('price', item.get('cost', 0)) 처럼 방어적으로 쓰세요."
```

> 요약하지 않고 원문 그대로 붙였기 때문에 AI가 정확한 줄과 정확한 원인을 바로 짚어줬습니다.

### 완성 결과

완성물은 "왜 터졌는지 한 줄 원인 + 수정된 코드 한 줄 + 재실행 후 통과 확인"입니다. 좋은 결과의 기준: (1) 에러 메시지가 사라졌다 (2) 왜 고쳤는지 내가 설명할 수 있다 (3) 같은 실수가 또 나면 1분 안에 알아챈다.

## 단계별 따라하기

### 1단계 — 트레이스백을 끝에서부터 읽기 (2분)

에러가 뜨면 위에서 아래로 훑지 말고, 맨 아랫줄부터 읽으세요. 마지막 줄이 '에러 종류: 이유' 형식입니다. 그 위에서 'File "...", line NN' 중 내 파일 이름이 있는 가장 아래 줄을 찾습니다. 🙋나

**복사·실행 예시**

```text
맨 아랫줄: NameError: name 'total' is not defined  → 종류=NameError, 이유='total'을 정의 안 함. 바로 위 'File "app.py", line 12'가 범인 줄.
```

### 2단계 — 에러 종류로 원인 좁히기 (3분)

종류 이름만 보고 카테고리를 판단하세요. NameError=오타/정의 안 한 변수, TypeError=자료형 안 맞음, IndexError/KeyError=없는 위치·키 접근, ModuleNotFoundError=설치·import 문제, IndentationError/SyntaxError=띄어쓰기·문법. 🙋나

**복사·실행 예시**

```text
KeyError: 'price' → 딕셔너리에 'price' 키가 없다는 뜻. data.get('price')로 바꾸거나 키 이름 오타를 확인.
```

### 3단계 — 범인 줄을 print로 들여다보기 (3분)

에러 난 줄 바로 위에 print()를 넣어 그 시점 변수값을 눈으로 확인하세요. 값이 None인지, 빈 리스트인지, 예상과 다른 타입인지 드러납니다. 확인 후 print는 지웁니다. 🙋나

**복사·실행 예시**

```text
line 12 위에 print('DEBUG total =', total, type(total)) 추가 → 출력이 'DEBUG total = None' 이면 total에 값이 안 담긴 것.
```

### 4단계 — AI에게 트레이스백 통째로 붙여넣기 (2분)

에러 메시지 첫 줄부터 마지막 줄까지 전부 복사해 AI에 붙이세요. 요약하지 말고 원문 그대로. 문제 코드도 함께 붙이면 정확도가 급상승합니다. 🤖A

**복사·실행 예시**

```text
'아래 파이썬 에러의 원인과 정확한 수정 코드를 알려줘. [트레이스백 전체] + [해당 함수 코드]' 를 붙여넣기.
```

### 5단계 — 한 번에 하나만 고치고 다시 실행 (3분)

AI가 여러 수정을 제안해도 한 개만 적용하고 즉시 실행하세요. 여러 개를 동시에 바꾸면 뭐가 효과였는지 모릅니다. 에러가 바뀌면 진전한 것 — 새 에러로 1단계 반복. 🤝함께

**복사·실행 예시**

```text
NameError 고쳤더니 이제 TypeError가 뜸 → 이건 실패가 아니라 한 계단 전진. 새 트레이스백으로 다시 1단계.
```

### 6단계 — 고친 이유를 한 줄로 메모 (2분)

해결되면 '무슨 에러를 왜 어떻게 고쳤는지'를 코드 주석이나 메모장에 한 줄 남기세요. 같은 에러가 다음에 또 나면 즉시 알아봅니다. 🙋나

**복사·실행 예시**

```text
# 2026-07-03 KeyError 'price' — API 응답 키가 'cost'였음. data['cost']로 수정.
```

## 흔한 실수와 교정
- **실수:** 에러를 위에서부터 읽다가 지레 겁먹고 코드를 통째로 갈아엎는다.
  - **교정:** 맨 아랫줄(에러 종류+이유)과 내 파일 줄 번호 딱 두 곳만 먼저 본다. 대부분 한두 줄 수정으로 끝난다.
- **실수:** AI에게 '에러 났어요'라고만 하고 트레이스백을 붙이지 않는다.
  - **교정:** 에러 메시지 첫 줄부터 끝까지 원문 그대로 복사해 붙인다. 요약하면 진짜 원인 줄이 사라져 AI도 못 맞힌다.
- **실수:** AI 제안을 여러 개 한꺼번에 적용하고 실행한다.
  - **교정:** 한 번에 하나만 바꾸고 즉시 실행한다. 에러가 바뀌면 진전 신호이니 새 트레이스백으로 다시 시작한다.

## 완료 체크리스트

- 맨 아랫줄에서 에러 종류와 이유를 확인했다
- 트레이스백에서 내 파일·내 줄 번호를 찾았다
- 에러 종류로 원인 카테고리를 좁혔다
- 범인 줄 위에 print를 넣어 변수값을 눈으로 봤다
- 트레이스백 전체를 AI에 붙여 수정안을 받았다
- 한 번에 하나만 고쳐 다시 실행하고, 고친 이유를 한 줄 메모했다

## 참고 답안

① 맨 아랫줄: TypeError, 'int'와 'str'을 더할 수 없음 ② 종류: TypeError=자료형 안 맞음 → input()은 항상 문자열을 반환한다는 게 원인 후보 ③ print(type(total), type(입력값)) 찍어보면 <class 'str'> 확인 ④ AI에게 트레이스백+코드 붙여넣기 → "input() 결과를 int()로 변환하세요" 답변 받음 ⑤ total = total + int(input("가격 입력: ")) 로 한 줄만 수정 후 재실행 ⑥ 메모: "input()은 항상 str, 숫자 계산 전엔 int()/float() 변환 필수"
