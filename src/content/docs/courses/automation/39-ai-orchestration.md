_여러 AI·도구 단계를 순서·분기·병렬로 엮는 워크플로 설계._

:::note[학습 목표]

> "AI한테 한 번에 다 시키면 어중간한 결과가 나옵니다. 진짜 고수는 AI를 '한 명'이 아니라 '여러 단계로 흐르는 공장 라인'처럼 씁니다."

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 리서치→초안→검수→교정 4단계를 각각 다른 프롬프트로 엮은 '나만의 블로그 글 자동 생산 워크플로'를 만들어 실제 글 1편을 뽑아낼 수 있습니다.

## 핵심 개념

오케스트레이션은 하나의 큰 요청을 작은 단계로 쪼개고, 각 단계의 출력을 다음 단계의 입력으로 넘기는 설계입니다. 요리로 치면 '손질→볶기→간보기→플레이팅'처럼 순서(sequence)가 있고, 재료에 따라 길이 갈리는 분기(branch), 여러 냄비를 동시에 올리는 병렬(parallel)이 있습니다. AI 한 번 호출은 실수해도, 각 단계에 '검수 단계'를 끼워 넣으면 앞 단계 오류를 뒤 단계가 잡아냅니다. 핵심은 '한 프롬프트가 하나의 일만 잘하게' 만드는 것입니다. 이 구조를 손으로 몇 번 돌려보면, 나중에 Zapier·Make 같은 자동화 도구로 그대로 옮길 수 있습니다.

### 왜 작동하는가

AI에게 큰 일을 통째로 맡기면, 사람이 회의 한 번에 기획·집필·검토를 다 끝내라는 것과 같아서 결과가 어중간해집니다. 그런데 작업을 리서치→초안→검수→교정처럼 작은 단계로 쪼개서 넘기면, 각 AI 호출은 딱 한 가지만 잘하면 되니 품질이 확 올라갑니다. 그래서 당신은 단계를 설계하고 결과를 이어붙이기만 하면, 나머지 실행은 AI가 대신합니다.

## 👀 따라하기 예시

주제: "재택근무 생산성 팁" 블로그 글 1편 만들기. 제가 먼저 리서치→초안→검수→교정 4단계를 처음부터 끝까지 돌려볼게요, 눈으로 따라오세요.

### 1. ① 리서치 프롬프트만 실행: "재택근무 생산성 팁의 핵심 포인트 5개를 - 포인트: / - 근거: 형식의 불릿으로만 출력해줘"

**실제 결과**

```text
- 포인트: 고정 출퇴근 시간 만들기 / 근거: 경계가 없으면 업무·휴식이 뒤섞여 피로 누적\n- 포인트: 하루 3대 우선순위만 정하기 / 근거: 할 일이 많아 보여도 실제 성과는 소수 작업에서 나옴\n- 포인트: 알림 몰아서 확인하기 / 근거: 잦은 알림 확인이 집중 흐름을 30초씩 깎아먹음\n- 포인트: 전용 작업 공간 두기 / 근거: 공간이 뇌에 "지금은 일하는 시간"이라는 신호를 줌\n- 포인트: 하루 끝 5분 회고 쓰기 / 근거: 오늘 뭘 끝냈는지 적어야 내일 우선순위가 명확해짐
```

> 리서치 단계는 글쓰기를 섞지 않고 "불릿+근거"만 뽑아야, 다음 단계가 재료를 깔끔하게 받아먹습니다.

### 2. ② 이 불릿 5개를 그대로 복사해 초안 프롬프트에 붙여넣기: "아래 핵심 포인트로 800자 블로그 초안만 써줘(설명·인사말 금지): [불릿 5개]"

**실제 결과**

```text
(800자 분량 초안 예시) "재택근무 3년 차, 저는 매일 같은 실수를 반복했습니다... 첫째, 출퇴근 시간을 고정하세요... 둘째, 하루 3개 우선순위만..." (이하 생략 — 5개 포인트를 순서대로 풀어쓴 완결된 글)
```

> 초안 프롬프트는 "글만 출력, 인사말 금지"로 못박아야 다음 검수 단계에 바로 넣을 수 있는 깨끗한 텍스트가 나옵니다.

### 3. ③ 초안을 검수 프롬프트에 그대로 붙여넣기: "이 글의 사실·논리 오류를 지적하고 PASS 또는 FAIL로 판정해줘"

**실제 결과**

```text
FAIL — "생산성이 40% 오른다"는 수치에 출처 없음. 3번째 문단이 "알림 끄기"에서 갑자기 "회의 줄이기"로 논리 비약.
```

> PASS/FAIL을 강제로 출력시키면, 사람이 매번 품질을 직접 판단하지 않아도 되는 자동 품질 게이트가 생깁니다.

### 4. ④ FAIL 지적사항 두 줄을 들고 다시 ②초안 프롬프트로 돌아가기(분기): "아래 지적을 반영해 다시 써줘: [지적 2줄]" → 재생성된 글을 다시 ③에 넣어 PASS 받으면 교정 단계로 진행

**실제 결과**

```text
PASS — 수치 삭제, 문단 순서 조정으로 논리 흐름 자연스러워짐. 최종 교정본 완성.
```

> FAIL이면 처음부터 다시 하는 게 아니라 초안 단계로만 되돌리는 것이 분기의 핵심 — 앞 단계를 통째로 버리지 않습니다.

### 완성 결과

완성물: "재택근무 생산성 팁" 최종 블로그 글 1편 + 4단계 각각의 출력 기록. 좋은 결과의 기준: (1) 각 단계 출력이 다음 단계에 손질 없이 바로 들어갔는가 (2) 검수에서 FAIL이 한 번이라도 걸려 실제로 교정되었는가 (3) 최종본에 근거 없는 수치·논리 비약이 남아있지 않은가.

## 단계별 따라하기

### 1단계 — 워크플로를 종이에 그리기 (5분) 🙋나

만들 결과물 1개를 정하고, 그 결과가 나오기까지의 단계를 화살표로 적으세요. 각 단계는 '입력→(AI가 하는 일)→출력' 형태로 한 줄씩. 순서형인지, 조건에 따라 갈라지는지(분기), 동시에 돌려도 되는지(병렬) 표시합니다.

**복사·실행 예시**

```text
목표: 블로그 글 1편. [주제] → ①리서치(핵심 포인트 5개) → ②초안(800자) → ③검수(사실·논리 오류 지적) → ④교정(지적 반영해 최종본). ③에서 '큰 오류 있음'이면 ②로 되돌림(분기).
```

### 2단계 — 각 단계를 '단일 임무' 프롬프트로 쪼개기 (7분) 🤝함께

단계마다 프롬프트를 따로 만듭니다. 한 프롬프트에 두 가지 일(리서치+글쓰기)을 섞지 마세요. 각 프롬프트 끝에 '출력 형식'을 못박아 다음 단계가 받아먹기 쉽게 합니다.

**복사·실행 예시**

```text
①리서치 프롬프트 출력형식: '- 포인트: / - 근거:' 불릿 5개만. ②초안 프롬프트는 이 불릿을 입력으로 받아 800자 글만 출력(설명·인사말 금지).
```

### 3단계 — 순서대로 손으로 돌려보기 (8분) 🤖A

ChatGPT/Claude 새 대화에서 ①프롬프트 실행→나온 출력을 복사→②프롬프트의 [입력] 자리에 붙여넣고 실행. 이렇게 ①→②→③→④를 이어서 굴립니다. 각 단계 출력을 메모장에 라벨 붙여 보관하세요.

**복사·실행 예시**

```text
①이 준 불릿 5개를 복사 → ②초안 프롬프트의 '핵심 포인트: [여기]'에 붙여넣기 → 800자 초안 생성 → 그 초안을 ③검수 프롬프트에 넣기.
```

### 4단계 — 검수·분기 단계로 품질 게이트 만들기 (7분) 🤖A

③검수 프롬프트에 'PASS/FAIL과 이유'를 반드시 출력하게 하세요. FAIL이면 지적사항을 들고 ②로 돌아가 다시 초안을 만드는 게 분기입니다. 사람이 이 판정을 보고 루프를 돌립니다.

**복사·실행 예시**

```text
검수 출력: 'FAIL — 통계 수치 출처 없음, 3번째 문단 논리 비약'. → 이 두 줄을 ②초안 프롬프트에 '아래 지적을 고쳐 다시 써줘'로 붙여 재생성.
```

### 5단계 — 병렬 단계 하나 추가해 속도 체험 (5분) 🤝함께

서로 의존하지 않는 두 작업은 동시에 돌립니다. 예: 본문 초안과 '제목 후보 10개'는 서로 안 기다려도 됩니다. 브라우저 탭 2개에서 동시에 실행해 마지막에 합치세요.

**복사·실행 예시**

```text
탭A: ②초안 생성 중. 탭B: '이 주제로 클릭 유도형 제목 10개' 동시 생성. 둘 다 끝나면 최종본에 제목 1개 골라 붙이기.
```

### 6단계 — 전체를 하나의 실행 카드로 문서화 (6분) 🙋나

각 단계 이름·프롬프트·입력출처·출력형식을 표 한 장에 정리하세요. 이 카드가 있으면 다음엔 주제만 바꿔 5분 만에 다시 돌리고, 나중에 Make/Zapier로 그대로 옮길 수 있습니다.

**복사·실행 예시**

```text
| 단계 | 입력 | 프롬프트 | 출력 | 다음 | 형태 | 표에 4행 채우고 파일명 'blog-workflow-v1.md'로 저장.
```

## 흔한 실수와 교정
- **실수:** 한 프롬프트에 리서치·글쓰기·교정을 다 몰아넣어 결과가 어중간해진다.
  - **교정:** 단계당 임무 1개 원칙. 리서치 프롬프트와 글쓰기 프롬프트를 물리적으로 분리하고, 앞 단계 출력을 뒤 단계 입력으로만 넘긴다.
- **실수:** 검수 단계 없이 첫 출력을 그냥 최종본으로 쓴다.
  - **교정:** PASS/FAIL을 강제하는 검수 단계를 끼우고, FAIL이면 지적을 들고 초안 단계로 되돌리는 분기를 사람이 직접 한 번 돈다.
- **실수:** 각 단계 출력 형식을 안 정해서 다음 단계에 붙일 때마다 손으로 다듬는다.
  - **교정:** 프롬프트 끝에 '출력 형식: 불릿 5개' 처럼 형식을 못박아 다음 단계가 그대로 복붙되게 만든다.

## 완료 체크리스트

- 만들 결과물 1개를 정하고 단계를 화살표로 그렸다
- 각 단계를 임무 1개짜리 프롬프트로 분리했다
- ①→②→③→④를 손으로 이어서 한 번 완주했다
- PASS/FAIL 검수 단계로 최소 1회 재작성을 돌렸다
- 전체를 실행 카드(표)로 저장해 재사용 가능하게 만들었다

## 도구

- ChatGPT (https://chat.openai.com) — 단계별 프롬프트 실행·검수
- Claude (https://claude.ai) — 긴 초안 작성·논리 검수에 강함
- Make (https://make.com) — 손workflow를 시각적 자동화로 이관
- Google Docs (https://docs.google.com) — 단계별 출력 라벨링·보관

## 직접 만들기 (미션)

:::tip
이번엔 당신 차례! 주제를 "1인 가구 자취 요리 꿀팁"으로 바꿔서 리서치→초안→검수→교정 4단계를 직접 손으로 돌려보세요. 리서치 프롬프트 하나, 초안 프롬프트 하나, 검수 프롬프트 하나를 각각 새 대화창에서 실행하고, 출력을 순서대로 이어붙이세요. 검수에서 FAIL이 나오면 반드시 초안 단계로 되돌려 최소 1회 재생성하세요.
:::

## 채점 기준

| 기준 | 배점 |
| --- | --- |
| 리서치 프롬프트와 초안 프롬프트에 서로 다른 임무 하나씩만 넣었나요, 아니면 섞였나요? | 5 |
| 검수 단계가 "PASS/FAIL과 이유"를 실제로 출력하도록 형식을 못박았나요? | 5 |
| FAIL이 나왔을 때 초안 단계로 정확히 되돌려 재생성했나요, 아니면 그냥 넘어갔나요? | 5 |
