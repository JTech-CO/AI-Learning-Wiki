_코딩 전에 문제의 빈도·고통·지불의사를 확인하고, 이미 돈을 쓰는 '진통제형' 문제인지 판별하는 아이디어 검증 체크리스트를 가르친다._

:::note[학습 목표]
- 이 레슨이 끝나면, 코딩을 시작하기 전에 아이디어의 빈도·고통·지불의사를 점수로 매겨 '만들 가치가 있는가'를 스스로 판정할 수 있습니다.

> "좋은 아이디어 같아서 3개월 코딩했는데 아무도 안 쓴다" — 인디 개발자가 망하는 방식 1위입니다. 코드 한 줄 짜기 전에, 이 아이디어가 '진통제'인지 '비타민'인지 5일 안에 판별해봅시다.

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 코딩을 시작하기 전에 아이디어의 빈도·고통·지불의사를 점수로 매겨 '만들 가치가 있는가'를 스스로 판정할 수 있습니다.

## 핵심 개념

SaaS 아이디어에는 두 종류가 있습니다. '비타민'(있으면 좋지만 없어도 사는 것)과 '진통제'(당장 아파서 돈 주고라도 없애고 싶은 것). 사람들은 진통제에만 지갑을 엽니다. 검증이란 '내 아이디어가 진통제인가'를 코드 없이 확인하는 과정이며, 핵심 3축은 빈도(문제가 얼마나 자주 발생하나)·고통(얼마나 괴로운가)·지불의사(이미 돈이나 시간을 쓰고 있나)입니다. 특히 '이미 엑셀·수작업·경쟁 툴에 돈을 쓰고 있다'는 신호가 가장 강력한 진통제 증거입니다.

### 왜 작동하는가

AI는 수천 개의 인터뷰·리뷰·커뮤니티 글을 순식간에 훑어서 "이 문제가 진짜 사람들을 괴롭히는지" 패턴을 잡아냅니다. 그래서 당신은 문제 한 문장과 질문만 던지면, AI가 문장을 날카롭게 다듬고 검증 항목을 짜주는 동안 당신은 진짜 사람 5명 인터뷰에만 집중하면 됩니다.

## 👀 따라하기 예시

"동네 필라테스 스튜디오 사장님들이 예약 노쇼 때문에 골치 아프다더라" — 이 아이디어 하나로 코딩 없이 검증까지 가는 과정을, 제가 먼저 처음부터 끝까지 보여드릴게요. 눈으로 따라오세요.

### 1. ① AI에게 문제 문장 다듬기를 시킨다

**실제 결과**

```text
"필라테스 스튜디오 사장님이(who) / 예약 취소 시간이 임박했을 때(when) / 노쇼로 그 시간대 매출이 그냥 날아간다(pain)" — 해결책 말고 문제만 남겼습니다.
```

> 해결책("노쇼 방지 앱 만들자")부터 말하면 확증편향에 빠집니다. AI는 감정 없이 "문제만" 걸러줍니다.

### 2. ② AI에게 3축 채점표를 만들어 달라고 한다

**실제 결과**

```text
빈도 4(수업마다 반복)·고통 4(그 시간대 매출 그대로 손실)·지불의사 3(일부는 예약 문자 서비스에 이미 돈 씀) = 11점 → "비타민에 가깝지만 애매하니 인터뷰로 확인 필요"
```

> 12점 미만이면 AI가 스스로 "확신 부족, 검증 더 필요"라고 경고해줍니다. 숫자가 결정을 감정에서 꺼내줍니다.

### 3. ③ AI에게 인터뷰 질문 5개를 뽑아 달라고 한다

**실제 결과**

```text
"마지막으로 노쇼가 생긴 게 언제였나요?" "그때 어떻게 대처하셨어요?" "노쇼 방지에 지금 쓰는 돈이나 방법이 있나요?" 등 전부 과거형 질문
```

> 미래형("쓰실 것 같아요?")은 예의상 답이 나옵니다. AI가 과거형 질문만 골라주면 거짓 긍정을 막습니다.

### 4. ④ AI에게 스모크 테스트 랜딩페이지 문구 초안을 시킨다

**실제 결과**

```text
헤드라인 "노쇼 걱정, 문자 한 통으로 끝" + "사전예약 등록하기" 버튼 문구 초안 생성
```

> 문구까지 AI가 초안을 뽑아주면 당신은 실제 방문자 확보와 등록률 관찰에만 시간을 씁니다.

### 완성 결과

완성물은 "문제 한 문장 + 3축 점수표 + 인터뷰 질문지 + 랜딩페이지 초안" 4종 세트입니다. 좋은 결과의 기준: (1) 해결책이 아니라 문제만 담겼는가, (2) 점수와 인터뷰가 서로 다른 이야기를 하지 않는가, (3) 랜딩페이지에 아직 아무 기능도 없는가(코드 0줄).

## 단계별 따라하기

### 1단계 — 문제 한 문장으로 못박기 (10분)

'누가(who) / 언제(when) / 무엇 때문에 괴롭다(pain)' 형식으로 한 문장을 쓴다. 해결책이 아니라 문제만 쓴다. AI에게 문장을 날카롭게 다듬어 달라고 시킨다. 🤝함께

**복사·실행 예시**

```text
'프리랜서 디자이너가(who) 월말 정산할 때(when) 여러 플랫폼 수입을 엑셀로 합치느라 2시간을 쓴다(pain)' — '앱을 만든다'가 아니라 이렇게 문제만 적는다.
```

### 2단계 — 진통제/비타민 3축 점수내기 (10분)

빈도·고통·지불의사 3개를 각각 1~5점으로 매긴다. 빈도=얼마나 자주, 고통=얼마나 괴로운지, 지불의사=지금 이 문제에 돈이나 시간을 이미 쓰는지. 합이 12점 미만이면 비타민일 가능성이 높으니 접거나 문제를 바꾼다. 🙋나

**복사·실행 예시**

```text
빈도 4(매월)·고통 3(짜증나지만 참을 만)·지불의사 2(무료 엑셀로 버팀) = 9점 → 비타민 쪽. 반대로 '자영업자 부가세 신고'는 빈도3·고통5·지불의사5 = 13점 → 진통제.
```

### 3단계 — 이미 쓰는 돈·시간 추적하기 (30분)

타겟이 이 문제에 이미 무엇을 쓰는지 조사한다. 경쟁 유료툴 검색, 관련 커뮤니티·카페·레딧에서 '이거 어떻게들 하세요' 검색. 유료 대안이 존재하고 사람들이 불평까지 하고 있으면 최고의 신호다. 🤖A

**복사·실행 예시**

```text
'프리랜서 수입 정산'을 검색 → 유료툴 3개 발견 + 카페에 '엑셀 너무 귀찮다' 글 12개 → 이미 시장이 돈·시간을 쓰고 있음 확인.
```

### 4단계 — 실제 사람 5명에게 문제 인터뷰 (2~3일)

타겟 5명에게 '요즘 X할 때 가장 귀찮은 게 뭐예요?'라고 묻는다. 절대 내 아이디어를 먼저 말하지 않는다(그러면 예의상 좋다고 함). 과거 행동만 캐묻는다: '마지막으로 그거 언제 했어요? 그때 어떻게 해결했어요? 돈 썼어요?' 🙋나

**복사·실행 예시**

```text
카톡 오픈채팅·단골 커뮤니티에 DM. '지난달에 정산 어떻게 하셨어요?' → 4명이 '그냥 엑셀로 노가다' → 실재하는 반복 고통 확인.
```

### 5단계 — 스모크 테스트로 지불의사 검증 (1일)

코드 대신 랜딩페이지 1장을 만든다. 문제·해결약속·가격·'사전예약/대기자 등록' 버튼만. 지인·커뮤니티에 뿌리고 이메일 등록률을 본다. 방문 대비 5% 이상 등록되면 지불의사 신호. 🤝함께

**복사·실행 예시**

```text
Carrd로 '프리랜서 정산 5분에 끝내기 — 사전예약' 페이지 제작 → 40명 방문 중 6명 이메일 등록(15%) → 만들 가치 있음.
```

### 6단계 — 종합 판정 및 결정 (10분)

3축 점수 + 인터뷰 + 스모크 결과를 한 표에 모아 GO/PIVOT/KILL을 정한다. 3축 12점 이상 + 인터뷰에서 반복 고통 + 등록률 5% 이상이면 GO. 하나라도 크게 미달이면 문제를 좁히거나(PIVOT) 버린다(KILL). 🙋나

**복사·실행 예시**

```text
점수 13 + 인터뷰 4/5 반복고통 + 등록 15% → GO. 반면 점수 9 + 인터뷰 미지근 + 등록 1% → KILL하고 다음 아이디어로.
```

## 흔한 실수와 교정
- **실수:** 인터뷰에서 내 아이디어를 먼저 설명하고 '어때요?'라고 묻는다.
  - **교정:** 아이디어는 숨기고 과거 행동만 물어라. '마지막으로 그 일 언제 했고, 어떻게 해결했고, 돈 썼나요?' 미래 의향('쓸 것 같아요')이 아니라 과거 사실만 신뢰한다.
- **실수:** '경쟁자가 있으니 안 된다'며 포기한다.
  - **교정:** 경쟁 유료툴의 존재는 오히려 지불의사가 증명된 진통제 시장이라는 신호다. 시장이 없는 게 더 위험하다. 좁은 틈새·특정 타겟으로 파고들 여지를 찾아라.
- **실수:** 검증 없이 '나라면 쓸 텐데'라는 자기 확신으로 바로 코딩한다.
  - **교정:** 나 자신은 표본 1명이자 편향의 정점이다. 코드 전에 5명 인터뷰 + 스모크 테스트 등록률이라는 외부 증거부터 확보하라.

## 완료 체크리스트

- 문제를 '누가/언제/무엇 때문에 괴롭다' 한 문장으로 적었다
- 빈도·고통·지불의사 3축을 점수로 매겨 합이 12점 이상인지 확인했다
- 타겟이 이미 쓰는 유료 대안·수작업을 조사했다
- 실제 타겟 5명에게 과거 행동 기반으로 인터뷰했다
- 랜딩페이지 스모크 테스트로 이메일 등록률(지불의사)을 측정했다

## 도구

- Carrd (carrd.co) — 코드 없이 스모크 테스트 랜딩페이지 1장 제작
- Google Forms (forms.google.com) — 인터뷰 응답·사전예약 이메일 수집
- Reddit / 네이버 카페 — 타겟이 이미 불평하는 곳에서 진통제 신호 탐색
- ChatGPT·Claude (chatgpt.com / claude.ai) — 문제 다듬기·조사·인터뷰 질문 생성

## 채점 기준

| 기준 | 배점 |
| --- | --- |
| 내가 쓴 문제 문장에 해결책 단어("앱", "만든다")가 섞여 있지 않은가? | 5 |
