_노코드 자동화(Zapier·Make·n8n)와 AI를 엮어 '유입 → 결제 → 전달 → 후속 마케팅'이 사람 손 없이 돌아가는 수익 파이프라인 1개를 설계·점검한다. 자동화의 진짜 의미(반복 작업 제거)와 한계(품질 감시·장애 대응은 여전히 필요)를 구분한다._

:::note[학습 목표]
- 노코드 자동화 도구(Zapier·Make·n8n)와 AI를 엮어 '유입 → 결제 → 전달 → 후속 마케팅'이 사람 손 없이 흐르는 수익 파이프라인 1개를 설계하고, 어디까지 자동화하고 어디서 사람이 개입할지 정한다.

> 주문이 들어오면 → 결제 → 파일 전달 → 후속 메일까지, 내가 자는 동안 자동으로 돌아간다면? 노코드 자동화 + AI로 '수익 파이프라인' 1개를 설계한다.

## 이 레슨에서 만드는 것

노코드 자동화 도구(Zapier·Make·n8n)와 AI를 엮어 '유입 → 결제 → 전달 → 후속 마케팅'이 사람 손 없이 흐르는 수익 파이프라인 1개를 설계하고, 어디까지 자동화하고 어디서 사람이 개입할지 정한다.

## 핵심 개념

자동화의 본질은 '반복되는 손작업을 한 번 만들어 두고 기계가 대신하게 하는 것'이다. 디지털 상품 판매를 예로 들면 '주문 알림 확인 → 결제 확인 → 파일 보내기 → 감사 메일 → 후기 요청'이 매번 반복된다. 이걸 노코드 도구(Zapier·Make·n8n)로 한 번 연결해 두면, 고객이 결제할 때마다 자동으로 흐른다. AI는 이 흐름에 '지능'을 더한다 — 고객 문의를 분류하거나, 맞춤 후속 메일 문구를 생성하는 식이다. 핵심 개념은 '트리거(방아쇠) → 액션(동작)'이다: '결제 완료(트리거)되면 → 파일 전송 + 감사 메일(액션)'. 하지만 자동화에는 분명한 한계가 있다. (1)품질 감시: 자동 생성된 메일이 이상하지 않은지 가끔 점검해야 한다. (2)장애 대응: 결제 오류·파일 누락 같은 예외는 사람이 처리한다. 그래서 '완전 무인'이 아니라 '반복은 자동, 예외·판단은 사람'이 현실적 목표다. 처음엔 흐름 전체를 자동화하려 말고, 가장 자주·귀찮게 반복되는 한 구간부터 자동화한다.

### 왜 작동하는가

자동화 도구는 "이런 일이 생기면(트리거) 이렇게 한다(액션)"는 규칙을 한 번만 만들어두면, 그 뒤로는 몇 번이든 똑같이 반복해줍니다. 사람이 매번 "결제됐나 확인 → 파일 보내기 → 메일 쓰기"를 손으로 하는 대신, Zapier 같은 도구가 24시간 그 자리에서 대기하다가 트리거가 뜨는 순간 바로 실행하는 거예요. 그래서 당신은 "무엇을, 언제, 어떻게" 딱 한 번만 설계하면 되고, 그 다음 반복 실행은 도구가 대신합니다.

## 👀 따라하기 예시

온라인으로 PDF 전자책을 파는 1인 셀러 상황 — "결제 후 후속 메일"을 자동화하고 싶어요. 제가 먼저 처음부터 끝까지 설계해볼게요, 눈으로 따라오세요.

### 1. ① 반복 흐름을 트리거→액션으로 그린다

**실제 결과**

```text
[결제 완료] → [PDF 자동 전달] → [감사+사용법 메일] → [3일 후 후기 요청 메일]
```

> 흐름을 그림으로 그려야 "어디가 반복이고 어디서 귀찮은지"가 눈에 보여요. 이게 자동화 설계도예요.

### 2. ② 가장 귀찮은 구간 1개만 고른다

**실제 결과**

```text
선택: "감사+사용법 메일 자동 발송" (매번 손으로 쓰기 가장 귀찮았던 구간)
```

> 전체를 한 번에 자동화하려면 지쳐서 포기해요. 제일 반복·귀찮은 딱 1구간부터 시작하는 게 핵심 아하 포인트예요.

### 3. ③ Zapier에서 트리거-액션을 연결한다

**실제 결과**

```text
Zap 설정: 트리거="새 결제(Gumroad)" → 액션="Gmail로 사용법 메일 발송" → 테스트 결제 1건으로 확인 완료
```

> 노코드 도구는 프로그래밍 없이 "일어나면 → 한다"를 클릭 몇 번으로 연결해줘요. 무료 플랜으로도 이 정도는 충분해요.

### 4. ④ AI로 지능을 더하고 사람 개입 지점을 정한다

**실제 결과**

```text
AI 단계 추가: 고객 문의 메일이 오면 AI가 "환불/사용법/기타"로 자동 분류 → 환불 건만 저에게 알림, 나머지는 AI가 초안 자동 응답. 저는 "환불 요청"과 "주간 메일 점검"만 직접 확인하기로 정함.
```

> 자동화는 반복은 없애지만 판단은 못 없애요. "사람이 반드시 볼 지점"을 미리 정해둬야 자동화를 믿고 맡길 수 있어요.

### 완성 결과

"결제→파일 전달→후속 메일"이 자동으로 도는 미니 파이프라인 1개 + 사람이 점검할 지점 목록. 좋은 결과의 기준: (1) 트리거-액션이 실제로 테스트에서 작동했는가, (2) 자동화 구간과 사람 개입 구간이 명확히 분리됐는가, (3) 가장 귀찮은 1구간부터 작게 시작했는가.

## 단계별 따라하기

### 1. 내 사업의 반복 흐름을 '트리거→액션'으로 그린다

종이에 '무슨 일이 생기면(트리거) → 무엇을 한다(액션)'을 순서대로 적는다. 예: 결제됨→파일 전송→감사 메일→3일 후 후기 요청. 이 그림이 자동화 설계도다. 어디가 가장 자주·귀찮은지 표시한다.

**복사·실행 예시**

```text
흐름: [결제 완료] → [상품 PDF 자동 전달] → [감사+사용법 메일] → [3일 후 후기 요청 메일]
```

### 2. 가장 귀찮은 '한 구간'부터 자동화한다

전체를 한 번에 하려다 지친다. 빈도·귀찮음이 가장 큰 1구간을 고른다(보통 '파일 전달' 또는 '후속 메일'). 판매 플랫폼이 이미 파일 자동전달을 지원하면 그 다음 단계(후속 메일)부터 도구로 연결한다.

**복사·실행 예시**

```text
고른 구간: '결제 후 사용법+후기 요청 메일 자동 발송'
```

### 3. 노코드 도구에서 트리거-액션을 연결한다

Zapier·Make·n8n 중 하나를 고른다(처음엔 Zapier가 가장 쉽다). '트리거 앱'(예: 결제·폼·이메일 수신)과 '액션 앱'(예: 이메일 발송·시트 기록)을 골라 연결한다. 무료 플랜으로 간단한 흐름은 충분히 만든다.

**복사·실행 예시**

```text
Zapier: [새 주문(트리거)] → [Gmail로 사용법 메일 발송(액션)] 연결
```

### 4. AI로 '지능'을 더하고, 사람 개입 지점을 정한다

흐름 안에 AI 단계를 끼운다 — 예: 고객 문의를 AI가 '환불/사용법/기타'로 분류, 또는 후속 메일 문구를 AI가 생성(아래 templates). 동시에 '사람이 반드시 볼 지점'을 정한다: 환불 요청, 자동 메일 주간 점검, 결제 오류 알림. 이 안전장치가 자동화를 '믿을 수 있게' 만든다.

**복사·실행 예시**

```text
AI 단계: 문의 메일을 AI가 분류 → 환불 건만 나에게 알림 / 나머지는 자동 응답 초안
```

## 흔한 실수와 교정
- **실수:** 처음부터 흐름 전체를 한 번에 자동화하려다 복잡해서 포기한다
  - **교정:** 가장 귀찮은 1구간부터. 작은 자동화 1개가 도는 걸 본 뒤 늘려라. 큰 설계는 미루고 작게 시작한다.
- **실수:** '완전 무인'을 기대하고 사람 점검을 0으로 만든다
  - **교정:** 자동화는 반복을 없애지 판단·예외를 없애지 않는다. 환불·오류·품질은 사람이 본다. 주기적 점검 지점을 반드시 남겨라.
- **실수:** 자동 발송 메일을 만들어 두고 한 번도 다시 안 읽는다
  - **교정:** AI·자동 메일은 가끔 어색하거나 맥락이 틀린다. 주 1회 실제 발송된 메일을 점검해 품질을 지켜라.
- **실수:** 유료 자동화 플랜부터 결제한다
  - **교정:** 대부분 무료 플랜으로 간단한 흐름은 충분하다. 실제로 자동화가 도는 걸 확인한 뒤 필요할 때만 유료로.

## 완료 체크리스트

- 반복 흐름을 '트리거→액션'으로 그렸다
- 가장 귀찮은 1구간을 골라 우선 자동화 대상으로 정했다
- 노코드 도구(Zapier 등)로 트리거-액션을 연결했다
- AI 단계(분류·문구 생성)를 흐름에 끼웠다
- 환불·오류·주간 점검 등 '사람 개입 지점'을 정했다

## 도구

- Zapier (zapier.com) — 가장 쉬운 노코드 자동화. 트리거-액션 연결, 무료 플랜으로 시작 가능.
- Make (make.com) / n8n (n8n.io) — 더 복잡한 흐름·분기에 강한 자동화 도구(n8n은 셀프호스팅 가능).
- ChatGPT / Claude API — 흐름 안에서 문의 분류·후속 메일 문구 생성 등 '지능' 단계 담당.
- Gmail / 이메일 발송 도구 — 자동 후속 메일 발송 액션(발송 전 문구는 사람이 1회 검수).

## 참고 답안

예시(온라인 클래스 판매): [결제 완료]→[줌 링크 자동 발송]→[전날 리마인드 메일]→[수강 후 만족도 조사]. 가장 귀찮은 구간="리마인드 메일" 선택 → Zapier로 "결제 D-1"을 트리거 삼아 Gmail 발송 액션 연결. AI 단계: 만족도 조사 답변을 AI가 "칭찬/불만/제안"으로 분류. 사람 개입 지점: 불만 답변은 반드시 직접 확인.

## 실전 프롬프트

### 자동화 흐름 설계

```text
나는 [PDF 디지털 상품(이메일 템플릿)]을 파는 1인 사업자야. 판매부터 사후관리까지 반복 업무를 노코드 자동화로 줄이고 싶어.
현재 수동으로 하는 일: [결제 확인 → 파일 전달 → 감사 메일 → 후기 요청]
1) 이 흐름을 '트리거 → 액션' 단계로 정리해줘.
2) 그중 '지금 바로 자동화하면 가장 이득인 1구간'을 골라줘.
3) 그 구간을 Zapier(또는 Make)로 연결하는 방법을 초보가 따라 할 수 있게 단계별로.
4) '사람이 반드시 직접 봐야 하는 예외 상황'도 알려줘.
```

### 후속 메일 문구 생성

```text
내 디지털 상품 [상황별 비즈니스 이메일 템플릿 30종 PDF]을 구매한 고객에게 보낼 자동 후속 메일 2종을 써줘.
1) [구매 직후] 감사 + 사용법 안내 메일 (따뜻하고 신뢰가게, 환불 없이 만족하도록)
2) [3일 후] 후기 요청 메일 (부담 없이, 후기 남기면 좋은 점 한 줄)
각 메일은 제목 + 본문. [고객명] 같은 자동 치환 변수를 대괄호로 넣어줘. 과장·스팸 느낌 없이.
```
