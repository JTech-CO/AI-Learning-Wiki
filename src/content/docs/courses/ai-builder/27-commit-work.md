_변경을 스테이징하고 의미 있는 메시지로 커밋해, 오늘 고치다 망가뜨려도 언제든 예전 상태로 정확히 되돌아올 수 있는 안전망을 스스로 만든다._

:::note[학습 목표]
- git add로 스테이징하고 git commit으로 확정하는 커밋 두 단계를 스스로 실행한다
- '무엇을 왜' 바꿨는지 미래의 내가 알아볼 수 있는 의미 있는 커밋 메시지를 쓴다
- git log --oneline으로 세이브 포인트를 확인하고 checkout으로 이전 상태로 되돌린다
:::

## 핵심 개념

Git 커밋은 **'지금 이 순간의 파일 상태'를 통째로 사진 찍어 영구 저장**하는 것이에요. 게임의 세이브 포인트처럼, 한번 커밋해 두면 나중에 무엇을 망가뜨려도 그 지점으로 정확히 되돌아올 수 있어요. 커밋은 두 단계예요 — 먼저 `git add`로 저장할 변경을 무대(스테이징)에 올리고, 그다음 `git commit`으로 메시지와 함께 확정합니다. 좋은 커밋 메시지는 '무엇을 왜 바꿨는지'를 미래의 나에게 설명하는 짧은 메모라서, 나중에 문제 지점을 찾을 때 **지도**가 돼요.

### 흐름

`git status`(뭐가 바뀌었나 확인) → `git add`(저장할 것만 무대에 올림) → `git commit -m`(메시지와 함께 확정) → `git log --oneline`(세이브 포인트 확인). 이 리듬 하나가 안전망 전체예요.

### 왜 이게 될까?

Git은 커밋할 때마다 파일 전체 상태를 사진 찍듯 저장소(`.git`)에 남겨둬요. 그래서 나중에 무엇을 망가뜨려도 "그 사진이 찍힌 시점"으로 정확히 돌아갈 수 있어요. 의미 있는 순간에 '셔터'(`git add` → `commit`)만 눌러주면, 되돌리기는 Git이 대신 기억해 줍니다.

## 👀 따라하기 예시 — index.html에 로그인 버튼을 추가하고 style.css도 살짝 고쳤는데 한 번도 커밋 안 한 상태

**① git status로 먼저 살펴보기**
```bash
$ git status
# Changes not staged for commit:
#   modified: style.css
# Untracked files:
#   index.html
```
> 💡 뭐가 바뀌었는지 모르고 커밋하면 실수로 엉뚱한 파일까지 끌려 들어가요. 커밋 전엔 항상 먼저 눈으로 확인하세요.

**② 원하는 파일만 골라 스테이징**
```bash
$ git add index.html style.css
# git status → Changes to be committed:
#   new file: index.html
#   modified: style.css
```
> 💡 '무대에 올린다'는 건 '이번 커밋에 포함시킬 것'을 고르는 거예요. 초록색(스테이징됨)이 된 걸 확인하는 게 핵심 아하 포인트!

**③ 의미 있는 메시지로 커밋 확정**
```bash
$ git commit -m "로그인 버튼 추가 및 버튼 색상 조정"
# [main 7f3a1c2] ... 2 files changed
```
> 💡 메시지는 '무엇을 왜' 했는지 현재형 동사로. '수정함'이 아니라 '로그인 버튼 추가'처럼 구체적으로 써야 미래의 내가 알아봐요.

**④ git log로 세이브 포인트 확인**
```bash
$ git log --oneline
# 7f3a1c2 로그인 버튼 추가 및 버튼 색상 조정
```
> 💡 앞의 7자리 해시가 이 순간의 주소예요. 이 주소만 있으면 언제든 이 상태로 정확히 돌아옵니다.

좋은 커밋의 기준: (1) `git status`에서 원하는 파일만 스테이징됐는가 (2) 메시지만 읽어도 무슨 변경인지 짐작되는가 (3) 한 커밋이 '기능 하나'처럼 딱 떨어지는 단위인가.

## 단계별 따라하기

1. **Git 설치 확인하고 저장소 만들기** — 터미널에서 `git --version`으로 설치를 확인한다. 안 깔려 있으면 git-scm.com에서 설치. 작업 폴더로 이동한 뒤 `git init`을 실행해 그 폴더를 Git 저장소로 만든다. (`$ git init` → `Initialized empty Git repository in ...`)
2. **이름·이메일 한 번만 설정하기** — 커밋에는 '누가' 했는지가 기록된다. 처음 한 번만 `git config --global user.name`과 `user.email`을 설정하면 이후 모든 커밋에 자동으로 붙는다. (`$ git config --global user.name "홍길동"` / `$ git config --global user.email "gildong@example.com"`)
3. **현재 상태 보고 변경을 스테이징하기** — `git status`로 어떤 파일이 새로 생기거나 바뀌었는지 확인한다. 빨간색으로 나온 파일 중 저장하고 싶은 것을 `git add 파일명`. 전부 올리려면 `git add .`. 다시 `git status`를 치면 초록색으로 바뀐다.
4. **의미 있는 메시지로 커밋하기** — `git commit -m "메시지"`로 확정한다. 메시지는 '무엇을 했는지'를 현재형 동사로 짧게. 예: '로그인 버튼 추가', '가격 계산 오류 수정'. 파일명이나 '수정함' 같은 모호한 말은 피한다. (메시지 문구는 AI에게 다듬어 받아도 좋다.)
5. **커밋 기록 확인하고 이전 상태 되돌려보기** — `git log --oneline`으로 세이브 포인트 목록을 본다. 각 줄 앞 7자리 코드가 그 커밋의 주소(해시)다. 파일을 일부러 망가뜨린 뒤 `git checkout -- 파일명`을 치면 마지막 커밋 상태로 즉시 복구된다. 이게 안전망이다.
6. **작은 단위로 자주 커밋하는 습관 굳히기** — 한 가지 일이 끝날 때마다 커밋한다. '하루치를 한 번에'가 아니라 **'기능 하나 = 커밋 하나'**가 원칙. 작은 변경 2개를 각각 따로 `add` → `commit` 해보며 리듬을 익힌다.

## 흔한 실수 → 교정

- ✗ `git add` 없이 바로 `git commit`을 쳐서 아무것도 커밋되지 않거나 원하지 않는 파일까지 다 들어감 → **커밋 전에 반드시 `git status`로 초록색(스테이징됨) 목록을 확인.** 원하는 파일만 `git add 파일명`으로 골라 올린 뒤 커밋한다.
- ✗ 커밋 메시지를 'update', '수정', 'ㅁㄴㅇㄹ'처럼 모호하게 써서 나중에 무슨 변경인지 전혀 알 수 없음 → **'무엇을 왜' 바꿨는지 현재형으로.** 예: '결제 금액 반올림 오류 수정'. 헷갈리면 커밋 메시지 템플릿으로 AI에게 다듬어 받는다.
- ✗ 하루 종일 작업한 걸 한 번에 몰아서 커밋해, 문제가 생겨도 어느 변경이 원인인지 되돌릴 지점이 없음 → **'기능 하나 = 커밋 하나' 원칙으로 작은 단위로 자주.** 그래야 정확히 그 지점만 골라 되돌릴 수 있다.

## 도구

- 🛠 **Git** (git-scm.com) — 버전 관리와 커밋의 핵심 도구.
- 🛠 **GitHub Desktop** (desktop.github.com) — 명령어 없이 클릭으로 add·commit 하는 GUI.
- 🛠 **ChatGPT** (chat.openai.com) — 커밋 메시지 다듬기·status 해석·실수 복구 도우미.
- 🛠 **VS Code** (code.visualstudio.com) — 편집기 안에서 변경과 커밋을 시각적으로 확인.

## 실전 프롬프트

### 커밋 메시지 다듬기 (가장 유용)

```text
나는 Git 초보야. 방금 한 작업은 다음과 같아: [무엇을 바꿨는지 편하게 설명]. 이걸 한 줄짜리 좋은 한국어 커밋 메시지로 만들어줘. 현재형 동사로 시작하고, 50자 이내로, '무엇을'이 명확하게. 후보 3개를 제시해줘.
```

> 확인된 작성 예시 없음

`커밋 메시지` `다듬기` `git`

### 내 git status 해석해줘

```text
아래는 내 'git status' 출력이야. 각 파일이 어떤 상태인지(추적 안 됨/스테이징됨/수정됨) 쉽게 설명하고, 지금 커밋하려면 어떤 명령을 순서대로 쳐야 하는지 알려줘. [git status 출력]
```

> 확인된 작성 예시 없음

`git status` `해석` `git`

### 실수 되돌리는 법 알려줘

```text
나는 Git 초보야. 방금 이런 실수를 했어: [파일을 잘못 수정함 / 커밋 메시지를 잘못 씀 / add를 취소하고 싶음]. 아직 push는 안 했어. 이걸 되돌리는 가장 안전한 명령을 한 단계씩, 각 명령이 무슨 일을 하는지 한 줄로 설명해줘.
```

> 확인된 작성 예시 없음

`되돌리기` `복구` `git`

### 오늘 한 작업을 커밋 단위로 쪼개줘

```text
오늘 내가 한 작업들은 다음과 같아: [작업들 나열]. 이걸 의미 있는 커밋 여러 개로 어떻게 나누면 좋을지, 각 커밋의 메시지와 'git add' 대상 파일 예시까지 제안해줘.
```

> 확인된 작성 예시 없음

`커밋 단위` `쪼개기` `git`
