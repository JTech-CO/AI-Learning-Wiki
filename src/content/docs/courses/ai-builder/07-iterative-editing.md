_한 번에 다 바꾸지 않고 작은 단위로 요청·확인·되돌리기를 반복하며 앱을 안전하게 개선하는 습관을 만든다. '버튼 색만 바꿔달라'고 했는데 앱 전체가 죽는 사고를, 변경을 하나로 쪼개고 체크포인트를 남기는 것으로 막는다._

:::note[학습 목표]
- 앱을 한 번에 하나씩만 고치도록 AI에게 범위를 좁혀 요청한다
- 변경한 뒤 바뀐 부분과 원래 되던 기능을 함께 확인한다
- 성공하면 체크포인트로 저장하고, 망가지면 5초 만에 직전 상태로 되돌린다
:::

## 핵심 개념

앱을 고칠 때 가장 위험한 순간은 **"이것저것 다 바꿔줘"라고 한 번에 크게 주문할 때**예요. 무언가 망가지면 다섯 개 변경 중 어느 것이 범인인지 알 수 없어 손도 못 대게 됩니다. 그래서 프로 개발자들은 **'작은 변경 → 바로 확인 → 문제 없으면 저장(커밋) → 다음 변경'**을 반복해요. 요리로 치면 소금을 한 숟갈씩 넣고 매번 맛보는 것과 같아요. 되돌리기(undo)와 저장 지점(체크포인트)만 확실히 잡아두면 어떤 실험도 두렵지 않습니다.

### 왜 이게 될까?

AI는 "지금까지 대화 전체"를 기억하며 코드를 고치기 때문에, 한 번에 여러 개를 시키면 어디서부터 꼬였는지 AI도 우리도 알 수 없게 됩니다. 반대로 딱 하나만 시키면 문제가 생겨도 범인은 항상 "방금 그 하나"뿐이라 되돌리기가 5초 만에 끝나요. 체크포인트(저장 지점)는 이 되돌리기를 가능하게 하는 안전벨트예요.

## 👀 따라하기 예시 — 로그인까지 잘 되는 앱에 "로그인 버튼을 파란색으로" 딱 하나의 변경

**① 지금 상태를 먼저 저장** — Lovable History에 "v1 - 로그인까지 정상" 체크포인트 생성.
> 💡 손대기 전에 안전지대부터 만들어야 실패해도 무섭지 않아요.

**② AI에게 "딱 하나만" 콕 집어 요청** — "메인 화면의 로그인 버튼 배경색만 파란색(#2563EB)으로 바꿔줘. 다른 코드나 레이아웃은 절대 건드리지 마." → 버튼 컴포넌트 한 곳의 색상 값만 수정됨.
> 💡 요청 범위를 좁힐수록 AI도 실수할 자리가 줄어요.

**③ 바뀐 것 + 원래 되던 것 둘 다 확인** — 미리보기에서 버튼이 파랗게 바뀐 것 확인, 버튼을 눌러 로그인 화면 이동도 정상 작동 확인.
> 💡 새로 바꾼 것만 보면 안 돼요 — 옆에서 조용히 망가진 게 없는지가 진짜 확인 포인트예요.

**④ 성공했으니 새 체크포인트로 저장** — "v2 - 버튼 파랑" 저장, 다음 변경(예: 폰트 크기)으로 넘어갈 준비.
> 💡 성공할 때마다 저장해야 다음 실험이 실패해도 잃는 게 "이번 것 하나"뿐이에요.

좋은 결과의 기준: (1) 요청한 것 딱 하나만 바뀌었다 (2) 원래 되던 기능이 다 그대로 된다 (3) 언제든 5초 만에 v1으로 되돌릴 수 있다.

## 단계별 따라하기

1. **지금 잘 되는 상태를 저장하기** — AI 코딩 도구(Bolt, Lovable, Cursor 등)에서 앱이 지금 정상 작동하는지 먼저 확인한 뒤 '이 상태를 저장'. Git 기반 도구면 'Commit(커밋)' 버튼을, 아니면 파일 전체를 복사해 별도 폴더에 백업. (Lovable 우측 상단 → History → 'v1 - 로그인까지 정상')
2. **변경을 딱 하나로 쪼개기** — 고치고 싶은 것을 종이에 다 적은 뒤, 그중 '가장 작고 독립적인 것 하나'만 골라 동그라미. 색 바꾸기, 글자 바꾸기 같은 단순한 것부터.
3. **AI에게 그 하나만 콕 집어 요청하기** — '무엇을 / 어디서 / 다른 건 건드리지 말고'를 명확히 적어 AI에게. 여러 개를 한 문장에 몰아넣지 않기. ('메인 화면의 로그인 버튼 배경색만 파란색(#2563EB)으로. 다른 코드나 레이아웃은 절대 건드리지 마.')
4. **바뀐 것만 눈으로 확인하기** — 미리보기를 새로고침하고, 방금 요청한 부분이 바뀌었는지 + 원래 되던 기능(다른 버튼, 페이지 이동)이 여전히 되는지 클릭.
5. **성공이면 저장, 실패면 되돌리기** — 잘 됐으면 1단계처럼 새 체크포인트로 저장하고 다음 변경으로. 망가졌으면 History/Undo로 직전 저장 지점으로 즉시 복원. 절대 망가진 위에 또 고쳐달라고 쌓지 말 것.
6. **문제가 생기면 AI에게 '되돌려줘'라고 정확히 말하기** — 도구에 Undo가 없다면 롤백 템플릿으로 '방금 변경을 취소하고 이전 상태로 돌려달라'고. 새 기능을 덧붙이는 게 아니라 '취소'라는 걸 분명히.

## 흔한 실수 → 교정

- ✗ '로그인, 결제, 디자인 다 바꿔줘'처럼 한 번에 여러 개를 몰아서 요청 → **한 번에 변경 하나만.** 목록으로 적어두고 위에서부터 하나씩 처리. 하나 끝날 때마다 저장.
- ✗ 망가진 상태에서 '아까 그거 다시 고쳐줘'라고 그 위에 계속 덧칠 → **먼저 직전 정상 저장 지점으로 되돌린 뒤(깨끗한 상태에서) 다시 시작.** 망가진 코드 위에 쌓으면 원인이 늘어남.
- ✗ 저장(커밋/체크포인트) 없이 계속 고치다가 되돌릴 지점이 아예 없어짐 → **잘 되는 상태가 나올 때마다 이름표를 붙여 저장하는 습관.** 되돌아갈 안전지대를 항상.

## 도구

- 🛠 **Lovable** (lovable.dev) — 화면별 History로 저장/되돌리기가 쉬운 AI 앱빌더.
- 🛠 **Bolt** (bolt.new) — 브라우저에서 바로 만들고 버전 되돌리기 지원.
- 🛠 **Cursor** (cursor.com) — Git 커밋으로 변경을 단계별로 저장·복원.
- 🛠 **ChatGPT** (chatgpt.com) — 요청을 작은 단계로 쪼개달라고 물어보는 코치.

## 실전 프롬프트

### 하나만 콕 집어 요청(가장 많이 씀)

```text
[앱의 어느 화면/부분]의 [바꿀 것 하나]만 [원하는 값]으로 바꿔줘. 다른 코드, 레이아웃, 기능은 절대 건드리지 마. 바꾼 부분만 알려줘.
```

`점진적 편집` `범위 제한`

### 망가졌을 때 되돌리기

```text
방금 한 변경([무엇을 바꿨는지]) 때문에 [어떤 문제]가 생겼어. 그 변경을 완전히 취소하고 직전의 정상 상태로 되돌려줘. 새 기능이나 코드는 추가하지 말고 원상복구만.
```

`되돌리기` `롤백`

### 큰 요청을 작은 단계로 쪼개달라기

```text
나는 [최종 목표]를 만들고 싶어. 한 번에 다 하지 말고, 한 번에 하나씩 안전하게 진행할 수 있게 가장 작은 단계 순서로 목록만 만들어줘. 각 단계는 실패해도 되돌리기 쉬운 크기여야 해. 아직 코드는 짜지 마.
```

`단계 쪼개기` `계획`

### 변경 전후 무엇이 바뀌는지 미리 확인

```text
[바꾸려는 요청 내용]. 실제로 코드를 바꾸기 전에, 어떤 파일의 어떤 부분이 바뀌고 그로 인해 다른 기능이 깨질 위험이 있는지 먼저 설명해줘. 내가 확인하면 그때 진행.
```

`사전 확인` `범위 제한`

## 직접 만들기 (미션)

:::tip
이제 당신 차례! 색이 아니라 '메인 화면 제목 글자 크기를 조금 더 크게' 바꿔보세요. (1) 지금 상태를 체크포인트로 저장 (2) 딱 이 변경 하나만 담은 요청 문장을 직접 써서 AI에게 (3) 미리보기에서 확인 (4) 성공이면 새 체크포인트 저장, 실패면 되돌리기.
:::

## 채점 기준

| 기준 | 배점 |
| --- | --- |
| 요청 문장에 '바꿀 것'과 '건드리지 말 것'이 둘 다 명확히 들어갔나 | 5 |
| 바뀐 부분만이 아니라 원래 되던 다른 기능도 클릭해서 확인했나 | 5 |
| 결과가 좋든 나쁘든 체크포인트를 남기거나 되돌렸나 | 5 |
