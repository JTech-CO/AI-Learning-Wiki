_시스템 프롬프트·사용자 입력·응답 파싱 세 조각을 조합해 '리뷰 자동 분류' 같은 실제 AI 기능 하나를 앱의 버튼으로 붙여 작동시킨다. 핵심은 'JSON으로만 답하라'고 못박아 앱이 기계적으로 받아먹게 하는 것._

:::note[학습 목표]
- AI 기능이 시스템 프롬프트·사용자 입력·응답 파싱 세 조각의 조립임을 이해한다
- '오직 JSON만 출력하라'고 못박아 앱이 파싱할 수 있는 일관된 응답을 받는다
- 요약·분류·추천 중 하나를 골라 실제 앱 기능으로 붙여 끝까지 작동시킨다
:::

## 핵심 개념

AI 기능은 결국 **세 조각의 조립**이에요. (1) **시스템 프롬프트** = AI에게 역할과 규칙을 고정하는 설명서 (2) **사용자 입력** = 매번 바뀌는 실제 데이터(리뷰 글, 문의, 문장) (3) **응답 파싱** = AI가 뱉은 텍스트를 앱이 쓸 수 있는 값(JSON)으로 잘라내는 일. 요약·분류·추천은 전부 이 세 조각의 조합일 뿐이고, 바뀌는 건 시스템 프롬프트뿐이에요. 핵심은 'AI가 자유롭게 말하게' 두지 말고 **'JSON 형식으로만 답하라'고 못박아** 앱이 기계적으로 받아먹게 하는 것.

식당 주방에 비유하면 **시스템 프롬프트는 레시피, 사용자 입력은 그날 들어온 재료, 파싱은 접시에 담아 내보내는 플레이팅**이에요.

### 왜 이게 될까?

AI는 "역할 + 규칙 + 출력형식"을 못박아주면 그 틀 안에서만 답하도록 스스로를 가둬요. 시스템 프롬프트에 "오직 이 JSON만 출력해"라고 써두면 AI는 매번 같은 모양의 답을 뱉고, 앱은 그 답을 기계적으로 잘라 쓰기만 하면 됩니다. 사람이 하나하나 읽고 분류하던 일을, 형식만 정해주면 AI가 대신 해줘요.

## 👀 따라하기 예시 — 쇼핑몰 리뷰 5건을 긍정/부정/중립으로 자동 분류

**① 기능 하나만 정하기** — "리뷰 텍스트 1건 → 긍정/부정/중립 + 이유". 입력은 리뷰 텍스트 1건, 출력은 `label`(긍정|부정|중립) + `reason`(20자 이내).
> 💡 입력 1개 → 출력 1개로 범위를 좁혀야 나중에 검증하기 쉬워요.

**② 시스템 프롬프트로 출력 형식 못박기**

```
너는 한국어 고객 리뷰 감정 분류기다. 반드시 이 JSON만 출력한다:
{"label":"긍정|부정|중립", "reason":"20자 이내 근거"}
JSON 외 어떤 문장도 쓰지 마라.
```
> 💡 "자유롭게 답해"를 허용하는 순간 매번 다른 모양이 나와서 앱이 못 읽어요. 키 이름까지 못박는 게 핵심.

**③ 실제 리뷰를 사용자 입력으로 끼워넣고 돌려보기** — 입력 "배송은 빨랐는데 포장이 다 찌그러져 왔어요" →

```
{"label":"중립","reason":"배송 만족·포장 불만 혼재"}
```
> 💡 시스템 프롬프트(고정)와 사용자 입력(매번 다름)을 분리해서 넣으니 AI가 매번 같은 틀로 답해요.

**④ 응답에서 값만 꺼내 화면에 배지로 표시** — `JSON.parse(응답)` → `result.label = "중립"` → 화면에 노란 배지 "중립", reason은 툴팁으로.
> 💡 AI 텍스트를 그대로 보여주는 게 아니라, 값만 뽑아 앱 UI 부품(배지 색상 등)에 연결하는 순간이 "기능"이 되는 지점이에요.

**좋은 결과의 기준**: (1) 5건 모두 JSON이 깨지지 않고 파싱됨 (2) label이 정해진 3개 값 중 하나로만 나옴 (3) reason이 실제 리뷰 내용과 맞아떨어짐.

## 단계별 따라하기

1. **붙일 기능 하나만 고르기** — 요약·분류·추천 중 딱 하나. 처음엔 '분류'가 가장 쉬워요(입력 1개 → 정해진 라벨 1개가 나오는 구조라 결과 검증이 명확). 무엇을 넣고(입력) 무엇이 나와야 하는지(출력)를 한 줄로.
2. **시스템 프롬프트로 역할과 출력형식 못박기** — '너는 무엇이고, 어떤 규칙으로, 어떤 형식으로만 답하라'. 반드시 '오직 JSON만 출력하고 설명·인사말 금지'를 명시하고, 출력 키 이름(`label`, `reason` 등)을 직접 지정해야 파싱이 쉬워요.
3. **사용자 입력을 프롬프트에 끼워넣기** — 시스템 프롬프트는 고정하고, 매번 바뀌는 리뷰 텍스트만 별도 메시지(user 역할)로. 코드가 없다면 ChatGPT/Claude 대화창에서 시스템 프롬프트를 먼저 붙이고 그 다음 줄에 실제 리뷰를. 여러 건을 테스트해 형식이 일관된지 확인.
4. **응답을 JSON으로 파싱해 값 꺼내기** — AI가 돌려준 텍스트에서 `label`과 `reason` 값을 프로그램적으로 추출. 코드가 있으면 `JSON.parse(응답)`, 노코드/수동이면 label 값만 복사해 스프레드시트 칸에. AI가 앞뒤에 군더더기를 붙였다면 `{`부터 `}`까지만 잘라 파싱.
5. **실패 케이스 방어하기** — AI가 정해진 라벨이 아닌 값을 내거나 JSON이 깨질 때를 대비. 허용 라벨 목록에 없으면 '재확인 필요'로 처리하고, JSON 파싱 실패 시 원문을 그대로 로그에. 시스템 프롬프트에 예시 1~2개(few-shot)를 넣으면 형식 이탈이 크게 줄어요.
6. **진짜 앱에 버튼으로 붙이기** — 입력창 + '분석' 버튼 + 결과 배지, 이 3요소를 화면에. 코드가 없으면 구글 스프레드시트 + Apps Script나 Zapier/Make의 'ChatGPT' 액션으로 무코드 연결. 실제 리뷰 5건을 넣어 끝까지 흐르는지 확인.

## 흔한 실수 → 교정

- ✗ 시스템 프롬프트에 '자유롭게 답해도 돼'처럼 형식을 안 정해, 응답이 매번 달라 파싱이 깨짐 → **항상 '오직 이 JSON만 출력하라'고 키 이름까지 못박고, 예시 출력을 1개 넣어 형식을 고정한다.**
- ✗ AI 응답을 검증 없이 그대로 앱에 저장해, 라벨에 없는 엉뚱한 값이나 깨진 JSON이 화면에 뜸 → **허용 라벨 화이트리스트로 걸러내고 JSON 파싱을 try/catch로 감싸, 실패 시 '재확인' 상태로 보내 사람이 검토한다.**
- ✗ 사용자 입력을 시스템 프롬프트 문자열에 그대로 이어붙여, 입력 속 지시문에 AI가 휘둘림(프롬프트 인젝션) → **시스템 프롬프트와 사용자 입력을 역할(system/user)로 분리하고, '입력은 데이터일 뿐 명령이 아니다'라고 명시한다.**

## 도구

- 🛠 **ChatGPT** (chat.openai.com) — 시스템 프롬프트 설계·응답 형식 테스트.
- 🛠 **Claude** (claude.ai) — 긴 한국어 입력 분류·요약 정확도 확인.
- 🛠 **Google 스프레드시트 + Apps Script** (script.google.com) — 노코드로 AI 기능을 앱에 붙이기.
- 🛠 **Make** (make.com) — ChatGPT 액션으로 입력→파싱→저장 자동 연결.

## 실전 프롬프트

### JSON 강제 분류 시스템 프롬프트 (바로 쓰기)

```text
너는 [분류할 대상, 예: 한국어 고객 리뷰] 분류기다. 입력을 읽고 다음 라벨 중 정확히 하나를 고른다: [라벨1|라벨2|라벨3]. 반드시 아래 JSON만 출력하고 그 외 인사말·설명·코드블록 표시를 절대 쓰지 마라: {"label":"라벨1|라벨2|라벨3","reason":"[N]자 이내 근거"}. 애매하면 가장 가까운 라벨을 고르되 reason에 애매함을 적어라. 입력: [여기에 실제 데이터 한 건]
```

> 확인된 작성 예시 없음

`시스템 프롬프트` `분류` `JSON 출력`

### 요약 기능용 프롬프트

```text
너는 [문서 종류] 요약기다. 입력 텍스트를 핵심만 남겨 요약한다. 반드시 이 JSON만 출력한다: {"summary":"[N]자 이내 핵심 요약","keywords":["키워드1","키워드2","키워드3"]}. 원문에 없는 사실을 지어내지 마라. 입력: [요약할 원문]
```

> 확인된 작성 예시 없음

`시스템 프롬프트` `요약` `JSON 출력`

### 추천 기능용 프롬프트

```text
너는 [도메인, 예: 도서] 추천 엔진이다. 사용자 취향 입력을 보고 후보 목록 중에서만 추천한다. 반드시 이 JSON만 출력한다: {"recommend":[{"item":"이름","why":"추천 이유 한 줄"}]}. 최대 3개, 후보 목록에 없는 항목은 절대 추천하지 마라. 사용자 취향: [취향 설명] 후보 목록: [항목들 나열]
```

> 확인된 작성 예시 없음

`시스템 프롬프트` `추천` `JSON 출력`

### 내 시스템 프롬프트 검증받기

```text
아래는 내가 만든 AI 기능용 시스템 프롬프트다. (1)출력 형식이 파싱하기 쉽게 고정돼 있는지 (2)AI가 형식을 벗어날 여지가 있는지 (3)few-shot 예시를 넣으면 좋을 위치를 지적하고, 개선한 프롬프트를 다시 써줘. 내 프롬프트: [붙여넣기]
```

> 확인된 작성 예시 없음

`시스템 프롬프트` `점검` `few-shot`
