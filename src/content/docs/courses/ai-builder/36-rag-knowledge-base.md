_수십~수백 개 문서를 청크·임베딩해 벡터 검색 위에 AI 답변을 얹어, 출처를 인용하며 환각을 줄인 사내 Q&A를 코딩 없이 구축한다. ChatGPT에 '우리 회사 환불 규정'을 물으면 지어내던 답을, '3페이지에 이렇게 적혀 있어요'라고 출처까지 찍어 답하게 만든다._

:::note[학습 목표]
- 내 문서(매뉴얼·정책·계약서 등) 여러 개를 올려, 질문하면 '어느 문서 몇 페이지에 이렇게 쓰여 있다'고 출처를 인용하며 답하는 나만의 RAG Q&A 시스템을 만들어 동작시킨다
- RAG(검색+보강+생성)가 왜 환각을 줄이는지 'AI에게 오픈북 시험을 보게 하는 것'이라는 비유로 이해한다
- 새 문서가 생기면 다시 가르칠 필요 없이 파일만 추가·삭제해 지식베이스의 최신성을 유지한다
:::

## 핵심 개념

RAG는 **'Retrieval(검색)+Augmented(보강)+Generation(생성)'**의 줄임말이에요. 쉽게 말하면 **'AI에게 오픈북 시험을 보게 하는 것'**. 보통 AI는 머릿속 기억만으로 답해서 모르는 건 지어냅니다(환각). RAG는 답하기 전에 먼저 내 문서 더미에서 관련된 페이지를 찾아오게(검색) 하고, 그 페이지를 AI에게 보여준 뒤(보강) 그걸 근거로 답을 쓰게(생성) 해요. 시험 때 책을 펴놓고 "이 페이지 보고 답해"라고 하는 것과 똑같죠. 그래서 출처를 콕 집어주고, 책에 없는 건 지어내지 않아요. 컴퓨터는 글을 **'숫자 좌표(임베딩)'**로 바꿔 비슷한 뜻끼리 가깝게 모아두기 때문에, 단어가 달라도 의미가 비슷한 페이지를 척척 찾아냅니다.

### 흐름

```
📄 내 문서 업로드(매뉴얼·정책 PDF)
  → 💬 질문 입력("환불 며칠?")
  → 🔍 관련 페이지 검색(의미로 찾기)
  → 📑 근거 보여주기(찾은 문장 전달)
  → ✅ 출처 인용 답변("3p 참고")
```

### 왜 이게 될까?

보통 AI는 머릿속 기억만으로 답해서 모르는 건 지어냅니다(환각). RAG는 답하기 전에 먼저 내 문서 더미에서 관련 페이지를 검색해와서 그걸 근거로 답을 쓰게 만들어요. 시험 볼 때 책을 펴놓고 '이 페이지 보고 답해'라고 하는 것과 똑같습니다. 당신은 문서만 올리면 출처 인용까지 AI가 대신 해줘요.

## 👀 따라하기 예시 — NotebookLM으로 '환불정책.pdf'·'배송안내.pdf'

**① 노트북 만들기** notebooklm.google.com 접속 → Gmail 로그인 → '+ 새로 만들기' 클릭 → 'Add sources' 창에 PDF/Google 문서/텍스트 붙여넣기/웹사이트 선택지가 뜬다.
> 💡 노트북 하나 = 지식베이스 하나. 먼저 '어떤 책을 펴놓을지'부터 정하는 것.

**② 문서 올리기(임베딩)** 두 파일을 점선 박스에 드래그 → 각 문서 옆 회색 점이 30초~1분 돌다 멈추고, 왼쪽 Sources 목록에 2개가 체크된 채로 뜬다.
> 💡 이 로딩이 '임베딩' — 컴퓨터가 문장을 숫자 좌표로 바꿔 의미가 비슷한 부분을 미리 정리하는 중.

**③ 질문하기** 채팅창에 '고객이 환불하려면 며칠 안에 신청해야 해?' 입력 → "구매 후 7일 이내에 신청해야 합니다 ①." 답과 함께 문장 끝에 인용 칩 ①이 붙는다.
> 💡 답만 던지는 게 아니라 '이 문장은 어디서 가져왔다'는 꼬리표를 다는 것. 일반 챗봇과 RAG의 결정적 차이.

**④ 근거 대조** 인용 칩 ① 클릭 → 오른쪽 패널에 환불정책.pdf 3페이지 원문이 노란색 하이라이트로 펼쳐진다 — '환불은 수령일로부터 7일 이내 신청 가능'.
> 💡 아하 포인트: AI 답을 그냥 믿는 게 아니라 원문을 1초 만에 대조 가능. 특히 숫자·금액은 꼭 이렇게 확인.

**좋은 결과의 기준:** (1) 답변마다 인용 칩이 붙어있다 (2) 칩을 클릭하면 실제 올린 문서의 해당 문장이 뜬다 (3) 문서에 없는 질문에는 '문서에 없음'이라고 솔직히 답한다.

## 단계별 따라하기

1. **도구 정하기 — 가장 쉬운 NotebookLM으로 시작** RAG를 코딩 없이 만드는 가장 쉬운 무료 도구는 구글 'NotebookLM'. 준비물은 Gmail 계정 하나. notebooklm.google.com 접속. "이 서비스를 사용할 수 없습니다"가 뜨면 회사 계정 대신 개인 Gmail로(회사 계정은 관리자가 막아둔 경우).
2. **새 노트북 만들고 내 문서 올리기** '+ 새로 만들기' → 'Add sources' 창에서 PDF/Google 문서/텍스트/웹사이트 중 선택. 점선 박스에 파일 드래그(여러 개 동시 OK). 소스 한도는 플랜별 — Free 50 / Plus 100 / Pro 300 / Ultra 최대 600. 업로드 후 회색 점이 돌다 멈추면 분석 완료.
3. **잘 들어갔는지 요약으로 확인** 문서를 다 올리면 NotebookLM이 자동으로 '노트북 가이드'와 요약을 생성. 요약을 읽어 내가 올린 내용이 맞게 들어갔는지 1차 확인. 엉뚱하면 소스 목록에서 ⋮ → '삭제' 후 다시 올림.
4. **질문하고 '출처 인용' 답변 받기** 아래 채팅 입력창에 평소 말하듯 질문 → 엔터. 답변 곳곳에 동그란 번호(①②③ 인용 칩). 클릭하면 '몇 번 문서 어느 문장에서 가져왔는지' 원문이 오른쪽에 펼쳐짐. 이게 RAG의 핵심 — 답의 근거를 눈으로 확인.
5. **환각 막는 안전장치 — '문서에 없으면 모른다고 답하라' 지시** 질문 앞에 '규칙'을 한 줄 붙임(근거-only 규칙). 문서에 없는 건 "제공된 문서에는 해당 내용이 없습니다"라고 솔직하게 답함. NotebookLM은 기본적으로 올린 문서 안에서만 답하도록 설계됐지만 이 한 줄로 더 확실.
6. **새 문서가 생기면 '추가만' 하면 끝(최신성 유지)** 정책이 바뀌거나 새 매뉴얼이 나오면 다시 처음부터 가르칠 필요 없음. 'Sources' 패널의 '+ 추가(Add)'로 새 파일만 올리고, 옛 문서는 ⋮ → '삭제'. 지식베이스만 갱신하면 다음 질문부터 최신 내용으로 답. 'AI를 재학습'시키는 게 아니라 '책장에 책만 갈아 끼우는' 방식.
7. **(선택) 더 큰 시스템으로 — Dify로 챗봇 공개** 직원 여러 명이 쓸 사내 챗봇은 'Dify'(dify.ai). 가입 후 'Create from Blank' → 'Chatbot' → 'Knowledge' 메뉴에서 문서 업로드(임베딩 자동) → 챗봇에 연결 → 'Publish'로 링크 생성해 동료에게 공유. NotebookLM보다 설정은 많지만 공유·웹삽입 가능. 처음이면 건너뛰고 NotebookLM으로 익힌 뒤 도전.

## 흔한 실수 → 교정

- ✗ 스캔한 사진 PDF(글자가 이미지로 된 문서)를 올리고 답이 안 나온다고 함 → **스캔된 PDF는 글자를 못 읽는다. '복사-붙여넣기'가 되는 진짜 텍스트 PDF인지 확인. 안 되면 구글 드라이브에 올려 '구글 문서로 열기'로 OCR 후 그 문서를 올린다.**
- ✗ 출처 번호를 확인 안 하고 AI 답을 그대로 믿음 → **RAG의 핵심은 '검증'. 인용 번호(①②)를 꼭 클릭해 원문이 정말 그 말인지 1초만 확인. 특히 숫자(기간·금액·비율)는 반드시 원문 대조.**
- ✗ 문서를 너무 많이/뒤죽박죽 올려 엉뚱한 페이지를 찾음 → **주제별로 노트북(지식베이스)을 나눈다. '환불·배송' 노트북, '제품매뉴얼' 노트북처럼 분리하면 검색 정확도가 확 올라간다.**
- ✗ 정책이 바뀌었는데 옛 문서를 안 지워서 옛 답이 계속 나옴 → **새 문서를 추가했으면 폐기된 옛 문서는 ⋮ → '삭제'. RAG는 올라온 문서 전부를 근거로 쓰기 때문에 옛 문서가 남아 있으면 충돌한 답이 나올 수 있다.**

## 완료 체크리스트

- ☐ NotebookLM(또는 Dify)에 로그인해 새 노트북/앱을 만들었다
- ☐ 내 문서를 2개 이상 올렸고 소스 목록에 정상 표시된다
- ☐ 질문을 했고 답변에 출처 인용 번호가 붙어 나온다
- ☐ 인용 번호를 클릭해 원문 문장이 맞는지 직접 확인했다
- ☐ '근거-only 규칙'을 붙여 문서에 없는 질문엔 '없음'으로 답하는 걸 확인했다
- ☐ 새 문서를 추가/삭제하는 방법(+추가, ⋮삭제)을 익혔다

## 도구

- 🛠 **NotebookLM** (notebooklm.google.com) — 구글 무료·코딩 0, 가장 쉬운 출처 인용 RAG. 입문 최고. 소스 한도 Free 50 / Plus 100 / Pro 300 / Ultra 최대 600.
- 🛠 **Dify** (dify.ai) — 동료와 공유·웹삽입 가능한 사내 챗봇을 노코드로 구축.
- 🛠 **ChatGPT** (chatgpt.com) — Projects 기능으로 파일·지시사항·대화 기록을 영구 워크스페이스에 보관, Google Drive·Notion·Slack 등 커넥터 지원.
- 🛠 **LlamaIndex** — 개발자용, 코드로 대규모 문서 RAG를 직접 설계.

## 실전 프롬프트

### 근거-only 규칙 (환각 차단, 모든 질문 앞에)

```text
아래 규칙을 반드시 지켜 답해라. 1) 업로드된 문서에 근거가 있는 내용만 답한다. 2) 근거가 없으면 추측하지 말고 '제공된 문서에는 해당 내용이 없습니다'라고만 답한다. 3) 답의 각 핵심 문장 끝에 출처(문서명·페이지 또는 인용 번호)를 표시한다. 질문: [질문]
```

> 확인된 작성 예시 없음

`환각 방지` `근거` `출처`

### 정책/규정 빠른 조회

```text
[제품명 또는 상황]에 대한 [환불/교환/배송/A/S] 규정을 알려줘. 조건·기간·예외사항을 항목별로 정리하고 각 항목마다 어느 문서 몇 페이지에서 나왔는지 출처를 함께. 문서에 없는 건 '없음'이라고.
```

> 확인된 작성 예시 없음

`정책 조회` `출처`

### 여러 문서 비교/충돌 찾기

```text
업로드한 문서들 중 [환불 기간]에 대해 서로 다르게 적힌 부분이 있는지 비교해줘. 어느 문서에서 며칠이라고 했는지 각각 출처와 함께 표로 정리하고, 충돌하면 어떤 게 최신인지 추정해줘.
```

> 확인된 작성 예시 없음

`문서 비교` `충돌 탐지` `출처`

### 신입 교육용 FAQ 자동 생성

```text
이 문서들을 바탕으로 신입 직원이 자주 물어볼 질문 10개와 답을 FAQ 형식으로. 각 답변마다 근거가 된 문서명·페이지를 반드시 표시하고, 문서에 답이 없는 질문은 만들지 마.
```

> 확인된 작성 예시 없음

`FAQ 생성` `신입 교육` `출처`
