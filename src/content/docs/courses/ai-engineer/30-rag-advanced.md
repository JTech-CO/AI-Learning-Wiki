_RAG가 엉뚱한 답을 줄 때: 문서 분할(chunking) 전략·재순위(reranking)·키워드+의미 하이브리드 검색으로 정확도를 끌어올린다._

:::note[학습 목표]
- 내 PDF·문서 묶음을 업로드하면 AI가 그 문서에서 "근거 문장까지 콕 집어" 답하는 나만의 Q&A 봇을 만들 수 있습니다. 또한 AI가 헛소리할 때 chunking·하이브리드 검색·reranking 3가지로 정확도를 직접 끌어올리고, 노코드 프롬프트 방식과 진짜 reranker(Cohere Rerank·Jina·BGE) 방식의 차이까지 구분할 수 있게 됩니다.
:::

> 내 PDF 100장을 ChatGPT에 붙여 물었더니 엉뚱한 답이 나온 적 있나요? 문서를 "제대로 잘라서·골라서·재정렬해서" 넣는 법만 알면 같은 AI가 정답을 줍니다. 30분이면 내 자료 전용 챗봇이 거짓말을 멈추고, 마지막엔 진짜 reranker로 정확도를 한 단계 더 올립니다.

## 이 레슨에서 만드는 것

내 PDF·문서 묶음을 업로드하면 AI가 그 문서에서 "근거 문장까지 콕 집어" 답하는 나만의 Q&A 봇을 만들 수 있습니다. 또한 AI가 헛소리할 때 chunking·하이브리드 검색·reranking 3가지로 정확도를 직접 끌어올리고, 노코드 프롬프트 방식과 진짜 reranker(Cohere Rerank·Jina·BGE) 방식의 차이까지 구분할 수 있게 됩니다.

## 핵심 개념

RAG(검색증강생성)는 "AI가 답하기 전에 내 문서를 먼저 찾아보게 하는 것"입니다. 시험을 머릿속 기억으로만 푸는 게 아니라, 교과서를 펴서 해당 페이지를 보고 답하는 것과 같아요. 단, 교과서를 통째로 한 페이지에 욱여넣으면 못 찾습니다. 그래서 세 가지 기술이 필요합니다.

(1) chunking = 문서를 적당한 크기로 "쪽쪽 자르기".
(2) 검색 = 질문과 관련된 조각만 골라오기. 여기서 "의미로 찾기(임베딩/벡터 검색)"와 "단어로 찾기(키워드/BM25)"를 같이 쓰는 게 하이브리드 검색입니다. 제품코드·이름 같은 정확한 단어도 놓치지 않게 해줍니다.
(3) reranking = 골라온 조각들을 "진짜 정답에 가까운 순서"로 한 번 더 줄세우기.

여기서 핵심 구분이 있습니다. 벡터 검색은 질문과 문서를 "각각 따로" 숫자로 바꿔 비교하는 bi-encoder라 빠르지만 거칠어요. 진짜 reranker는 질문과 문서를 "함께 한 번에" 읽고 점수를 매기는 cross-encoder라 훨씬 정확합니다. 그래서 실무 표준 파이프라인은 "벡터로 후보 50~100개를 빠르게 뽑고 → cross-encoder reranker로 상위 5~10개만 정밀하게 다시 줄세워 → LLM에 넣기"입니다. 대표 reranker로는 Cohere Rerank 4.0(2025년 12월 출시 최신 플래그십, rerank-v4.0-pro / rerank-v4.0-fast, 100여 개 언어·32K 컨텍스트·JSON 반정형 데이터 지원; rerank-v3.5도 여전히 사용 가능), Jina Reranker v3(jina-reranker-v3, 2026년 Jina AI 플래그십, listwise, 131K 컨텍스트, SOTA), 오픈소스 BGE-reranker-v2-m3(약 5.7억 파라미터, 한국어 강함, 자체 서버 가능), 가벼운 FlashRank가 있습니다.

코드 없이 쓰는 사람은 이 cross-encoder를 "프롬프트로 흉내"낼 수 있습니다(후보를 여러 개 뽑게 한 뒤 점수 매겨 1등만 답하게 시키기). 이건 진짜 reranker만큼 정밀하진 않지만, NotebookLM·ChatGPT·Claude 같은 도구 안에서 즉시 효과를 냅니다.

### 왜 작동하는가

AI는 질문과 문서를 통째로 비교하지 않고, 문서를 잘게 쪼갠 뒤 '의미가 비슷한 조각'을 먼저 찾아와서 그 조각만 보고 답합니다. 그런데 조각이 너무 크거나 뒤섞여 있으면 엉뚱한 걸 찾아오죠. 그래서 ①깔끔하게 자르고(chunking) ②단어와 의미를 같이 써서 찾고(하이브리드) ③후보들을 다시 한번 정밀하게 줄세우면(reranking), 같은 AI가 갑자기 정답만 콕 집어옵니다.

## 👀 따라하기 예시

회사 휴가규정.pdf, 연봉테이블.pdf, 복지제도.docx 3개를 NotebookLM에 올려서 'AX-7200 모델 보증기간이 며칠이야?'를 물어보는 상황이에요. 제가 먼저 처음부터 끝까지 해볼게요, 눈으로 따라오세요.

### 1. ① 문서 3개를 NotebookLM Sources에 업로드

**실제 결과**

```text
Processing... → 완료 후 왼쪽 Sources 패널에 사내_휴가규정, 2026_연봉테이블, 복지제도_안내 3개가 체크된 채로 등장
```

> 업로드 즉시 AI가 자동으로 문서를 잘게 쪼개(chunking) 색인합니다 — 우리가 손 안 대도 1단계가 뒤에서 돌아가요

### 2. ② 첫 질문은 가볍게: '이 문서들에 어떤 항목이 있어?'

**실제 결과**

```text
AI: '휴가 규정(연차·병가), 2026년 직급별 연봉 테이블, 복지제도(건강검진·경조사비) 3개 문서가 있습니다.'
```

> 바로 어려운 질문 던지지 않고 색인이 제대로 됐는지 먼저 확인하는 거예요 — 아하 포인트: 밑작업 확인이 실패를 반으로 줄입니다

### 3. ③ 정확한 모델명을 따옴표로 콕 집어 질문: 모델명 'AX-7200'의 보증기간을 규정 문서에서 정확히 찾아줘

**실제 결과**

```text
AI: 'AX-7200 모델의 보증기간은 구매일로부터 24개월입니다 ①' (①을 클릭하면 오른쪽에 원문 문장 'AX-7200: 보증 24개월(소모품 제외)'이 그대로 펼쳐짐)
```

> 따옴표로 정확 단어를 넣으면 의미검색이 놓칠 수 있는 걸 키워드 매칭이 강제로 끌어옵니다 — 이게 하이브리드 검색을 사용자가 직접 흉내내는 법

### 4. ④ 후보가 여러 개 헷갈릴 때 재순위 프롬프트 추가: 관련 문단을 3~5개 찾아 0~10점으로 신뢰도를 매기고, 가장 높은 문단만 근거로 답해줘

**실제 결과**

```text
AI: '문단A(9점, 보증기간 명시) / 문단B(3점, 다른 모델) / 문단C(2점, 무관) → 문단A 기준: 24개월입니다'
```

> 여러 후보를 AI가 스스로 채점하고 1등만 답하게 하면 cross-encoder reranker를 프롬프트로 흉내낸 효과가 납니다

### 완성 결과

완성물: 내 문서 전용 Q&A 봇 + 근거 인용 링크. 좋은 결과의 기준 — (1) 답 끝에 출처 번호가 붙어 원문을 바로 확인할 수 있다, (2) 정확한 이름·코드를 물었을 때 다른 문서와 헷갈리지 않는다, (3) 근거가 약하면 '문서에 명확한 근거가 없습니다'라고 솔직히 말한다.

## 단계별 따라하기

### 1. 준비물 챙기기 (계정·문서)

필요한 건 딱 둘입니다. (1) 도구 계정 — 입문은 NotebookLM 추천: notebooklm.google.com 에 들어가 평소 쓰는 구글 계정으로 로그인하면 끝(무료 플랜 기준 한 노트북당 출처 50개까지; Google AI Plus·Pro·Ultra 구독 시 100~600개로 확장). 문서가 많거나 Claude를 쓰고 싶으면 claude.ai로 로그인 → 왼쪽 메뉴 Projects를 씁니다. ※ Claude Projects는 무료 플랜에서도 사용 가능(Anthropic 공식 기준). RAG 모드(10x 자동 확장)는 무료·유료 플랜 모두 지원됩니다. 단, 무료는 프로젝트 5개·메시지·길이 한도가 작아 컨텍스트 한도에 빠르게 도달하는 것이 실질적 제약이므로, 대용량·여러 프로젝트를 자주 돌리면 Pro($20/월)·Team이 실용적입니다. (2) 테스트할 내 문서 — PDF·구글문서·복사 텍스트 2~5개. 회사 매뉴얼·강의 노트·계약서처럼 내가 자주 찾는 자료가 좋습니다. 화면에 왼쪽 Sources(출처) 패널과 가운데 채팅창이 보이면 준비 완료. 막히면: 회사 구글/Claude 계정이 관리자 차단이면 개인 계정으로 로그인하세요.

**복사·실행 예시**

```text
준비 문서 예시: 사내_휴가규정.pdf, 2026_연봉테이블.pdf, 복지제도_안내.docx 3개
```

### 2. 문서 올리기 = 자동 chunking 체험

NotebookLM 첫 화면에서 + 새 노트북(Create new)을 누르면 가운데에 출처 추가(Add sources) 박스가 뜹니다. PDF는 끌어다 놓거나 파일 선택, 구글문서는 Google Drive, 웹페이지는 Website, 복사 텍스트는 Copied text를 고릅니다. 올리면 도구가 자동으로 문서를 잘게 쪼개(chunking) 임베딩으로 색인합니다 — 1번 핵심 기술이 도구 안에서 자동으로 도는 것. 잠시 Processing 표시 후 왼쪽 Sources에 문서 제목들이 체크박스와 함께 나타납니다. (Claude Projects를 쓴다면: 프로젝트 생성 후 Project knowledge에 같은 파일을 올립니다.)

**복사·실행 예시**

```text
휴가규정.pdf를 끌어다 놓으면 → Processing... → 왼쪽에 사내_휴가규정 항목이 체크된 상태로 생김
```

### 3. 근거 답변 받아보기 (출처 클릭)

가운데 채팅창에 질문을 칩니다. NotebookLM은 답 문장 끝에 작은 숫자 동그라미(예: ①②)를 붙입니다 — 근거 표시. 그 숫자를 클릭하면 오른쪽에 원문 문서의 그 문장이 그대로 펼쳐집니다. 이게 RAG가 헛소리를 막는 핵심: 답이 어느 문장에서 나왔는지 눈으로 확인됩니다. 출처가 안 붙은 답은 추측일 수 있으니 의심하세요. (Claude Projects는 인용을 자동으로 안 붙일 때가 있으니 "근거 문장을 그대로 인용해줘"라고 덧붙이세요.)

**복사·실행 예시**

```text
질문: 신입사원 첫해 연차는 며칠인가요? → 답: 입사 1년 미만은 매월 개근 시 1일씩 최대 11일 ① → ①클릭하면 휴가규정 원문이 오른쪽에 뜸
```

### 4. 엉뚱한 답 고치기 ① — chunking(쪼개는 크기)

AI가 표·목록을 섞어 틀리게 답하면 보통 한 조각에 너무 많은 게 섞여서입니다. 해결: 올리기 전에 한 주제=한 문단이 되게 정리하세요. 표는 따로 떼어 항목: 값 형태(예: 연차 11일)로 풀어 쓰면 적중률이 확 올라갑니다. 자동 chunking도 입력이 깔끔하면 깔끔해집니다. 규칙: 한 문단 3~6문장, 소제목 붙이기. (실무 팁: 코드로 RAG를 만들 땐 청크 크기 300~800토큰, 겹침 10~15%가 무난한 출발점입니다.)

**복사·실행 예시**

```text
나쁜 입력: 표 한 덩어리 → 좋은 입력: ## 연차 규정 / - 1년 미만: 최대 11일 / - 1년 이상: 15일 / - 3년차부터: 2년마다 +1일
```

### 5. 엉뚱한 답 고치기 ② — 하이브리드(단어+의미)

제품코드·사람이름·법조항 번호처럼 정확한 단어를 물을 때 AI가 비슷한 다른 걸 가져오면, 질문에 그 단어를 따옴표로 콕 집어 넣으세요. 이게 사용자가 직접 하는 하이브리드 검색입니다 — 의미검색(벡터)이 놓친 정확 단어를 키워드 매칭으로 강제로 끌어옵니다. NotebookLM·ChatGPT·Claude 모두 질문에 정확 키워드가 들어가면 그 단어가 든 조각을 우선합니다. (코드로 만들 땐 BM25 같은 키워드 검색과 벡터 검색 점수를 합치는 하이브리드 retriever를 씁니다.)

**복사·실행 예시**

```text
나쁜 질문: 그 모델 보증기간 알려줘 → 좋은 질문: 모델명 "AX-7200"의 보증기간을 규정 문서에서 정확히 찾아줘
```

### 6. 엉뚱한 답 고치기 ③ — reranking(노코드: 재순위 프롬프트)

AI가 여러 후보 중 엉뚱한 걸 골랐다면 여러 개 뽑은 뒤 가장 근거가 강한 것만 고르라고 시키면 됩니다. 이게 cross-encoder reranking을 프롬프트로 흉내내는 법입니다. 아래 재순위 프롬프트 템플릿을 그대로 붙여 쓰면 AI가 후보에 점수를 매기고 1등만 답합니다. 코드 없이 즉시 효과를 보는 길입니다.

**복사·실행 예시**

```text
질문 끝에 추가: 관련 문단을 3~5개 찾아 각각 0~10점으로 신뢰도를 매기고, 가장 높은 점수의 문단만 근거로 답하세요. 점수가 모두 5점 미만이면 "문서에 명확한 근거가 없습니다"라고 답하세요.
```

### 7. 진짜 reranking — 실제 reranker(cross-encoder) 붙이기

프롬프트 흉내는 편하지만 후보가 많아지면 LLM이 다 못 읽어 한계가 옵니다. 정확도를 제대로 올리는 표준은 진짜 reranker(cross-encoder)를 파이프라인에 끼우는 것입니다. 흐름: 벡터 검색으로 후보 50~100개 → reranker가 질문+각 문서를 함께 읽어 정밀 점수 매김 → 상위 5~10개만 LLM에. 선택지: ① Cohere Rerank 4.0(rerank-v4.0-pro / rerank-v4.0-fast) — 2025년 12월 출시 현행 Cohere 플래그십. API 한 줄 호출, Amazon Bedrock 제공, 100여 개 언어·32K 컨텍스트·JSON 반정형 데이터 지원. 고정밀이 필요하면 v4.0-pro, 저지연·대량 처리가 필요하면 v4.0-fast를 선택. 구버전 rerank-v3.5도 여전히 호출 가능하나 신규 프로젝트엔 v4.0 권장. ② Jina Reranker v3(jina-reranker-v3) — 2026년 Jina AI 최신 플래그십. listwise 아키텍처로 최대 64개 문서를 동시 비교, 131K 컨텍스트, BEIR nDCG@10 61.94(SOTA), 18개 언어 지원. v2는 구버전. ③ 오픈소스 BGE-reranker-v2-m3 — 한국어 등 아시아어에 강하고 약 5.7억(568M) 파라미터라 일반 GPU·자체 서버로 돌릴 수 있어 데이터 보안·비용 통제에 유리. ④ FlashRank — 초경량, 노트북에서도 OK. 코드 없이 쓰는 분은 LangChain/LlamaIndex 같은 프레임워크의 "reranker" 설정에 위 모델 이름만 넣으면 됩니다. 핵심 판단: 후보 recall이 높을 때 reranking이 정밀도를 크게 올려주지만, 애초에 검색이 정답을 못 뽑아오면(recall 낮음) reranker로도 못 살리니 먼저 chunking·하이브리드를 점검하세요.

**복사·실행 예시**

```text
Cohere 예: POST /v2/rerank 에 model="rerank-v4.0-pro", query="AX-7200 보증기간", documents=[후보 50개] 보내면 점수순 정렬 반환 → 상위 5개만 LLM에. / 오픈소스 예: BGE-reranker-v2-m3를 LlamaIndex의 node postprocessor로 등록
```

## 흔한 실수와 교정
- **실수:** PDF 한 권을 통째로 올리고 바로 어려운 질문을 던진다
  - **교정:** 먼저 문서에 어떤 항목들이 있어?로 가볍게 물어 색인을 확인하고, 표·복잡한 부분은 4단계처럼 정리 후 올린다.
- **실수:** 출처(근거 인용)가 없는 답을 그대로 믿는다
  - **교정:** 답 끝의 출처 숫자(①)나 인용 문장을 꼭 클릭·확인한다. 없으면 근거 문장을 인용해줘로 다시 요청한다.
- **실수:** 제품코드·이름을 평범하게 물어 비슷한 다른 걸 받는다
  - **교정:** 정확한 단어를 따옴표로 감싸 질문한다(5단계 하이브리드). 예: "AX-7200".
- **실수:** reranking을 프롬프트 흉내만으로 끝내고 정밀도 한계에 부딪힌다
  - **교정:** 후보가 많거나 정확도가 중요하면 진짜 cross-encoder reranker를 파이프라인에 붙인다. 신규 프로젝트에는 Cohere Rerank 4.0(rerank-v4.0-pro / rerank-v4.0-fast)이 현행 권장 모델이며, Jina Reranker v3·BGE-reranker-v2-m3도 좋은 대안이다. 단, 검색이 정답을 아예 못 뽑으면(recall 낮음) reranker로도 못 살리니 먼저 chunking·하이브리드를 점검한다.
- **실수:** Claude Projects RAG 모드가 유료 전용인 줄 알고 무료 사용자가 포기한다
  - **교정:** Anthropic 공식 헬프센터 기준, RAG 모드(10x 자동 확장)는 무료 플랜을 포함한 모든 플랜(free·Pro·Max·Team·Enterprise)에서 지원된다. 단, 무료 플랜은 프로젝트 수·메시지·길이 한도가 작아 컨텍스트 한도에 빠르게 도달하는 것이 실질적 제약이므로, 대용량 작업이 잦으면 유료 플랜을 고려한다.
- **실수:** 답이 틀리면 도구 탓을 하며 포기한다
  - **교정:** 대부분 입력 문서가 지저분하거나 질문이 모호한 탓이다. 4(쪼개기)·5(단어)·6~7(재순위) 순서로 점검하면 같은 도구로 정확도가 올라간다.

## 완료 체크리스트

- NotebookLM 또는 Claude Projects(무료 가능)에 내 문서 2개 이상 올려 색인 완료를 확인했다
- 질문에 대한 답에서 출처 숫자/인용 문장을 클릭해 원문을 직접 확인했다
- 표나 복잡한 문단을 항목: 값 형태로 정리해 다시 올려봤다(chunking)
- 정확한 단어를 따옴표로 묶어 질문해봤다(하이브리드)
- reranking 프롬프트로 후보에 점수를 매겨 최종 1등만 답하게 시켜봤다(노코드)
- 진짜 reranker(Cohere Rerank 4.0·Jina Reranker v3·BGE-reranker-v2-m3)와 프롬프트 흉내의 차이를 설명할 수 있고, 어느 쪽을 쓸지 판단 기준을 안다

## 도구

- NotebookLM — 구글 무료(출처 50개, 무료 기준; Google AI Plus·Pro·Ultra 구독 시 100~600개로 확장), 내 문서로 근거 인용 Q&A봇 만들기에 최적(입문 추천)
- Claude Projects — 2026년 기준 무료 플랜에서도 Projects 사용 가능. RAG 모드(컨텍스트 한도 도달 시 자동 10x 확장)는 무료·유료 플랜 모두 지원(Anthropic 공식 헬프센터 기준). 단, 무료는 프로젝트 5개·메시지·길이 한도가 작아 컨텍스트 한도에 빠르게 도달하는 것이 실질적 제약. 대용량·여러 프로젝트를 자주 돌리면 Pro($20/월)·Team으로 올리면 한도가 커집니다.
- ChatGPT — 파일 업로드 후 위 프롬프트 템플릿으로 reranking·하이브리드 흉내내기
- Cohere Rerank 4.0 (rerank-v4.0-pro / rerank-v4.0-fast) — 2025년 12월 출시 현행 Cohere 플래그십 reranker. cross-encoder 방식, 100여 개 언어·32K 컨텍스트·JSON 반정형 데이터 지원. rerank-v4.0-pro(고정밀)와 rerank-v4.0-fast(저지연) 두 버전 제공. API 한 줄·Amazon Bedrock 제공. 구버전 rerank-v3.5도 여전히 호출 가능하나 신규 프로젝트엔 v4.0 권장
- Jina Reranker v3 (jina-reranker-v3) — 2026년 Jina AI 최신 플래그십. listwise 아키텍처(Qwen3-0.6B 기반)로 최대 64개 문서를 동시에 처리·비교, 131K 토큰 컨텍스트, BEIR nDCG@10 61.94(SOTA), 18개 언어 지원. v2는 구버전.
- BGE-reranker-v2-m3 — 오픈소스 cross-encoder, 약 5.7억(568M) 파라미터, 한국어 강함, 자체 서버·일반 GPU로 구동 가능(데이터 보안)
- FlashRank — 초경량 오픈소스 reranker, 로컬에서도 빠름
- LangChain · LlamaIndex — 위 reranker를 코드 몇 줄로 RAG 파이프라인에 붙이는 프레임워크

### 진짜 reranker — Cohere Rerank 4.0 API 호출(코드)

```text
# Cohere Rerank 4.0 (rerank-v4.0-pro) 예시 — 벡터 검색 후보를 정밀 재순위
# 현행 Cohere 플래그십 (2025년 12월 출시). 저지연이 필요하면 rerank-v4.0-fast 사용
import cohere
co = cohere.ClientV2("<COHERE_API_KEY>")
resp = co.rerank(
    model="rerank-v4.0-pro",
    query="AX-7200 보증기간",
    documents=[c1, c2, c3],  # 벡터 검색으로 뽑은 후보 50~100개 텍스트
    top_n=5,
)
for r in resp.results:
    print(r.index, r.relevance_score)  # 점수순 정렬된 상위 5개
# 오픈소스로 자체 서버에 두려면 model 자리에 BGE-reranker-v2-m3 / jina-reranker-v3를 LlamaIndex·LangChain reranker로 등록
```
