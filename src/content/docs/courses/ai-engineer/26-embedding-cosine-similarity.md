_임베딩으로 텍스트를 벡터(좌표)로 바꾸고 코사인 유사도로 의미적으로 가까운 문장을 직접 계산해 찾아본다. '강아지'와 'puppy'처럼 글자가 하나도 안 겹치는데 AI가 둘을 비슷한 뜻으로 아는 비밀, 바로 '숫자로 된 의미 지도'를 손으로 체득한다._

:::note[학습 목표]
- 문장 몇 개를 임베딩 벡터로 바꾸고 코사인 유사도를 손으로 계산해 '의미가 가장 가까운 문장'을 찾아낸다
- 코사인 유사도 공식(내적 ÷ 각 벡터 크기의 곱)에서 정규화의 역할을 이해하고 직접 적용한다
- 임베딩이 '글자'가 아니라 '의미'를 비교한다는 원리로 검색·추천·RAG가 돌아감을 확인한다
:::

## 핵심 개념

**임베딩(embedding)**은 단어나 문장을 수백 개의 숫자로 된 벡터, 즉 하나의 '좌표'로 바꾸는 기술이에요. 의미가 비슷한 문장은 이 좌표 공간에서 서로 **가까운 곳에 모입니다**. 두 벡터가 얼마나 같은 방향을 가리키는지를 재는 것이 **코사인 유사도**이고, 값은 **-1(정반대)에서 1(똑같은 방향)**까지예요. 검색·추천·챗봇의 "관련 문서 찾기(RAG)"가 모두 이 원리로 돌아갑니다. 즉 임베딩은 "글자 맞추기"가 아니라 **"뜻 맞추기"**를 컴퓨터가 하게 만드는 핵심 부품이에요.

### 왜 이게 될까?

AI는 수백만 개의 문장을 학습하면서 뜻이 비슷한 말들은 좌표 공간에서 가까운 곳에 모이도록 숫자(벡터)를 배웁니다. 그래서 "강아지"와 "puppy"처럼 글자가 하나도 안 겹쳐도 벡터의 방향이 비슷하면 "이 둘은 뜻이 비슷하구나"라고 알아요. 당신은 그저 두 벡터의 방향을 **코사인 유사도라는 공식 하나로 비교**하기만 하면, 검색·추천·RAG가 다 이 원리 위에서 돌아가는 걸 확인할 수 있어요.

## 👀 따라하기 예시 — 세 문장의 의미 거리 재기

> 문장 A "강아지가 공을 물고 왔다" / B "반려견이 장난감을 가져왔다" / C "오늘 주가가 크게 떨어졌다"

**① 세 문장을 3차원 벡터로 단순화해 좌표 받기** → A=[0.9, 0.8, 0.1], B=[0.85, 0.82, 0.15], C=[0.1, 0.2, 0.95]
> 💡 실제론 수백 차원이지만 3개만 봐도 A·B는 앞 두 축이 크고 C만 세 번째 축이 크다는 패턴이 바로 보여요 — 아하 포인트.

**② A와 B의 내적(같은 자리끼리 곱해서 더하기)** → `0.9×0.85 + 0.8×0.82 + 0.1×0.15 = 1.436`
> 💡 내적이 크다는 건 두 벡터가 같은 방향을 많이 공유한다는 뜻이에요.

**③ 벡터 크기로 나눠서(정규화) 코사인 유사도 완성** → |A|≈1.207, |B|≈1.192 → `cos(A,B) = 1.436 ÷ (1.207×1.192) ≈ 0.998`
> 💡 내적만 쓰면 문장이 길수록 유리해지니, 크기로 나눠 "방향"만 순수하게 비교해요.

**④ 같은 방식으로 A와 C도 계산해 대조** → `cos(A,C) ≈ 0.295` — cos(A,B)=0.998과 비교하면 확 낮아요.
> 💡 뜻이 먼 문장은 값이 뚝 떨어진다는 걸 숫자로 눈앞에서 확인해요.

좋은 결과의 기준: (1) 뜻이 비슷한 쌍(A-B)의 값이 1에 훨씬 가깝다 (2) 뜻이 먼 쌍(A-C)은 값이 뚜렷하게 낮다 (3) 계산 과정에서 반드시 정규화(크기로 나누기)를 거쳤다.

## 단계별 따라하기

1. **임베딩이 왜 필요한지 손으로 체감하기** — 종이에 세 문장(A: 강아지가 공을 물고 왔다 / B: 반려견이 장난감을 가져왔다 / C: 오늘 주가가 크게 떨어졌다)을 적는다. 글자 겹침(키워드 매칭)으로는 셋 다 안 겹치지만 뜻은 A와 B가 짝. '글자만 비교하면 어떤 쌍이 비슷하다고 나올까?'를 먼저 추측한다.
2. **AI에게 임베딩 개념을 3D로 번역시키기** — ChatGPT나 Claude에 첫 프롬프트를 붙여넣어 실제 임베딩(수백 차원)을 3차원 벡터로 비유해 각 문장에 좌표를 받는다. A=[0.9,0.8,0.1], B=[0.85,0.82,0.15], C=[0.1,0.2,0.95] — 숫자보다 'A와 B의 방향이 비슷하다'는 감을 잡는다.
3. **코사인 유사도 공식을 직접 계산하기** — 코사인 유사도 = (두 벡터의 내적) ÷ (각 벡터 크기의 곱). 내적은 같은 자리 숫자끼리 곱해서 더하고, 크기는 각 숫자를 제곱해 더한 뒤 루트. A·B 내적 = `0.9×0.85+0.8×0.82+0.1×0.15 = 1.436`, |A|=√(0.81+0.64+0.01)=1.207, |B|=√(0.7225+0.6724+0.0225)=1.192 → `cos ≈ 0.998`.
4. **A와 C 유사도도 계산해 대조하기** — 같은 공식으로 A·C 내적 = `0.9×0.1+0.8×0.2+0.1×0.95 = 0.345` → `cos = 0.345 ÷ (1.207×0.969) ≈ 0.295`. A-B(0.998) ≫ A-C(0.295), '뜻이 먼 문장은 값이 확 낮아진다'를 눈으로 확인한다.
5. **진짜 임베딩 API로 재현하기** — Cohere 무료 임베딩 플레이그라운드나 OpenAI embeddings에 같은 세 문장을 넣어 실제 벡터를 뽑고, 두 번째 프롬프트로 코사인 유사도 표를 받는다. 실제 예: A-B 0.71, A-C 0.09, B-C 0.11 → 값 크기는 달라도 '손계산의 방향(A-B가 최고)'이 진짜 모델에서도 재현된다.
6. **미니 의미검색기 만들기** — 세 번째 프롬프트로 '문서 5개 + 질문 1개'를 주고 임베딩 유사도 순으로 정렬한다. 질문 '강아지 산책 팁' → 반려동물 운동 글이 0.68로 1위, 주식 뉴스가 0.05로 꼴찌. 이게 바로 검색엔진·RAG 챗봇의 핵심 동작.

## 흔한 실수 → 교정

- ✗ 코사인 유사도와 '거리(distance)'를 헷갈려 값이 클수록 멀다고 해석 → **코사인 유사도는 1에 가까울수록 '비슷함'.** 멀다고 표현하려면 1에서 유사도를 뺀 값(코사인 거리)을 쓴다.
- ✗ 벡터 크기(분모)로 나누는 정규화를 빼먹고 내적만으로 비교 → **내적만 쓰면 길이가 긴 벡터가 무조건 커 보인다.** 반드시 각 벡터 크기의 곱으로 나눠 방향만 비교해야 공정하다.
- ✗ 임베딩이 글자·철자를 비교한다고 오해 → **임베딩은 '의미'를 좌표로 바꾼다.** 글자가 하나도 안 겹쳐도(강아지 vs puppy) 유사도가 높게 나오는 게 정상.

## 실전 프롬프트

### 임베딩 3D 비유 좌표 뽑기

```text
다음 세 문장을 의미 임베딩의 원리대로 사람이 이해할 수 있게 3차원 벡터(각 축 0~1)로 좌표를 매겨줘. 각 축이 대략 어떤 의미(예: 동물성/동작/경제성)를 담는지도 한 줄로. 문장1: [강아지가 공을 물고 왔다] 문장2: [반려견이 장난감을 가져왔다] 문장3: [오늘 주가가 크게 떨어졌다]. 마지막에 세 문장 중 어느 두 개가 방향이 가장 비슷한지 알려줘.
```

> 확인된 작성 예시 없음

`임베딩` `벡터` `3D비유`

### 코사인 유사도 표 계산

```text
아래 문장들의 의미 임베딩을 기준으로 모든 쌍의 코사인 유사도를 -1~1 값으로 계산해 표로 보여줘. 계산 공식(내적 ÷ 크기 곱)도 한 줄로 같이 보여주고, 가장 유사한 쌍과 가장 다른 쌍을 콕 짚어줘. 문장 목록: [문장 3~5개]
```

> 확인된 작성 예시 없음

`코사인 유사도` `표`

### 미니 의미검색기(RAG 맛보기)

```text
너는 임베딩 기반 의미검색 엔진이야. 아래 [문서] 5개와 [질문] 1개가 있어. 각 문서와 질문의 의미 유사도를 0~1로 추정해 높은 순으로 정렬하고, 왜 1위 문서가 질문과 가장 가까운지 한 줄로 설명해줘. [질문]: [강아지 산책 팁]. [문서]: 1)... 2)... 3)... 4)... 5)...
```

> 확인된 작성 예시 없음

`의미검색` `RAG`

벡터 A=[숫자,숫자,숫자], B=[숫자,숫자,숫자]가 있어. 코사인 유사도를 내적과 각 벡터 크기를 단계별로 다 보여주면서 계산해줘. 내가 손으로 구한 값은 [내 답]인데 맞는지 검산하고, 틀렸으면 어디서 틀렸는지 짚어줘.
