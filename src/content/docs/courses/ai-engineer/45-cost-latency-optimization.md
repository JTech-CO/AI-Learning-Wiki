_모델 티어 선택·프롬프트 캐싱·배치·프롬프트 축약으로 응답 속도와 API 비용을 동시에 낮추는 최적화 전략을 익힌다._

:::note[학습 목표]
- 이 레슨이 끝나면, 하나의 AI 기능에서 모델 티어·프롬프트 캐싱·배치·프롬프트 축약을 적용해 비용과 지연을 측정 가능한 수치로 낮춘 최적화 리포트 1장을 만들 수 있습니다.
:::

> 매달 나오는 AI API 청구서를 보고 놀란 적 있나요? 같은 결과를 내면서 비용은 10분의 1로, 응답은 2배 빠르게 만드는 방법이 실제로 존재합니다.

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 하나의 AI 기능에서 모델 티어·프롬프트 캐싱·배치·프롬프트 축약을 적용해 비용과 지연을 측정 가능한 수치로 낮춘 최적화 리포트 1장을 만들 수 있습니다.

## 핵심 개념

AI API 비용은 대부분 '입력 토큰 + 출력 토큰 x 모델 단가'로 정해집니다. 그래서 최적화의 핵심은 네 가지입니다. (1) 작업 난이도에 맞는 모델 티어 선택(쉬운 일에 비싼 모델 쓰지 않기), (2) 반복되는 긴 지시문을 캐싱해 재사용, (3) 급하지 않은 대량 작업은 배치로 묶어 할인, (4) 프롬프트에서 군더더기를 걷어내 토큰 자체를 줄이기. 카페 주문에 비유하면, 굳이 바리스타 명장(고급 모델)에게 얼음물(간단 작업)을 시키지 않고, 매번 같은 주문서(캐싱)를 다시 읽히지 않으며, 단체 주문(배치)은 미리 예약하는 것과 같습니다. 중요한 건 '감'이 아니라 실제 토큰 수와 응답 시간을 재서 비교하는 것입니다.

### 왜 작동하는가

단순한 작업까지 최고급 모델에게 맡기면, 마치 라면 끓이는 데 미슐랭 셰프를 부르는 것과 같아요. AI 비용은 "쓴 토큰 수 x 모델 단가"로 정해지기 때문에, 작업 난이도에 맞는 모델을 고르고 반복되는 부분을 캐싱해두면 품질은 그대로 두고 값만 확 낮출 수 있습니다. 그래서 당신은 "어떤 결과가 필요한지"만 정하면, 값을 깎는 계산은 이 네 가지 트릭(모델 다운그레이드·캐싱·배치·축약)이 대신 해줍니다.

## 👀 따라하기 예시

하루 2000건씩 돌아가는 "고객 리뷰 긍정/부정 분류" 기능이 매달 청구서 폭탄을 만들고 있어요. 제가 먼저 이 기능을 처음부터 끝까지 최적화해볼게요, 눈으로 따라오세요.

### 1. ① 현재 비용부터 잰다

**실제 결과**

```text
GPT-4o 사용 중, 입력 850토큰 / 출력 5토큰, 응답 2.4초, 호출당 약 0.005달러 x 하루 2000건 = 하루 10달러
```

> 재지 않으면 뭘 고쳤는지도 모릅니다. 숫자가 먼저예요.

### 2. ② 더 싼 모델로 20개만 테스트

**실제 결과**

```text
GPT-4o-mini로 같은 20개 리뷰 분류 → 20개 전부 정답 일치, 응답 0.9초, 호출당 0.0003달러
```

> 품질이 같으면 굳이 비싼 모델 쓸 이유가 없어요. 이게 바로 아하 포인트!

### 3. ③ 고정 지시문을 앞으로 몰아 캐싱

**실제 결과**

```text
역할 설명·분류 규칙 600토큰을 프롬프트 맨 앞에 고정 배치 → 캐시 히트 시 이 부분 비용 대폭 할인
```

> 매번 바뀌는 리뷰 텍스트만 새로 계산되니 반복 비용이 사라져요.

### 4. ④ 전후 비교표로 마무리

**실제 결과**

```text
하루 10달러 → 0.5달러(95%↓), 응답 2.4초 → 0.9초, 품질 동일 → 월 285달러 절감
```

> 한 장짜리 표가 있어야 "진짜 절감됐다"를 남에게도 보여줄 수 있어요.

### 완성 결과

완성물은 "최적화 전/후 비교표 1장"입니다. 좋은 결과의 기준: (1) 품질이 최적화 전과 동일하다는 근거(샘플 비교)가 있다, (2) 비용·응답시간이 실제 숫자로 비교되어 있다, (3) "왜 이 조합을 골랐는지" 한 문장 결론이 있다.

## 단계별 따라하기

### 1단계 — 최적화할 AI 기능 1개와 현재 비용 측정 (5분)

내가 쓰는 AI 호출 중 가장 자주 실행되거나 가장 비싼 것 하나를 고른다. 그 프롬프트를 실제로 한 번 돌려보고, 입력/출력 토큰 수와 걸린 시간을 기록한다. 토큰은 OpenAI Tokenizer나 Anthropic 콘솔에서 확인한다.

**복사·실행 예시**

```text
🙋나: '고객 리뷰를 긍정/부정으로 분류' 기능 선택. 현재 GPT-4o 사용, 입력 850토큰(전체 리뷰+긴 지시문) / 출력 5토큰, 응답 2.4초, 호출당 약 0.005달러 x 하루 2000건 = 하루 10달러.
```

### 2단계 — 모델 티어 다운그레이드 실험 (7분)

같은 프롬프트를 더 싸고 빠른 모델(예: GPT-4o-mini, Claude Haiku, Gemini Flash)로 그대로 돌린다. 결과 품질이 유지되는지 20개 샘플로 눈으로 비교한다. 품질이 같으면 채택, 떨어지면 원래 티어 유지.

**복사·실행 예시**

```text
🤝함께: 리뷰 분류를 GPT-4o-mini로 교체 → 20개 중 20개 정답 일치, 응답 0.9초, 호출당 0.0003달러. 품질 동일하므로 채택 → 비용 약 94% 절감.
```

### 3단계 — 반복되는 지시문 프롬프트 캐싱 적용 (8분)

프롬프트에서 매번 똑같이 들어가는 부분(역할 지시, 분류 규칙, 예시)을 앞쪽에 모으고, 매번 바뀌는 부분(실제 리뷰 텍스트)을 뒤로 뺀다. Anthropic은 cache_control, OpenAI는 프롬프트를 안정적으로 앞부분에 고정하면 자동 캐싱 할인이 적용된다.

**복사·실행 예시**

```text
🙋나: 고정 지시문 600토큰을 캐시 처리 → 캐시 히트 시 그 부분 비용이 크게 내려가고, 실제 청구는 바뀌는 리뷰 텍스트 위주로만 계산됨.
```

### 4단계 — 급하지 않은 작업은 배치로 전환 (6분)

실시간 응답이 꼭 필요한지 판단한다. 야간에 몰아서 처리해도 되는 작업이면 Batch API로 묶어 제출한다. 보통 24시간 내 처리 조건으로 표준 대비 큰 할인이 적용된다.

**복사·실행 예시**

```text
🤖A: '이 작업이 실시간이 필요한지, 배치로 돌려도 되는지 판단 기준을 알려줘'라고 AI에 물어 판단 → 리뷰 분류는 대시보드용이라 실시간 불필요 → Batch API로 야간 처리 전환해 추가 할인.
```

### 5단계 — 프롬프트 축약으로 토큰 다이어트 (7분)

프롬프트에서 중복 설명, 불필요한 예의 표현, 장황한 예시를 걷어낸다. 출력도 'JSON만', '한 단어만' 처럼 최소 형식으로 제한한다. AI에게 프롬프트를 압축시켜 토큰을 세어 비교한다.

**복사·실행 예시**

```text
🤖A: '아래 프롬프트를 의미 손실 없이 최대한 짧게 다시 써줘'로 850토큰 지시문을 420토큰으로 축약. 출력도 긍정/부정 한 단어로 제한 → 입력 토큰 절반.
```

### 6단계 — 최적화 전후 비교 리포트 1장 작성 (6분)

측정한 수치를 표로 정리한다. 항목: 모델, 입력/출력 토큰, 응답 시간, 호출당 비용, 일일 비용. 최적화 전/후 두 열로 나란히 놓고 절감률을 적는다.

**복사·실행 예시**

```text
🙋나: 표 작성 → 하루 10달러 → 0.5달러(95%↓), 응답 2.4초 → 0.9초. 품질 동일. 한 문장 결론: '분류 작업은 mini+캐싱+배치로 충분하며 월 285달러 절감.'
```

## 흔한 실수와 교정
- **실수:** 모든 작업에 무조건 가장 비싼 최신 모델을 쓴다.
  - **교정:** 작업 난이도부터 판단한다. 분류·추출·요약 같은 단순 작업은 소형 모델로 20개 샘플 비교 후 품질이 같으면 다운그레이드한다.
- **실수:** '느낌상 싸졌다'며 실제 토큰과 비용을 재지 않는다.
  - **교정:** Tokenizer로 입력/출력 토큰을 세고, 호출당·일일 비용을 최적화 전후로 숫자 비교한다. 측정 없는 최적화는 착각이다.
- **실수:** 매번 바뀌는 텍스트와 고정 지시문을 뒤섞어 캐싱이 무효화된다.
  - **교정:** 고정 지시문을 프롬프트 앞쪽에 모으고 가변 입력을 뒤로 빼서 캐시 히트율을 높인다.

## 완료 체크리스트

- 최적화 대상 AI 기능 1개를 고르고 현재 토큰/시간/비용을 측정했다
- 더 싸고 빠른 모델로 20개 샘플 품질을 비교했다
- 고정 지시문과 가변 입력을 분리해 캐싱 구조로 재배치했다
- 실시간이 불필요한 작업을 배치로 전환할지 판단했다
- 프롬프트를 축약하고 출력 형식을 최소화했다

## 도구

- OpenAI Tokenizer (https://platform.openai.com/tokenizer) — 입력/출력 토큰 수 세기
- OpenAI Batch API (https://platform.openai.com/docs/guides/batch) — 대량 작업 할인 처리
- Anthropic Prompt Caching 문서 (https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching) — 반복 지시문 캐싱
- OpenRouter (https://openrouter.ai) — 여러 모델 티어 단가 한눈에 비교

## 참고 답안

예: "이메일 제목 생성" 기능 선택 → 현재 GPT-4o, 호출당 0.004달러 → GPT-4o-mini로 20개 비교해 품질 동일 확인 → 고정 지시문(톤·형식 규칙) 500토큰을 앞으로 몰아 캐싱 → 결과: 호출당 0.0004달러, 약 90% 절감, 응답 1초 단축.
