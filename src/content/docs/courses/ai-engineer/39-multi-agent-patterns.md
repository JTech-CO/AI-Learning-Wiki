_관리자-작업자·파이프라인·토론 등 멀티 에이전트 협업 패턴과 역할 분리·핸드오프·종료 조건을 설계하는 법을 익힌다._

:::note[학습 목표]
- 이 레슨이 끝나면, 관리자-작업자·파이프라인·토론 3가지 협업 패턴 중 하나를 골라 역할·핸드오프·종료 조건까지 정의한 멀티 에이전트 워크플로 설계서 한 장을 만들 수 있습니다.
:::

> 하나의 AI에게 "블로그 글 쓰고, 검수하고, 이미지까지 골라줘"라고 시키면 어중간한 결과가 나옵니다. 사람 회사가 역할을 나누듯, AI도 여러 에이전트로 쪼개면 훨씬 좋아집니다.

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 관리자-작업자·파이프라인·토론 3가지 협업 패턴 중 하나를 골라 역할·핸드오프·종료 조건까지 정의한 멀티 에이전트 워크플로 설계서 한 장을 만들 수 있습니다.

## 핵심 개념

멀티 에이전트란 하나의 큰 일을 여러 AI '역할'에게 나눠 맡기고, 그 결과물을 서로 주고받게 만드는 방식입니다. 사람 팀에서 기획-실무-검수가 나뉘듯, 각 에이전트에 좁고 명확한 역할을 주면 환각과 누락이 줄어듭니다. 대표 패턴 3가지는 (1) 관리자가 일을 쪼개 작업자에게 배분하는 '관리자-작업자', (2) A의 출력이 B의 입력이 되는 '파이프라인', (3) 서로 반박하며 답을 다듬는 '토론'입니다. 핵심 설계 요소는 역할 분리(누가 뭘 하나), 핸드오프(무엇을 어떤 형식으로 넘기나), 종료 조건(언제 멈추나)입니다. 종료 조건이 없으면 토론 에이전트가 무한 반복하며 비용만 태우니 반드시 못박아야 합니다.

### 왜 작동하는가

AI 한 대에게 "써, 검수해, 다듬어"를 한꺼번에 시키면 머릿속이 뒤섞여 검수를 대충 넘어가곤 합니다. 그런데 역할을 셋으로 쪼개 "너는 오직 지적만 해"라고 좁혀주면, 그 역할에만 집중하느라 놓치는 게 훨씬 줄어듭니다. 그래서 당신은 역할·핸드오프 형식·종료 조건 이 세 가지만 설계하면, 실행은 AI들끼리 주고받으며 끝냅니다.

## 👀 따라하기 예시

2022 개정 초등 수학 분수 단원 블로그 글 1편을 파이프라인(작가→검수자→편집자)으로 만들어야 하는 상황. 제가 먼저 처음부터 끝까지 돌려볼게요, 눈으로 따라오세요.

### 1. ① 목표를 한 줄로 고정하고 작가 역할 시작

**실제 결과**

```text
목표: 분수의 덧셈 개념 글 1편(2000자, 예제 3개, 오탈자 0). 작가 AI 초안 첫 문장: 1/2와 1/3을 더하려면 왜 분모부터 맞춰야 할까요? 피자 조각으로 생각해봅시다.
```

> 목표 문장이 없으면 나중에 검수자가 뭘 기준으로 통과·탈락을 판단할지 알 수 없어요. 뿌리부터 심어둡니다.

### 2. ② 검수자에게 JSON 형식으로만 답하라고 못박기

**실제 결과**

```text
검수자 응답: pass=false, issues=[예제가 2개뿐 3개 필요, 3번째 문단에 오탈자 있음(분모가→분자가)]
```

> 자유 문장으로 예제가 좀 부족한 것 같아요 받으면 작가가 뭘 몇 개 더 써야 하는지 파싱하기 어려워요. 정해진 형식이 다음 에이전트의 입력을 깔끔하게 만듭니다.

### 3. ③ issues를 들고 작가에게 되돌리기(1회차 반복)

**실제 결과**

```text
작가 AI: 예제 3번째 추가함 — 3/4 - 1/4=2/4=1/2. 오탈자 수정 완료. 검수자 재확인: pass=true, issues=[]
```

> pass=false → 되돌림 → 재검수, 이 왕복이 바로 파이프라인이 스스로 품질을 끌어올리는 지점이에요. 사람이 매번 안 고쳐도 됩니다.

### 4. ④ 편집자에게 마지막 다듬기만 맡기고 종료

**실제 결과**

```text
편집자: 제목을 분수 덧셈, 분모부터 맞추는 이유로 확정, 소제목 3개 삽입, SEO 키워드 분수 덧셈 2회 배치. → 최종 산출물 완성.
```

> 편집자는 절대 내용을 다시 쓰지 않아요. 역할이 좁아야 검수자가 이미 통과시킨 내용을 편집자가 망치지 않습니다.

### 완성 결과

완성물: 블로그 글 1편(제목+본문 2000자+예제 3개). 좋은 결과의 기준 — (1) 검수자 pass=true를 실제로 받았는가, (2) 왕복 횟수가 최대 상한(3회) 안에서 끝났는가, (3) 각 역할이 자기 일만 했는가(작가가 SEO 손대지 않았는가).

## 단계별 따라하기

### 1단계 — 목표와 산출물 한 줄로 고정 (5분) 🙋나

만들 최종 결과물이 무엇인지, 무엇이 있으면 '완성'인지 한 문장으로 적는다. 이게 나중에 종료 조건의 뿌리가 된다.

**복사·실행 예시**

```text
목표: '2022 개정 초등 수학 분수 단원 블로그 글 1편(2000자, 예제 3개, 오탈자 0)을 자동 생산한다.'
```

### 2단계 — 패턴 고르기 (5분) 🙋나

일의 성격으로 패턴을 고른다. 순서가 뚜렷하면 파이프라인, 큰 일을 잘게 나눠 병렬로 돌리면 관리자-작업자, 정답이 애매해 검증이 중요하면 토론.

**복사·실행 예시**

```text
블로그 글은 '초안→검수→SEO 다듬기' 순서가 뚜렷하므로 파이프라인 선택.
```

### 3단계 — 역할·시스템 프롬프트 쪼개기 (10분) 🤝함께

에이전트마다 이름·한 줄 임무·금지사항을 표로 적는다. 각 역할은 '한 가지 일'만 하도록 좁힌다. 초안은 AI에게 뽑게 하고 내가 다듬는다.

**복사·실행 예시**

```text
작가: 초안만 씀(사실확인 안 함) / 검수자: 오류·과장만 지적(다시 쓰지 않음) / 편집자: 제목·소제목·SEO만 손봄.
```

### 4단계 — 핸드오프 형식 정하기 (10분) 🙋나

에이전트 사이에 넘기는 데이터의 형식을 못박는다. 자유 문장 대신 JSON이나 정해진 머리말을 쓰면 다음 에이전트가 파싱하기 쉽다.

**복사·실행 예시**

```text
검수자는 반드시 {"pass": true/false, "issues": ["..."]} 형식으로만 응답. pass=false면 작가에게 issues와 함께 되돌림.
```

### 5단계 — 종료 조건과 상한 박기 (5분) 🙋나

언제 멈출지 3종류로 정한다: 성공 조건(무엇이 만족되면 끝), 최대 반복 횟수(무한루프 방지), 실패 탈출(몇 번 실패하면 사람 호출).

**복사·실행 예시**

```text
종료: 검수자 pass=true면 종료 / 최대 3회 왕복 / 3회째도 fail이면 초안을 사람에게 넘기고 중단.
```

### 6단계 — 손으로 1회 돌려보기 (15분) 🤖A

코드 없이 ChatGPT/Claude 대화창 하나에서 역할을 번갈아 연기시켜 워크플로를 검증한다. 핸드오프 형식과 종료 조건이 실제로 작동하는지 눈으로 확인.

**복사·실행 예시**

```text
'지금부터 너는 작가다' → 초안 → '이제 검수자다, JSON으로만' → {pass:false...} → '다시 작가로, 이 issues 반영' → ... pass:true에서 멈추는지 확인.
```

## 흔한 실수와 교정
- **실수:** 에이전트 한 개에 여러 역할을 몰아준다(초안 쓰기+사실확인+SEO 동시).
  - **교정:** 역할을 '한 가지 일'로 쪼갠다. 작가는 쓰기만, 검수자는 지적만. 좁을수록 품질이 올라간다.
- **실수:** 종료 조건을 안 정해 토론·재작성이 무한 반복되며 비용이 폭증한다.
  - **교정:** 성공 조건·최대 반복 횟수·실패 탈출 3종을 반드시 박는다. 예: 최대 3회, 3회째 실패면 사람 호출.
- **실수:** 핸드오프를 자유 문장으로 넘겨 다음 에이전트가 엉뚱하게 해석한다.
  - **교정:** JSON이나 고정 머리말 등 파싱 가능한 형식으로 계약을 정한다. 형식을 어기면 다시 요청한다.

## 완료 체크리스트

- 최종 산출물과 완성 기준을 한 문장으로 적었다
- 일의 성격에 맞는 패턴(관리자-작업자/파이프라인/토론)을 골랐다
- 각 에이전트의 이름·임무·금지사항을 한 가지 역할로 좁혀 정의했다
- 에이전트 간 핸드오프 형식(JSON 등)을 못박았다
- 성공 조건·최대 반복 횟수·실패 탈출까지 종료 조건 3종을 정하고 손으로 1회 돌려봤다

## 도구

- ChatGPT (chat.openai.com) — 대화창 하나에서 역할 번갈아 연기시켜 워크플로 검증
- Claude (claude.ai) — 긴 지시·JSON 핸드오프 설계와 시뮬레이션에 강함
- n8n (n8n.io) — 코드 없이 에이전트 파이프라인을 노드로 연결·자동화
- CrewAI (crewai.com) — 관리자-작업자·역할 기반 멀티 에이전트를 코드로 구현하는 프레임워크

## 참고 답안

작가: 대본 초안만 씀(60초 분량, 예시 1개 포함) / 검수자: pass·issues 형식으로 시간 초과·예시 부족만 지적, 다시 쓰지 않음 / 편집자: 오프닝 후킹 문장과 엔딩 궁금증 문장만 다듬음. 종료 조건: 검수자 pass=true면 종료, 최대 3회 왕복, 3회째도 fail이면 사람이 직접 마무리.
