_"이렇게 정리해줘"라고 백 번 설명하는 대신 잘 된 예시 2~3개만 붙여넣어 AI에게 원하는 출력 형식·스타일을 학습시킨다. 예시의 개수·순서·품질이 결과에 어떤 영향을 주는지 직접 실습한다._

:::note[학습 목표]
- '입력→출력' 예시 2~3개를 프롬프트에 넣어 AI의 출력 형식·스타일을 원하는 대로 고정한다
- 예시 개수를 1→3개로 늘려가며 형식이 안정되는 '최소 개수'를 찾는다
- 예시끼리 구분자·말투·길이·이모지를 글자 단위로 통일해 저품질 예시를 걸러낸다
:::

## 핵심 개념

퓨샷(few-shot)은 **'입력→출력' 예시 몇 개를 프롬프트에 넣어 AI에게 원하는 패턴을 학습시키는 기법**이에요. 규칙을 길게 말로 설명하는 대신(제로샷) 완성된 정답 예시를 보여주면 AI가 형식·말투·길이·구조를 그대로 흉내 냅니다. 신입에게 "보고서는 이렇게 써"라고 지난 보고서 샘플을 건네는 것과 똑같아요. 예시의 **개수(보통 2~5개), 순서, 그리고 무엇보다 '품질'**이 결과를 좌우하며, **나쁜 예시 하나가 좋은 설명 열 줄보다 더 나쁜 영향**을 줍니다.

### 왜 이게 될까?

예시는 규칙보다 강해요. AI는 이미 수억 개의 '입력→출력' 패턴을 학습했기 때문에, 당신이 말로 백 번 설명할 규칙을 예시 2~3개만 보여줘도 그 안의 형식·말투·구조를 즉시 캐치해서 따라합니다. 그래서 '정답처럼 보이는 예시' 몇 개만 정성껏 만들면 나머지 반복 작업은 AI가 그 패턴대로 대신 해줘요.

## 👀 따라하기 예시 — 쇼핑몰 고객 문의를 담당팀에 자동 분류하는 프롬프트

**① 예시 없이 그냥 지시만** 입력 '배송이 아직도 안 왔어요' → 출력 '안녕하세요 고객님, 문의주신 배송 지연 관련하여 확인 후 안내드리겠습니다.' (너무 길고 존댓말, 형식이 안 잡힘)
> 💡 예시 없이는 AI가 제 머릿속 형식을 모름 — 이 차이가 바로 예시로 가르쳐야 할 부분이에요.

**② 좋은 예시 2개를 손으로 만들어 붙여넣기** 입력 '배송이 안 와요' → 출력 '📦 배송 지연 문의' / 입력 '환불 언제 되나요' → 출력 '💳 환불 시점 문의' / 입력 '사이즈 교환 되나요' → 출력 '👕 사이즈 교환 문의'
> 💡 예시 딱 2개만 줬는데 AI가 '이모지+한 줄+명사형' 패턴을 스스로 찾아냈어요. 아하 포인트!

**③ 일부러 애매한 경계 케이스 넣어보기** 입력 '배송도 늦고 환불도 원해요' → 출력 '📦💳 배송+환불 복합 문의'
> 💡 예시에 없던 복합 케이스도 패턴을 응용해서 처리 — 예시가 '규칙'이 아니라 '감각'을 가르친 거예요.

**④ 예시 3개 vs 1개 결과 비교하기** 예시 1개일 때 가끔 이모지 빠뜨림 / 예시 3개일 때 매번 정확히 이모지+한 줄 유지 → 3개로 확정
> 💡 예시는 무조건 많을수록 좋은 게 아니라 형식이 '안정되는 최소 개수'를 찾는 게 핵심이에요.

좋은 결과의 기준: (1) 모든 예시가 형식·말투·길이가 완전히 똑같다 (2) 애매한 입력에도 패턴이 안 깨진다 (3) 예시 개수가 필요 이상으로 많지 않다.

## 단계별 따라하기

1. **말로 안 되는 지점 찾기** — 먼저 예시 없이 그냥 지시만으로 AI에 시켜보고, 결과가 내가 원하는 형식과 어떻게 다른지 3가지를 메모. 이 '차이'가 예시로 가르칠 부분이다. (지시 '고객 문의를 요약해줘' → AI 결과가 너무 길고 존댓말이며 이모지가 없음. 원하는 건 한 줄, 반말체, 앞에 이모지 1개)
2. **좋은 예시 2~3개 직접 만들기** — 내가 원하는 형식대로 '입력→출력' 쌍을 손으로 2~3개 완성. 대충 말고 실제로 내놓고 싶은 최고 품질로. 예시들끼리 형식(구분자, 길이, 말투)을 반드시 통일. (입력: 배송이 아직도 안 왔어요 → 출력: 📦 배송 지연 문의 / 입력: 환불 언제 되나요 → 출력: 💳 환불 시점 문의)
3. **예시를 프롬프트에 넣고 형식 고정하기** — '다음 예시처럼 답해줘' 한 줄 + 예시 2~3개 + 마지막에 진짜 입력만 남기고 출력 자리는 비워둠. AI가 그 빈칸을 예시 형식대로 채운다.

```
아래 예시처럼 형식을 맞춰라.
입력: 배송이 안 와요 → 출력: 📦 배송 지연 문의
입력: 환불 언제 되나요 → 출력: 💳 환불 시점 문의
입력: 사이즈 교환 되나요 → 출력:
```

4. **예시 개수 A/B 테스트** — 같은 진짜 입력을 두고 예시 1개일 때 vs 3개일 때 결과를 나란히 비교. 보통 2~3개부터 형식이 안정. 무조건 많이 넣지 말고 '충분한 최소 개수'를. (예시 1개: 가끔 이모지를 빠뜨림 / 예시 3개: 매번 이모지+한 줄+반말 정확히 → 3개 채택)
5. **헷갈리는 경계 케이스를 예시로 추가** — AI가 자꾸 틀리는 애매한 입력을 골라 그 케이스의 정답 예시를 하나 더 추가. AI에게 '내 형식에서 실수하기 쉬운 경계 케이스 예시를 만들어줘'라고 시켜도 좋다. (복합 문의('배송도 늦고 환불도 원해요')를 AI가 헷갈려함 → 출력: 📦💳 배송+환불 복합 문의 예시를 추가하니 해결)
6. **나쁜 예시 제거하고 최종본 저장** — 예시 중 형식이 미묘하게 다르거나 오타가 있는 것을 제거. 나쁜 예시 하나가 전체 출력을 오염시킨다. 완성된 퓨샷 프롬프트를 메모앱에 템플릿으로 저장해 재사용. (예시 3개 중 하나만 존댓말이었음 → 제거하니 나머지 출력의 말투가 즉시 통일)

## 흔한 실수 → 교정

- ✗ 예시끼리 형식이 제각각(하나는 존댓말, 하나는 반말)이라 AI가 뭘 따라야 할지 몰라 결과가 뒤죽박죽 → **모든 예시의 구분자·말투·길이·이모지 유무를 글자 단위로 통일한다.** 예시는 '규칙의 사진'이므로 흔들리면 안 됨.
- ✗ 예시를 대충 만들거나 오타가 있는 저품질 예시를 넣음. 나쁜 예시 하나가 좋은 지시문보다 결과를 더 망침 → **예시는 '실제로 내놓을 최고 품질'로만.** 애매한 예시는 넣지 말고 빼는 게 나음.
- ✗ 무조건 예시를 많이(10개+) 넣으면 좋다고 생각해 토큰만 낭비하고 특정 예시에 과적합 → **보통 2~5개면 충분.** 개수를 1→3으로 늘리며 형식이 안정되는 '최소 개수'에서 멈춘다.

## 실전 프롬프트

### 기본 퓨샷 형식 고정

```text
다음 예시들과 똑같은 형식·말투·길이로 답해줘. 설명은 하지 말고 출력만.
입력: [예시입력1] → 출력: [예시출력1]
입력: [예시입력2] → 출력: [예시출력2]
입력: [예시입력3] → 출력: [예시출력3]
입력: [진짜입력] → 출력:
```

`퓨샷` `형식 고정`

### 예시를 AI에게 만들게 하기

```text
나는 [고객문의 한 줄 요약]을 하고 싶어. 내가 원하는 출력 형식은 [이모지1개+반말+한줄]이야. 이 형식을 잘 보여주는 서로 다른 입력→출력 예시 3개를 만들어줘. 예시끼리 형식은 완전히 통일.
```

`퓨샷` `예시 생성`

### 경계 케이스 예시 보강

```text
아래는 내 퓨샷 예시들이야. [기존 예시] 이 형식에서 AI가 실수하기 쉬운 애매한 경계 케이스 2개와 그 정답 출력을, 위와 똑같은 형식으로.
```

`퓨샷` `경계 케이스`

### 예시 개수 비교 실험

```text
같은 입력 [진짜입력]에 대해 아래 예시를 (a)1개만 줬을 때 (b)3개 다 줬을 때 각각 어떻게 답이 달라지는지 두 결과를 나란히. 예시: [예시1] / [예시2] / [예시3]
```

`퓨샷` `A/B 테스트`
