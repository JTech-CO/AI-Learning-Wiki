_단기(대화)·장기(벡터·파일) 메모리와 상태 저장으로 세션을 넘나들며 맥락을 유지하는 에이전트를 만드는 법을 익힌다._

:::note[학습 목표]
- 이 레슨이 끝나면, 세션이 바뀌어도 사용자 정보와 대화 맥락을 기억하는 간단한 메모리 에이전트를 직접 만들 수 있습니다.
:::

> 어제 30분 동안 설명한 내용을 오늘 다시 물으면 AI는 "처음 뵙겠습니다" 하고 백지로 돌아옵니다. 진짜 비서라면 어제 한 말을 기억해야 하지 않을까요?

## 이 레슨에서 만드는 것

이 레슨이 끝나면, 세션이 바뀌어도 사용자 정보와 대화 맥락을 기억하는 간단한 메모리 에이전트를 직접 만들 수 있습니다.

## 핵심 개념

에이전트의 "기억"은 사람 뇌처럼 두 종류로 나뉩니다. 단기 메모리는 지금 이 대화창 안에서만 유지되는 최근 대화 기록이고(창을 닫으면 사라짐), 장기 메모리는 파일이나 벡터DB에 저장해 며칠·몇 주 뒤에도 꺼내 쓰는 기억입니다. 카카오톡 상담봇이 "지난번 주문 잘 받으셨어요?"라고 묻는 건, 사용자 ID로 이전 대화를 파일에서 불러왔기 때문입니다. 핵심은 매 대화가 끝날 때 중요한 사실을 요약해 저장하고, 새 대화가 시작될 때 그 요약을 프롬프트 맨 앞에 다시 넣어주는 저장→불러오기 왕복입니다.

### 왜 작동하는가

AI는 원래 매 대화를 백지에서 시작합니다. 그런데 우리가 이전 요약을 JSON 파일에 저장해뒀다가, 새 대화가 열릴 때 그 요약을 프롬프트 맨 앞에 슬쩍 끼워 넣으면 AI는 마치 원래 기억하고 있던 것처럼 자연스럽게 이어받습니다. 그래서 당신은 "저장"과 "불러오기" 두 동작만 챙기면, 기억은 파일이 대신 해줍니다.

## 👀 따라하기 예시

단골 카페 상담봇을 만드는 중이라고 해봅시다. 고객 김민수 님이 어제 "저는 아메리카노보다 핫초코를 좋아해요"라고 말했는데, 오늘 새 대화창을 열어도 그 사실을 기억하게 만들고 싶습니다. 제가 먼저 처음부터 끝까지 해볼게요, 눈으로 따라오세요.

### 1. ① 어제 대화가 끝날 때, AI에게 "다음에도 기억할 사실만 3줄로 요약해줘"라고 시킵니다.

**실제 결과**

```text
- 아메리카노보다 핫초코 선호\n- 존댓말 사용 원함\n- 오전 방문이 잦음
```

> 원문 전체가 아니라 핵심만 뽑아야 나중에 파일이 안 터집니다.

### 2. ② 이 3줄을 memory/user_kim.json 파일의 last_summary 항목에 저장합니다.

**실제 결과**

```text
{"name":"김민수","prefs":"존댓말, 짧게","last_summary":"아메리카노보다 핫초코 선호 / 존댓말 사용 원함 / 오전 방문이 잦음"}
```

> 사용자 ID를 파일명으로 써서 1인 1파일로 분리하면 다른 사람 기억과 안 섞입니다.

### 3. ③ 오늘 새 대화가 열리자마자, 그 JSON을 읽어서 시스템 프롬프트 맨 앞에 "[기억: 아메리카노보다 핫초코 선호, 존댓말 사용]"이라고 붙여 넣습니다.

**실제 결과**

```text
[기억: 김민수 님, 아메리카노보다 핫초코 선호, 존댓말 사용, 오전 방문 잦음]\n사용자: 저 뭐 좋아한다고 했었죠?
```

> 불러오기를 대화 시작 전에 해둬야 AI가 첫 답변부터 기억한 척 반응합니다.

### 4. ④ 사용자 질문에 AI가 답합니다.

**실제 결과**

```text
"김민수 님은 아메리카노보다 핫초코를 좋아하시고, 오전에 자주 오신다고 기억하고 있어요!"
```

> AI 입장에선 이 문장도 방금 받은 프롬프트일 뿐이지만, 사용자 눈에는 진짜 기억처럼 보입니다.

### 완성 결과

완성물은 memory/user_kim.json 파일 하나 + "대화 끝나면 요약 저장, 대화 시작하면 요약 불러오기"라는 두 줄짜리 루틴입니다. 좋은 결과의 기준: (1) 창을 닫고 새로 열어도 이전 선호가 답변에 반영된다 (2) last_summary가 5줄을 넘지 않는다 (3) 다른 사용자 파일과 절대 섞이지 않는다.

## 단계별 따라하기

### 1단계 — 단기와 장기 메모리 개념 손으로 구분하기 (5분) 🙋나

종이나 메모장에 두 칸을 그리고, 내 챗봇이 기억해야 할 정보를 '이 대화만 필요'와 '다음에도 필요'로 나눠 적습니다. 앞칸이 단기, 뒷칸이 장기 메모리입니다.

**복사·실행 예시**

```text
단기: '방금 물어본 배송비 얼마?' / 장기: '이 고객 이름=김민수, 알레르기=땅콩, 지난주문=아메리카노'
```

### 2단계 — 사용자별 기억 파일 만들기 (7분) 🙋나

컴퓨터에 memory 폴더를 만들고, 사용자 한 명당 JSON 파일 하나를 둡니다. 파일 안에 이름·선호·최근요약 3개 항목만 먼저 넣어 구조를 잡습니다.

**복사·실행 예시**

```text
memory/user_kim.json 안에: {"name":"김민수","prefs":"존댓말, 짧게","last_summary":"땅콩 알레르기 확인함"}
```

### 3단계 — 불러오기: 저장된 기억을 프롬프트 맨 앞에 넣기 (8분) 🤝함께

새 대화를 시작할 때, JSON 파일을 읽어 그 내용을 시스템 프롬프트 앞부분에 '아래는 이 사용자에 대해 기억하는 사실'이라고 붙여 넣습니다. 아래 첫 번째 템플릿을 그대로 사용하세요.

**복사·실행 예시**

```text
프롬프트 첫 줄: [기억: 이름=김민수, 존댓말 선호, 땅콩 알레르기] 그 다음 사용자의 새 질문을 이어 붙임
```

### 4단계 — 저장하기: 대화 끝에 3줄 요약 생성해 파일에 갱신 (8분) 🤖A

대화가 끝나면 AI에게 '이번 대화에서 다음에도 기억할 새 사실만 3줄로 요약해줘'라고 시키고, 그 결과를 JSON의 last_summary에 덮어씁니다. 두 번째 템플릿을 사용합니다.

**복사·실행 예시**

```text
AI 요약 결과: '아이스보다 핫 선호 / 매장 방문 주로 오전 / 이번에 텀블러 구매' → 이 3줄을 파일에 저장
```

### 5단계 — 왕복 테스트: 창 닫고 다시 열어 기억 확인 (7분) 🙋나

대화를 저장한 뒤 창을 완전히 닫고 새로 엽니다. 3단계 방식으로 파일을 다시 불러와 '내가 뭘 좋아한다고 했지?'라고 물어 기억이 살아있는지 확인합니다.

**복사·실행 예시**

```text
새 창에서 질문: '나 뭐 좋아한댔지?' → 답: '핫 음료를 선호하시고 오전에 자주 오신다고 기억합니다'
```

### 6단계 — 넘침 방지: 오래된 기억 정리 규칙 정하기 (5분) 🤝함께

기억이 무한정 쌓이면 프롬프트가 터집니다. 'last_summary는 최대 5줄, 넘으면 가장 오래된 줄 삭제' 같은 한 줄 규칙을 파일 맨 위 주석이나 별도 rule에 적어둡니다.

**복사·실행 예시**

```text
rule: '중요 사실 5개까지만 유지, 90일 이상 안 쓴 사실은 archived로 이동'
```

## 흔한 실수와 교정
- **실수:** 매 대화가 끝날 때 저장을 안 해서, 불러올 기억 파일이 늘 비어 있다.
  - **교정:** 대화 종료를 하나의 '루틴'으로 정하세요. 끝날 때마다 2번째 템플릿으로 3줄 요약을 만들어 파일에 덮어쓰는 걸 습관화하면 됩니다.
- **실수:** 대화 전체 원문을 통째로 저장해 파일이 수천 줄로 불어나고 프롬프트가 터진다.
  - **교정:** 원문 대신 '요약'만 저장하세요. 원문은 버리고 핵심 사실 5줄 이내만 남기는 것이 장기 메모리의 핵심입니다.
- **실수:** 여러 사용자의 기억을 한 파일에 섞어 저장해, 엉뚱한 사람 정보로 답한다.
  - **교정:** 사용자 ID(전화번호·이메일 등)를 파일명으로 삼아 user_kim.json처럼 1인 1파일로 완전히 분리하세요.

## 완료 체크리스트

- 단기·장기 기억을 종이에 실제로 나눠 적어봤다
- 사용자 1명당 JSON 파일 1개 구조를 만들었다
- 저장된 기억을 프롬프트 맨 앞에 넣어 대화를 시작해봤다
- 대화 끝에 3줄 요약을 만들어 파일에 갱신했다
- 창을 닫았다 다시 열어 기억이 유지되는지 확인했다
