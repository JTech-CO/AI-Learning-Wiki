_여러 단계를 잇고 조건에 따라 경로를 나누며, 실패 시 자동 재시도·알림까지 넣은 견고한 자동화 흐름 하나를 Make로 직접 구성한다. 사람 손 안 대고 '신청서 → 견적 계산 → 금액 크면 승인, 작으면 자동 처리'까지 흐르게 만드는 것이 목표다._

:::note[학습 목표]
- 여러 단계를 하나의 흐름으로 잇고(체인), 조건에 따라 경로를 나눈다(Router·Filter)
- 실패할 수 있는 단계에 재시도와 오류 알림을 걸어 흐름을 견고하게 만든다
- Run once로 고액·소액·실패 케이스를 검증한 뒤 스케줄을 켜 사람 개입 없이 돌린다
:::

## 핵심 개념

단순 자동화가 "A 하면 B 한다"라면, 실무 자동화는 **"A 하면, 조건을 보고 B 또는 C로 갈라지고, 중간에 실패하면 다시 시도하거나 나에게 알린다"**예요. 핵심은 세 부품이에요: 여러 단계를 잇는 **연결(체인)**, 조건으로 길을 나누는 **분기(if/else·Router·Filter)**, 실패에 대비하는 **안전장치(재시도·오류 알림)**. 택배 물류 흐름처럼 — 주소가 정상이면 배송으로, 문제 있으면 반송 라인으로 자동으로 갈라지고, 배송 실패 시 재시도 후 담당자에게 문자가 가는 식이죠. Make(구 Integromat)나 n8n 같은 노코드 도구면 코드 없이 블록으로 조립할 수 있어요.

### 왜 이게 될까?

Make 같은 노코드 도구는 "만약 ~이면 이 길, 아니면 저 길"을 Router+Filter 블록으로 미리 정해두면, 데이터가 들어올 때마다 조건만 자동으로 확인해서 알아서 갈라 보내요. 조건과 갈림길을 한 번만 설계해두면 신청서가 100건이든 1000건이든 사람 손 없이 각자 맞는 경로로 흘러가요. 실패 대비(재시도·알림)도 같은 원리예요 — 미리 "실패하면 이렇게" 규칙을 걸어두면 AI가 아니라 도구 자체가 그 약속을 계속 지켜요.

## 👀 따라하기 예시 — 견적 금액에 따라 팀장 승인 or 자동 승인 분기 + 메일 실패 시 재시도 (Make)

**① 트리거 연결** Google Forms Watch Responses 모듈을 놓고 계정 연결 후 Run once → 신청서 필드(이름: 김민수, 견적금액: 450000)가 오른쪽 패널에 표시됨.
> 💡 실제 데이터가 넘어오는지부터 확인해야, 뒤에 만들 조건식이 진짜 필드명으로 맞게 걸려요.

**② Router 추가** 두 경로 분기점 생성 → 화살표가 두 갈래(경로A, 경로B)로 나뉨.
> 💡 Router는 "여기서부터 길이 나뉜다"는 표시일 뿐, 아직 조건은 없어요 — 다음 단계에서 Filter로 조건을 걸어야 진짜 분기가 돼요.

**③ 경로별 Filter** 경로A에 `{{amount}} >= 300000`, 경로B에 `{{amount}} < 300000` → 450000으로 테스트 실행 → 경로A만 초록색, 경로B는 회색(미실행).
> 💡 두 조건이 겹치지도, 빠지지도 않게(경계값 300000 포함) 걸어야 "동시에 둘 다 실행" 사고를 막아요.

**④ 끝단 + 안전장치** 경로A 끝에 Slack 승인요청, 경로B 끝에 Gmail 자동확인메일. 각 메일 모듈에 error handler(Break, 재시도 3회) → 일부러 잘못된 이메일로 테스트하면 15분 간격 재시도 로그 3번, 최종 실패 시 "자동화 실패 알림" 메일이 내 주소로 옴.
> 💡 실패는 언젠가 반드시 일어나므로, 실패했을 때 사람이 자동으로 알게 되는 경로까지 있어야 흐름이 "완성"이에요.

좋은 결과의 기준: (1) 고액·소액 테스트 각각 딱 한 경로만 실행됨 (2) 실패를 일부러 유발해도 방치되지 않고 알림이 옴 (3) 스케줄 ON 후에도 사람 개입 없이 계속 돎.

## 단계별 따라하기

1. **자동화할 흐름을 종이에 순서도로 그리기** — 만들기 전에 반드시 흐름을 글로 먼저. '무엇이 시작(트리거)이고 → 어떤 단계들을 거치고 → 어디서 조건으로 갈라지는지 → 실패하면 어떻게 할지'를 한 줄씩. 화살표(→)와 갈림(만약~이면/아니면)만 써도 충분.
2. **순서도를 AI에게 주고 자동화 설계로 변환** — 순서도를 그대로 붙여넣고, 어떤 노코드 도구의 어떤 블록(모듈)을 어떤 순서로 놓아야 하는지 물어본다. (예: 'Make — [1]Google Forms Watch Responses → [2]Set variable(견적계산) → [3]Router → 경로A: Filter(금액>=300000)+Slack / 경로B: Filter(금액<300000)+Gmail')
3. **Make에서 트리거와 첫 단계 연결** — make.com 무료 가입 → Create a new scenario → 첫 모듈로 트리거(예: Google Forms 'Watch Responses')를 놓고 계정 연결. 두 번째 모듈로 데이터 가공(Set variable 등). 실제 테스트 데이터 1건으로 'Run once'.
4. **Router로 조건 분기 만들기** — 흐름 중간에 'Router' 모듈을 추가하면 길이 두 갈래로. 각 갈래 시작점의 연결선을 클릭 → 'Set up a filter'로 조건. 경로A '금액 >= 300000', 경로B '금액 < 300000'. 조건이 맞는 경로만 실행.
5. **실패 대비: 재시도와 오류 알림 넣기** — 메일·슬랙처럼 실패할 수 있는 모듈에서 우클릭 → 'Add error handler' → 'Break' 지시자를 선택하면 실패 시 자동 재시도(시나리오 설정에서 재시도 횟수·간격). 오류 핸들러 끝에 나에게 알리는 모듈(예: 이메일 'To: 내 주소').
6. **전체 흐름 테스트하고 스케줄 켜기** — 고액 케이스 1건, 소액 케이스 1건을 실제로 제출해 두 경로가 각각 올바로 실행되는지 확인. 일부러 잘못된 이메일로 실패도 유발해 재시도·알림 작동 확인. 확인되면 좌하단 스케줄을 'ON'.

## 흔한 실수 → 교정

- ✗ 조건을 안 걸고 Router만 놓아서, 갈라진 두 경로가 '동시에 다' 실행 → **Router에서 갈라진 각 연결선에 반드시 Filter.** 경로A·B 조건이 서로 겹치지 않고(둘 다 참 방지), 어느 쪽에도 안 걸리는 값이 없게(경계값 포함) 설계.
- ✗ 실패를 대비하지 않아, 메일 한 번 실패하면 흐름이 멈추고 아무도 모름 → **실패 가능한 모듈마다 error handler를 붙이고,** 재시도 후에도 실패하면 나에게 알림(이메일/슬랙)이 가는 경로를 반드시.
- ✗ 만들자마자 실제 데이터로 켜서, 잘못된 흐름이 고객에게 진짜 메일을 보내버림 → **먼저 'Run once'로 테스트 데이터 1건씩(고액·소액·실패 케이스)을 돌려** 두 경로와 재시도를 검증한 뒤에 스케줄을 ON.

## 도구

- 🛠 **Make** (make.com) — 노코드로 다단계·조건분기 자동화 시나리오를 블록으로 조립.
- 🛠 **n8n** (n8n.io) — 오픈소스 자동화, 셀프호스팅 가능하고 분기·재시도 지원.
- 🛠 **Google Forms** (forms.google.com) — 신청·설문을 자동화 트리거로.
- 🛠 **Slack** (slack.com) — 승인요청·실패 알림을 받는 실시간 알림 채널.

## 실전 프롬프트

### 순서도 → 자동화 설계 변환 (가장 먼저)

```text
나는 노코드 자동화 도구 [Make 또는 n8n]로 아래 업무 흐름을 만들려고 해. 초보자용으로, 어떤 모듈(블록)을 어떤 순서로 놓아야 하는지 단계별로 알려줘. 조건 분기는 Router+Filter로, 실패 대비는 재시도와 오류 알림으로 해줘.
[업무 흐름]
트리거: [구글폼 신청 접수]
중간 단계: [견적 금액 계산]
조건 분기: 만약 [조건]이면 [경로A], 아니면 [경로B]
실패 대비: [어떤 단계]가 실패하면 [재시도/알림]
각 모듈의 이름과 핵심 설정값까지 구체적으로.
```

`자동화` `설계` `순서도`

### 분기 조건(필터) 정확히 쓰기

```text
Make의 Router 뒤 Filter 조건을 만들려고 해. 아래 상황에서 각 경로에 넣을 필터 조건(필드명, 연산자, 값)을 정확한 표현으로 알려줘. 경계값(예: 정확히 30만원)이 어느 경로로 가야 하는지도 명확히 해줘.
분기 기준: [견적 금액]
경로A: [팀장 승인]
경로B: [자동 처리]
경계 처리: [30만원은 승인 경로]
```

`분기` `필터` `조건`

### 오류 처리·재시도 설계

```text
내 자동화에서 [모듈 이름, 예: Gmail 발송] 단계가 가끔 실패해. Make의 error handler로 '몇 번 재시도 후 그래도 실패하면 나에게 알림'을 넣고 싶어. Break/Resume/Ignore/Rollback 중 무엇을 골라야 하는지 이유와 함께, 재시도 횟수·간격은 어떻게 잡는 게 좋은지 알려줘.
```

`오류 처리` `재시도`

### 흐름 점검 체크 (만들고 나서)

```text
아래는 내가 만든 자동화 흐름 설명이야. 논리적 허점(빠진 조건, 무한 반복 위험, 실패해도 알림 없는 구간, 두 경로에 다 걸리거나 아무 경로에도 안 걸리는 경우)이 있는지 점검하고, 고칠 점을 알려줘.
[흐름 설명 붙여넣기]
```
