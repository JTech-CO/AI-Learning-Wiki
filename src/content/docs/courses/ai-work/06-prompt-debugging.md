_원하는 답이 안 나올 때 프롬프트를 통째로 다시 쓰지 말고, 무엇이 빠졌는지 진단해 한 번에 한 가지씩만 고쳐 재시도하는 반복 개선 절차를 익힌다._

:::note[학습 목표]
- AI 답이 마음에 안 들 때 무엇이 빠졌는지 결함을 명사로 진단한다
- 한 번에 한 가지씩만 고쳐 3~4번 안에 원하는 답에 도달한다
- 효과 있던 수정을 기록해 재사용 템플릿으로 남긴다
:::

## 핵심 개념

프롬프트를 잘 쓴다는 건 **한 방에 완벽한 문장을 뽑는 게 아니라 빠르게 고쳐 나가는 것**이에요. AI가 엉뚱한 답을 주는 건 대부분 정보 부족(맥락·예시·형식 지정 누락) 때문이지 AI가 멍청해서가 아닙니다. 요리사에게 "맛있게 해주세요"라고만 하면 뭐가 나올지 모르듯, **빠진 조건을 하나씩 채우면 점점 정확해져요**. 핵심은 한 번에 여러 개를 바꾸지 않는 것. 두세 개를 동시에 고치면 어떤 수정이 효과였는지 알 수 없어 배울 게 없습니다.

### 왜 이게 될까?

AI가 엉뚱한 답을 주는 건 프롬프트에 정보가 빠졌기 때문이에요. "뭐가 빠졌는지"만 정확히 짚어 하나씩 채우면 매번 더 정확한 답을 냅니다. 과학실험의 **"변인통제"와 똑같아요** — 한 번에 하나만 바꿔야 무엇이 효과였는지 알 수 있고, 다음번엔 처음부터 좋은 프롬프트를 쓰게 됩니다.

## 👀 따라하기 예시 — "마케팅 문구 써줘" → 밋밋

**① 나쁜 답을 구체적으로 진단** "설명이 추상적이고 실제 예시가 하나도 없다."
> 💡 "별로다"가 아니라 결함을 명사로 콕 집어야 뭘 고칠지 보여요.

**② 원인 가설 딱 하나만** 내 프롬프트엔 예시도 독자도 없음 → 오늘은 "예시 없음"부터.
> 💡 결함이 5가지(맥락·예시·형식·독자·톤) 중 무엇인지 분류하면 고칠 지점이 명확해져요.

**③ 한 가지만 바꿔 재요청** 추가한 한 줄 "아래 좋은 예시 톤을 참고해서 다시 써줘: (좋은 예시 붙여넣기)" → 훨씬 구체적.
> 💡 통째로 새로 쓰지 않고 한 줄만 얹으면 맥락이 유지되며 이 수정의 효과만 확인할 수 있어요.

**④ 전후 비교·기록** 메모 "먹히는 조건 = 좋은 예시 직접 붙여넣기. 효과 O." → 다음 결함(독자 미지정)으로 루프.
> 💡 효과 있던 수정만 기록하면 다음에 이 조건부터 바로 써요.

좋은 결과의 기준: (1) 결함이 명사로 특정됨 (2) 한 사이클에 수정 1개 (3) 효과 유무가 O/X로 기록됨.

## 단계별 따라하기

1. **나쁜 답을 구체적으로 진단** — 막연히 '별로다'가 아니라 '너무 길다 / 예시가 없다 / 존댓말이 아니다'처럼 결함을 명사로. 예: '설명이 추상적이고 실제 예시가 없다'(→ 예시 추가).
2. **원인 가설 딱 하나만** — 5가지 중 하나로 분류: (1)맥락 부족 (2)예시 없음 (3)형식 미지정 (4)역할/독자 미지정 (5)분량/톤 미지정. 오늘 고칠 것 하나만.
3. **한 가지만 바꿔 재요청** — 이전 프롬프트는 그대로 두고 고르기로 한 한 줄만 추가/수정. 같은 대화창에서 '방금 답에서 예시를 3개 넣어 다시 써줘'처럼 이어서.
4. **전후 답 비교·기록** — '이 수정이 효과 있었나?'를 O/X로. 효과 있으면 '먹히는 조건'으로 저장, 없으면 버리고 원상복구.
5. **다음 결함으로 루프 반복** — 남은 불만이 없어질 때까지. 매 사이클 결함 1개→수정 1개. 보통 3~4바퀴. 예: 1바퀴 예시 추가 → 2바퀴 독자를 '초등 학부모'로 → 3바퀴 3문장 제한.
6. **완성 프롬프트를 템플릿으로 저장** — 바뀔 부분을 [대괄호]로. 예: '[독자]를 대상으로 [주제]를 3문장으로, 아래 예시 톤 참고해 써줘: [예시]'.

## 흔한 실수 → 교정

- ✗ 답이 마음에 안 들면 통째로 새로 쓴다 → **이전 프롬프트를 남기고 한 줄만 바꿔라.** 통째로 바꾸면 무엇이 효과였는지 영원히 모른다.
- ✗ 한 번에 예시·형식·톤·독자를 다 같이 고친다 → **한 사이클에 결함 1개, 수정 1개만.** 여러 개 동시엔 재현 불가.
- ✗ '더 좋게 해줘', '자연스럽게'처럼 막연 → **불만을 명사로 특정.** '예시 3개 추가', '3문장으로 축소'처럼 측정 가능한 지시.

## 도구

- 🛠 **ChatGPT** (chat.openai.com) — 같은 대화창에서 이어 고치며 맥락 유지.
- 🛠 **Claude** (claude.ai) — 긴 예시 붙여넣고 톤 맞추기.
- 🛠 **메모장/노션** — 먹히는 조건·완성 템플릿 저장.
- 🛠 **Google Docs** — 전후 답 비교 2단 표.

## 실전 프롬프트

### 진단 요청

```text
방금 준 답이 내 기대와 다릅니다. 내가 원한 것은 [원하는 결과]인데 실제 답은 [불만인 점]이었습니다. 이 답이 그렇게 나온 이유를, 내 프롬프트에서 빠졌거나 모호했던 조건 관점에서 3가지만 짚어주세요. 고치라고는 하지 말고 진단만.
```

`프롬프트` `디버깅` `진단`

### 한 가지만 고쳐 재시도

```text
이전 답은 그대로 참고하되, 딱 한 가지만 바꿔서 다시 써주세요. 바꿀 것: [예시 추가 / 형식을 표로 / 독자를 OO로 / 3문장으로 줄이기 중 하나]. 나머지 조건은 절대 바꾸지 마세요.
```

`프롬프트` `디버깅` `변인통제`

### 좋은 예시로 톤 맞추기

```text
아래는 내가 원하는 톤과 형식의 좋은 예시입니다. 이 예시의 문체와 구조를 그대로 따라, [내 주제]에 대해 새로 써주세요. 좋은 예시: [붙여넣기]
```

`프롬프트` `예시` `톤`

### 완성 프롬프트 템플릿화

```text
방금 여러 번 고쳐서 완성한 이 프롬프트를, 다음에 재사용할 수 있도록 바뀔 부분만 [대괄호] 변수로 바꾼 재사용 템플릿으로 정리해주세요.
```

`프롬프트` `템플릿` `재사용`
