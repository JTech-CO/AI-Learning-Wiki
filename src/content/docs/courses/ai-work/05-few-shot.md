_원하는 입력→출력 예시 2~3개를 프롬프트에 넣어 AI가 톤·형식을 똑같이 복제하게 만드는 few-shot 기법을 실습한다. '이렇게 써줘'라고 백 번 설명하기보다 잘 된 예시 2개를 보여주는 게 빠르다._

:::note[학습 목표]
- 원하는 예시 2~3개만 넣어 AI가 톤·형식을 똑같이 복제하도록 만드는 few-shot 프롬프트를 스스로 작성한다
- '입력:/출력:' 라벨로 예시와 실제 입력의 경계를 명확히 긋는다
- 결과가 어긋날 때 지시문을 늘리는 대신 예시 하나를 더 추가해 교정한다
:::

## 핵심 개념

**few-shot(퓨샷)**은 원하는 '입력→출력' 예시를 프롬프트 안에 직접 넣어주는 기법이에요. 규칙을 말로 길게 설명하는 대신 **완성된 결과물 샘플**을 보여주면 AI가 그 패턴을 그대로 흉내 냅니다. 예시 0개면 zero-shot, 1개면 one-shot, 2~3개면 few-shot이에요.

신입에게 "이 서류들처럼 만들어줘"라며 완성본 몇 장을 건네는 것과 같아요. 그러면 톤·길이·형식·말투가 놀랍도록 일관되게 고정됩니다. 한 가지만 기억하세요 — **예시의 품질이 곧 결과의 품질**. 대충 만든 예시를 넣으면 대충 나와요.

### 왜 이게 될까?

AI는 수억 개의 글을 보며 '패턴을 흉내 내는 법'을 배웠어요. 그래서 말로 규칙을 설명하는 것보다 **완성된 예시 2~3개를 보여주는 게 그 패턴(톤·길이·형식)을 훨씬 정확히 복제**하게 만듭니다. '좋은 예시'만 만들어 두면 나머지 반복 작업은 AI가 대신 해줘요.

## 👀 따라하기 예시 — 고객센터 사과 답변

**① 입력→출력 쌍 2개를 손으로 완성**
- 예시1) 입력 '배송이 3일이나 늦었어요' → 출력 '늦어져 정말 죄송합니다. 오늘 중 우선 발송해 드리겠습니다. 불편을 드린 점 다시 한번 사과드립니다.'
- 예시2) 입력 '상품이 파손된 채로 왔어요' → 출력(같은 3문장, 사과→해결책→재사과)
> 💡 이 예시가 곧 '교과서'예요. 두 예시의 문장 개수·순서를 똑같이 맞춘 게 핵심.

**② 지시문+예시+새 입력을 라벨로 조립**
"다음 예시처럼 정중한 3문장 답변… 입력:.../출력:... 입력:.../출력:... 입력: 결제가 두 번 됐어요 출력:"
> 💡 '입력:/출력:' 라벨로 경계를 긋고, 맨 끝은 '출력:'만 비워 AI가 이어 채우게 하세요.

**③ 실행**
'결제가 두 번 되었다니 정말 죄송합니다. 확인 즉시 초과 결제분을 환불해 드리겠습니다. 불편을 드려 다시 한번 사과드립니다.'
> 💡 새 입력인데 앞 두 예시와 문장 수·어조·구조가 똑같아요 — few-shot의 아하 포인트. 말이 아니라 예시가 규칙이에요.

**④ 어긋나면 설명 대신 예시 하나 더 추가**
너무 길게 썼다면 '짧고 완벽한 예시'를 세 번째로 추가 → 길이가 맞춰집니다.
> 💡 지시문을 늘리는 건 비효율. 틀리는 지점을 보여주는 예시 1개가 설명 열 줄보다 강력해요.

좋은 결과의 기준: (1) 모든 예시가 같은 형식(문장 수·순서) 유지 (2) 새 입력의 출력이 예시들과 톤·길이 일치 (3) 예시와 실제 입력 경계가 라벨로 명확.

## 단계별 따라하기

1. **고정하고 싶은 결과물 정하기** — '입력'과 '출력'이 명확히 나뉘는 반복 작업. 예) 고객 문의 → 정중한 3문장 답변.
2. **잘 된 예시 2~3개 직접 만들기** — 톤·길이·형식을 원하는 대로 정성껏. 예시끼리 형식 통일.
3. **예시를 프롬프트로 조립** — '다음 예시처럼 작성해줘' + 예시 2~3개 + 마지막에 진짜 새 입력. '입력:/출력:' 라벨로 구분.
4. **AI에 붙여넣고 실행** — 출력이 예시들의 톤·형식과 얼마나 닮았는지 비교.
5. **어긋나면 예시로 교정** — 지시문을 늘리지 말고 '가장 이상적인 정답' 예시를 하나 더. 자꾸 틀리는 부분을 보여주는 예시로.
6. **재사용 템플릿으로 저장** — 실제 입력 부분만 `[placeholder]`로. 다음엔 갈아끼우기만.

## 흔한 실수 → 교정

- ✗ 예시를 대충·오타·형식 불일치로 넣는다 → **AI는 예시를 '정답'으로 믿고 복제해요. 예시 자체를 최고 품질로 다듬고 형식(라벨·줄바꿈·길이)을 통일한다.**
- ✗ 결과가 별로면 지시문 설명만 계속 늘린다 → **말 대신 '이상적 정답' 예시를 하나 더.** 자꾸 틀리는 지점을 보여주는 예시가 지시문 열 줄보다 강력.
- ✗ 예시와 실제 입력 경계가 흐려 예시까지 다시 답한다 → **'입력:/출력:' 라벨로 구분하고, 마지막은 '출력:'만 비워 둔다.**

## 실전 프롬프트

### 만능 few-shot 뼈대

```text
아래 예시들과 똑같은 톤과 형식으로 결과를 만들어줘. 설명 없이 출력만.
입력: [예시1 입력]
출력: [예시1 결과]
입력: [예시2 입력]
출력: [예시2 결과]
입력: [진짜 새 입력]
출력:
```

> 확인된 작성 예시 없음

`프롬프트` `few-shot` `만능`

### 고객 답변 톤 복제

```text
너는 우리 브랜드 CS 담당자야. 아래 예시처럼 '사과 → 해결책 → 재사과' 3문장, 존댓말, 이모지 없이.
문의: 배송이 너무 늦어요
답변: 늦어져 정말 죄송합니다. 오늘 중 우선 발송해 드리겠습니다. 불편을 드려 다시 한번 사과드립니다.
문의: [실제 문의]
답변:
```

> 확인된 작성 예시 없음

`프롬프트` `few-shot` `고객답변`

### 제목·카피 스타일 고정

```text
아래 예시들의 말투와 길이를 그대로 따라, 같은 스타일의 [SNS 게시글 제목]을 5개.
예시1: [제목1]
예시2: [제목2]
예시3: [제목3]
주제: [이번 주제]
```

> 확인된 작성 예시 없음

`프롬프트` `few-shot` `카피`

### 데이터→정해진 형식 변환

```text
아래 예시처럼 입력 정보를 정해진 JSON으로. 키 이름을 예시와 100% 똑같이.
입력: 홍길동, 서울, 30대
출력: {"name":"홍길동","city":"서울","age_group":"30s"}
입력: [새 정보]
출력:
```

> 확인된 작성 예시 없음

`프롬프트` `few-shot` `형식변환`
