title: "추론·서빙·최적화"

---

학습된 모델이 출력을 생성하고 서비스되는 방식 분야의 검토 완료 백과 문서입니다.

- [가중치 전용 양자화](/wiki/weight-only-quantization/) — 가중치 전용 양자화는 모델 가중치만 낮은 비트로 저장·계산하고 활성값은 상대적으로 높은 정밀도로 유지하는 방식이다.
- [그리디 디코딩](/wiki/greedy-decoding/) — 매 단계에서 확률이 가장 높은 토큰을 선택하는 결정적 생성 방식이다.
- [길이 페널티](/wiki/length-penalty/) — 길이 페널티는 후보 시퀀스 점수를 길이에 따라 보정해 빔 탐색이 지나치게 짧거나 긴 출력을 선호하지 않게 하는 규칙이다.
- [다양성 빔 탐색](/wiki/diverse-beam-search/) — 다양성 빔 탐색은 빔을 여러 그룹으로 나누고 앞선 그룹과 유사한 후보에 패널티를 주어 서로 다른 시퀀스를 찾는 방법이다.
- [다중 모델 서빙](/wiki/multi-model-serving/) — 다중 모델 서빙은 하나의 서빙 플랫폼이나 자원 풀에서 여러 모델과 버전을 동시에 운영하는 방식이다.
- [다항 표본추출](/wiki/multinomial-sampling/) — 각 토큰의 확률을 범주형 분포로 보고 그 분포에서 다음 토큰 하나를 무작위로 추출하는 생성 방법이다.
- [대조 탐색](/wiki/contrastive-search/) — 대조 탐색은 높은 언어 모델 확률과 이전 은닉 표현에 대한 낮은 퇴화를 함께 고려해 다음 토큰을 선택하는 디코딩 방법이다.
- [동적 배칭](/wiki/dynamic-batching/) — 동적 배칭은 도착 시간이 다른 추론 요청을 짧은 대기 창에서 묶어 실행 시점마다 배치 크기를 구성하는 서빙 방식이다.
- [디코드 단계](/wiki/decode-phase/) — 디코드 단계는 이전 출력과 키·값 캐시를 사용해 다음 토큰을 한 단계씩 생성하는 자기회귀 추론 단계다.
- [로짓](/wiki/logit/) — 확률로 정규화하기 전 모델이 각 클래스나 토큰 후보에 내놓는 실수 점수이며, 이항 문제에서는 로그 오즈로 해석된다.
- [모델 게이트웨이](/wiki/model-gateway/) — 모델 게이트웨이는 여러 모델 제공자와 내부 모델 앞에서 공통 인증, 라우팅, 정책과 관측 기능을 제공하는 진입 계층이다.
- [모델 복제본](/wiki/model-replica/) — 모델 복제본은 같은 모델 버전과 설정을 독립 프로세스나 장치에 적재한 추론 서비스 인스턴스다.
- [모델 서빙](/wiki/model-serving/) — 모델 서빙은 학습된 모델을 요청 가능한 서비스로 배치해 입력 전처리, 추론, 출력 후처리와 운영 관측을 제공하는 체계다.
- [반복 페널티](/wiki/repetition-penalty/) — 반복 페널티는 이미 생성된 토큰의 다음 단계 점수를 조정해 동일 표현의 과도한 반복을 줄이는 디코딩 제어다.
- [배치 추론](/wiki/batch-inference/) — 배치 추론은 대량의 저장된 입력을 묶어 일정이나 작업 단위로 처리하고 결과를 파일·테이블에 기록하는 방식이다.
- [배칭](/wiki/batching/) — 여러 추론 요청을 묶어 하드웨어 사용률과 처리량을 높이는 기법이다.
- [빈도 페널티](/wiki/frequency-penalty/) — 빈도 페널티는 지금까지 등장한 횟수에 비례해 해당 토큰의 로짓을 낮추는 생성 제어 방식이다.
- [빔 탐색](/wiki/beam-search/) — 여러 후보 시퀀스를 동시에 유지하며 전체 점수가 높은 출력을 찾는 탐색 방법이다.
- [생성 온도](/wiki/temperature/) — 생성 시 로짓을 나누어 토큰 확률분포의 집중도를 조절하고 출력의 반복성과 다양성 사이의 균형을 바꾸는 디코딩 매개변수다.
- [서버리스 추론](/wiki/serverless-inference/) — 서버리스 추론은 사용자가 서버를 상시 관리하지 않고 요청이나 작업량에 따라 자동 할당되는 실행 환경에서 모델을 제공하는 방식이다.
- [소프트맥스](/wiki/softmax/) — 여러 실수 점수를 지수화하고 합으로 나눠 합이 1인 비율 벡터로 바꾸는 함수다.
- [수락 제어](/wiki/admission-control/) — 수락 제어는 시스템 용량과 서비스 목표를 지키기 위해 새 요청의 실행 허용 여부를 결정하는 메커니즘이다.
- [스트리밍 생성](/wiki/streaming-generation/) — 스트리밍 생성은 모델이 전체 응답을 완성하기 전에 생성된 토큰이나 조각을 순차적으로 클라이언트에 전달하는 방식이다.
- [엣지 추론](/wiki/edge-inference/) — 엣지 추론은 센서·모바일·현장 장치처럼 데이터 생성 지점 가까이에서 모델 예측을 수행하는 방식이다.
- [연속 배칭](/wiki/continuous-batching/) — 연속 배칭은 실행 중인 추론 배치에 완료된 요청을 제거하고 새 요청을 단계별로 투입해 장치 활용률을 높이는 스케줄링 방식이다.
- [온라인 추론](/wiki/online-inference/) — 온라인 추론은 사용자나 시스템의 개별 요청에 대해 짧은 지연 시간 안에 즉시 예측을 반환하는 처리 방식이다.
- [요청 대기열](/wiki/request-queue/) — 요청 대기열은 즉시 실행할 자원이 없는 추론 요청을 도착 순서와 우선순위 정보와 함께 보관하는 구조다.
- [요청 스케줄러](/wiki/request-scheduler/) — 요청 스케줄러는 동시 추론 요청의 우선순위, 배치 구성과 실행 순서를 결정하는 구성 요소다.
- [전형성 샘플링](/wiki/typical-sampling/) — 현재 분포의 엔트로피에 가까운 정보량을 가진 토큰을 우선 남겨 전형적인 확률 영역에서 표본을 추출하는 디코딩 방법이다.
- [정적 배칭](/wiki/static-batching/) — 정적 배칭은 미리 정한 개수나 고정된 입력 묶음을 하나의 텐서로 구성해 함께 추론하는 방식이다.
- [제약 디코딩](/wiki/constrained-decoding/) — 제약 디코딩은 문법, 스키마, 어휘 집합이나 필수 구문을 만족하는 토큰만 다음 후보로 허용하는 생성 방법이다.
- [존재 페널티](/wiki/presence-penalty/) — 존재 페널티는 토큰이 한 번이라도 등장했는지를 기준으로 고정된 패널티를 적용하는 생성 제어 방식이다.
- [중지 시퀀스](/wiki/stop-sequence/) — 중지 시퀀스는 생성 결과에서 지정한 토큰 또는 문자열 패턴이 나타나면 디코딩을 종료하도록 하는 조건이다.
- [지연 시간](/wiki/latency/) — 요청을 보낸 뒤 첫 토큰 또는 전체 응답을 받을 때까지 걸리는 시간이다.
- [처리량](/wiki/throughput/) — 단위 시간에 시스템이 처리하거나 생성할 수 있는 요청 또는 토큰 수다.
- [첫 토큰 시간](/wiki/time-to-first-token/) — 첫 토큰 시간은 요청이 서버에 도착한 시점부터 첫 생성 토큰이 사용자에게 전달될 때까지의 지연 시간이다.
- [청크 프리필](/wiki/chunked-prefill/) — 청크 프리필은 긴 입력 프롬프트의 사전 계산을 여러 토큰 구간으로 나누어 디코딩 요청과 번갈아 실행하는 스케줄링 기법이다.
- [초안 모델](/wiki/draft-model/) — 초안 모델은 추측 디코딩에서 목표 모델보다 빠르게 다음 토큰 후보 묶음을 제안하는 보조 모델이다.
- [추론](/wiki/inference/) — 학습된 모델이 새 입력을 받아 예측이나 생성을 수행하는 과정이다.
- [추론 부하 분산](/wiki/inference-load-balancing/) — 추론 부하 분산은 여러 모델 복제본에 요청을 나눠 처리량과 가용성을 유지하는 방법이다.
- [추론 서버](/wiki/inference-server/) — 추론 서버는 학습된 모델을 메모리에 적재하고 네트워크 요청을 받아 예측 결과를 반환하는 실행 서비스다.
- [추론 엔드포인트](/wiki/inference-endpoint/) — 추론 엔드포인트는 특정 모델 또는 모델 집합에 예측 요청을 보낼 수 있도록 공개된 네트워크 주소와 계약이다.
- [추론 자동 확장](/wiki/inference-autoscaling/) — 추론 자동 확장은 요청량과 자원 지표에 따라 모델 복제본 수를 자동으로 늘리거나 줄이는 운영 방식이다.
- [추측 디코딩](/wiki/speculative-decoding/) — 추측 디코딩은 작은 초안 모델이 여러 토큰 후보를 먼저 만들고 큰 목표 모델이 한 번에 검증해 자동회귀 생성 속도를 높이는 기법이다.
- [캐시 오프로딩](/wiki/cache-offloading/) — 캐시 오프로딩은 장치 메모리의 KV나 모델 상태 일부를 호스트 메모리 또는 저장장치로 옮겨 가속기 용량을 확보하는 방식이다.
- [캐시 적중률](/wiki/cache-hit-rate/) — 캐시 적중률은 전체 조회 중 요청한 데이터가 캐시에 있어 원본 계산이나 저장소 접근을 피한 비율이다.
- [캐시 축출](/wiki/cache-eviction/) — 캐시 축출은 제한된 KV 또는 접두사 캐시에서 보존 가치가 낮은 항목을 제거해 새 요청 공간을 확보하는 정책이다.
- [토큰 간 지연 시간](/wiki/inter-token-latency/) — 토큰 간 지연 시간은 스트리밍 응답에서 연속한 출력 토큰 사이에 걸리는 시간이다.
- [토큰 샘플링](/wiki/token-sampling/) — 토큰 샘플링은 다음 토큰 확률분포에서 난수로 토큰을 뽑아 생성 시퀀스를 이어가는 디코딩 방식이다.
- [페이지드 KV 캐시](/wiki/paged-kv-cache/) — 페이지드 KV 캐시는 시퀀스의 어텐션 키·값을 고정 크기 블록으로 나누어 비연속 장치 메모리에 배치하는 관리 방식이다.
- [프롬프트 조회 디코딩](/wiki/prompt-lookup-decoding/) — 프롬프트 조회 디코딩은 입력 문맥에 이미 나타난 토큰 연속열을 초안 후보로 찾아 여러 토큰을 한 번에 검증하는 추론 가속 방식이다.
- [프리픽스 캐싱](/wiki/prefix-caching/) — 프리픽스 캐싱은 여러 요청이 공유하는 프롬프트 접두사의 KV 상태를 저장해 같은 구간의 프리필 계산을 재사용하는 기법이다.
- [프리필 단계](/wiki/prefill-phase/) — 프리필 단계는 입력 토큰 전체를 병렬 처리해 첫 출력 예측과 이후 디코딩에 사용할 키·값 캐시를 만드는 추론 단계다.
- [학습 후 양자화](/wiki/post-training-quantization/) — 학습 후 양자화는 추가 전체 학습 없이 이미 학습된 모델의 가중치나 활성값을 낮은 비트 표현으로 변환하는 기법이다.
- [활성값 양자화](/wiki/activation-quantization/) — 활성값 양자화는 계층 사이에서 생성되는 중간 텐서를 낮은 정밀도 범위로 표현하는 기법이다.
- [FP8 추론](/wiki/fp8-inference/) — FP8 추론은 지수와 가수 비트가 적은 8비트 부동소수 형식을 사용해 가속기 처리량과 메모리 효율을 높이는 방식이다.
- [GGUF 형식](/wiki/gguf-format/) — GGUF는 llama.cpp 계열 런타임에서 모델 텐서와 토크나이저·설정 메타데이터를 함께 저장하는 단일 파일 형식이다.
- [INT4 추론](/wiki/int4-inference/) — INT4 추론은 주로 가중치를 4비트 정수로 압축해 메모리 사용량과 대역폭을 크게 줄이는 모델 실행 방식이다.
- [INT8 추론](/wiki/int8-inference/) — INT8 추론은 모델의 일부 또는 대부분의 행렬 연산을 8비트 정수 표현과 누산기로 수행하는 실행 방식이다.
- [KV 캐시](/wiki/kv-cache/) — 이전 토큰의 어텐션 키와 값을 저장해 자동회귀 생성의 중복 계산을 줄이는 캐시다.
- [KV 캐시 양자화](/wiki/kv-cache-quantization/) — KV 캐시 양자화는 어텐션 키와 값을 더 낮은 비트 표현으로 저장해 생성 중 메모리 사용량을 줄이는 기법이다.
- [Min-p 샘플링](/wiki/min-p-sampling/) — 최고 확률 토큰의 확률에 비례한 최소 임계값보다 낮은 토큰을 제거한 뒤 남은 분포에서 추출하는 디코딩 방법이다.
- [ONNX Runtime](/wiki/onnx-runtime/) — ONNX Runtime은 ONNX 계산 그래프를 여러 하드웨어 실행 공급자에서 최적화하고 실행하는 추론 엔진이다.
- [Top-k 샘플링](/wiki/top-k-sampling/) — 확률이 높은 상위 k개 후보만 남겨 다음 토큰을 선택하는 방법이다.
- [Top-p 샘플링](/wiki/top-p-sampling/) — 누적 확률이 p에 도달하는 최소 후보 집합에서 다음 토큰을 선택하는 방법이다.
