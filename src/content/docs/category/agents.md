---
title: "에이전트·자동화·MCP"
description: "모델이 도구를 사용해 여러 단계를 수행하는 구조"
---

모델이 도구를 사용해 여러 단계를 수행하는 구조 분야의 검토 완료 백과 문서입니다.

- [감독 에이전트](/wiki/supervisor-agent/) — 감독 에이전트는 목표를 하위 작업으로 나누고 작업 에이전트의 배정·진행·결과를 통제하는 상위 역할이다.
- [감지-사고-행동 순환](/wiki/sense-think-act-cycle/) — 센서 입력을 수집하고 해석한 뒤 행동을 선택해 환경에 적용하는 세 단계 제어 모형이다.
- [검증 에이전트](/wiki/verifier-agent/) — 검증 에이전트는 주장이나 작업 결과가 명세, 외부 근거 또는 실행 가능한 검사와 일치하는지 확인하는 에이전트다.
- [계층적 과제 네트워크](/wiki/hierarchical-task-network/) — 계층적 작업 네트워크는 복잡한 목표를 미리 정의한 방법 규칙에 따라 더 작은 작업으로 반복 분해하는 계획 표현이다.
- [계획](/wiki/planning/) — 목표를 하위 단계와 실행 순서로 분해하고 필요에 따라 계획을 수정하는 과정이다.
- [계획 검증](/wiki/plan-verification/) — 계획 검증은 생성된 행동 순서가 전제조건·안전 제약·목표 조건을 만족하는지 실행 전에 확인하는 과정이다.
- [계획 후 실행](/wiki/plan-and-execute/) — 계획 후 실행은 목표를 먼저 여러 하위 과제로 분해한 다음 실행기가 각 단계를 수행하고 결과에 따라 계획을 수정하는 에이전트 방식이다.
- [계획자 에이전트](/wiki/planner-agent/) — 계획자 에이전트는 목표를 실행 가능한 단계로 분해하고 선후 관계, 필요한 정보와 도구를 정하는 에이전트다.
- [공유 에이전트 메모리](/wiki/shared-agent-memory/) — 공유 에이전트 메모리는 여러 에이전트가 공동으로 읽거나 갱신하는 사실, 작업 상태와 경험 저장소다.
- [기억 망각](/wiki/memory-forgetting/) — 기억 망각은 오래되거나 부정확하거나 과제와 무관한 기록의 검색 우선순위를 낮추거나 삭제하는 기억 관리 과정이다.
- [기억 통합](/wiki/memory-consolidation/) — 기억 통합은 여러 일화와 단기 기록에서 반복되는 정보를 추려 더 안정적인 요약·의미 기억·절차로 재구성하는 과정이다.
- [다중 에이전트 갈등 해결](/wiki/multi-agent-conflict-resolution/) — 다중 에이전트 갈등 해결은 에이전트들의 목표, 자원 요구나 결론이 충돌할 때 공동 실행 가능한 결정을 만드는 과정이다.
- [다중 에이전트 토론](/wiki/multi-agent-debate/) — 다중 에이전트 토론은 여러 에이전트가 서로 다른 답이나 근거를 제시하고 반박하면서 결론을 개선하는 협업 추론 방식이다.
- [다중 에이전트 합의](/wiki/multi-agent-consensus/) — 다중 에이전트 합의는 여러 에이전트가 서로 다른 제안이나 믿음에서 출발해 공동으로 채택할 결론을 정하는 절차다.
- [대화 메모리](/wiki/conversation-memory/) — 대화 메모리는 사용자와 에이전트 사이의 발화, 역할, 결정과 미해결 항목을 대화 단위로 유지하는 기억이다.
- [도구 결과 처리](/wiki/tool-result-handling/) — 도구 결과 처리는 외부 호출의 성공 값, 오류, 부분 결과와 부수 효과를 에이전트 상태에 안전하게 반영하는 절차다.
- [도구 권한](/wiki/tool-permission/) — 도구 권한은 에이전트가 특정 도구와 자원에 대해 조회·변경·전송할 수 있는 범위를 제한하는 정책이다.
- [도구 레지스트리](/wiki/tool-registry/) — 도구 레지스트리는 에이전트가 사용할 수 있는 도구의 명세, 버전, 권한과 상태를 검색 가능하게 관리하는 목록이다.
- [도구 발견](/wiki/tool-discovery/) — 도구 발견은 현재 과제를 수행할 수 있는 도구를 레지스트리나 서버에서 찾아 기능과 제약을 파악하는 단계다.
- [도구 부작용](/wiki/tool-side-effect/) — 도구 부작용은 도구 호출이 반환값 이외에 파일·계정·메시지·금전·외부 시스템 상태에 남기는 변화다.
- [도구 선택](/wiki/tool-selection/) — 도구 선택은 여러 도구 후보 중 목표, 입력 형식, 비용, 신뢰도와 권한 조건에 맞는 실행 수단을 고르는 과정이다.
- [도구 실행](/wiki/tool-invocation/) — 도구 실행은 선택된 도구의 입력 스키마에 맞춰 인수를 구성하고 실제 호출을 경계 계층에 전달하는 단계다.
- [라우터 에이전트](/wiki/router-agent/) — 라우터 에이전트는 요청의 종류와 위험, 필요한 능력을 판별해 적절한 모델, 도구 또는 전문 에이전트로 전달한다.
- [멀티 에이전트 시스템](/wiki/multi-agent-system/) — 역할이 다른 여러 에이전트가 협력하거나 경쟁하며 문제를 해결하는 시스템이다.
- [모델 기반 계획](/wiki/model-based-planning/) — 모델 기반 계획은 환경의 상태 전이와 보상 또는 비용을 예측하는 모델을 이용해 행동 결과를 미리 비교하는 방식이다.
- [모델 컨텍스트 프로토콜](/wiki/mcp/) — AI 애플리케이션이 외부 도구와 데이터 소스를 표준 방식으로 연결하도록 정의한 프로토콜이다.
- [벡터 메모리](/wiki/vector-memory/) — 벡터 메모리는 텍스트나 관찰을 임베딩 벡터와 메타데이터로 저장해 의미적 유사성으로 회상하는 에이전트 기억 구현이다.
- [브라우저 사용 에이전트](/wiki/browser-use-agent/) — 브라우저 사용 에이전트는 웹 페이지의 시각 정보와 문서 구조를 해석해 탐색·입력·클릭·다운로드 같은 브라우저 행동을 수행하는 에이전트다.
- [블랙보드 아키텍처](/wiki/blackboard-architecture/) — 블랙보드 아키텍처는 여러 전문 모듈이 공용 작업 공간의 부분 결과를 읽고 쓰며 문제를 해결하는 협업 구조다.
- [비평 에이전트](/wiki/critic-agent/) — 비평 에이전트는 다른 에이전트가 만든 계획이나 산출물의 결함을 기준에 따라 찾아 수정 제안을 내는 역할이다.
- [빔 계획](/wiki/beam-planning/) — 빔 계획은 각 단계에서 점수가 높은 제한된 수의 부분 계획만 유지해 탐색 폭을 제어하는 계획 기법이다.
- [상태 관리](/wiki/state-management/) — 여러 단계에 걸쳐 입력·중간 결과·진행 상황을 일관되게 유지하는 방법이다.
- [생각의 그래프](/wiki/graph-of-thoughts/) — 생각의 그래프는 중간 추론 단위를 노드로, 변환·의존·통합 관계를 간선으로 나타내는 일반화된 추론 구조다.
- [생각의 나무](/wiki/tree-of-thoughts/) — 생각의 나무는 언어 모델이 여러 중간 추론 후보를 가지로 생성하고 평가하면서 유망한 경로를 탐색하는 추론 방법이다.
- [성찰 루프](/wiki/reflection-loop/) — 성찰 루프는 에이전트가 직전 시도의 결과와 오류를 검토해 다음 계획이나 답변을 수정하는 반복 제어 구조다.
- [세션 상태](/wiki/session-state/) — 세션 상태는 하나의 상호작용 세션에서 현재 사용자, 메시지 순서, 선택한 도구, 임시 변수와 진행 단계를 나타내는 상태다.
- [에이전트 가드레일](/wiki/agent-guardrail/) — 에이전트 가드레일은 에이전트의 입력·계획·도구 사용·출력에 정책과 권한 경계를 적용해 위험 행동을 예방·탐지·중단하는 통제다.
- [에이전트 간 통신](/wiki/inter-agent-communication/) — 에이전트 간 통신은 에이전트들이 의도, 관측, 요청과 결과를 정해진 메시지 형식으로 교환하는 메커니즘이다.
- [에이전트 계획 품질](/wiki/agent-plan-quality/) — 에이전트 계획 품질은 목표를 달성하기 위한 단계가 타당한 순서·의존성·완료 조건·비용·위험을 얼마나 잘 표현하는지 나타내는 평가 대상이다.
- [에이전트 과제 분해](/wiki/agent-task-decomposition/) — 복잡한 에이전트 과제를 실행 가능하고 검증 가능한 하위 과제로 나누고 의존 관계를 정하는 과정이다.
- [에이전트 과제 성공률](/wiki/agent-task-success/) — 에이전트 과제 성공은 주어진 목표의 필수 완료 조건과 제약을 에이전트 실행 결과가 모두 만족한 상태다.
- [에이전트 궤적 평가](/wiki/agent-trajectory-evaluation/) — 에이전트 궤적 평가는 최종 답뿐 아니라 관측·추론·도구 호출·상태 전환으로 이어지는 실행 경로의 품질을 판정하는 방법이다.
- [에이전트 단기 기억](/wiki/short-term-agent-memory/) — 에이전트 단기 기억은 한 세션이나 인접한 작업 단계 사이에서 최근 대화와 행동 결과를 유지하는 임시 기억 계층이다.
- [에이전트 도구](/wiki/agent-tool/) — 에이전트 도구는 모델이 외부 정보 조회나 상태 변경을 수행할 수 있도록 명세된 함수·API·실행 환경이다.
- [에이전트 도구 정확도](/wiki/agent-tool-accuracy/) — 에이전트 도구 정확도는 적절한 도구 선택, 인수 구성, 호출 시점과 결과 해석이 기준에 맞는 정도다.
- [에이전트 런타임](/wiki/agent-runtime/) — 에이전트 런타임은 모델 호출, 도구 실행, 상태 보존, 오류 복구와 관측 기록을 실제로 수행하는 실행 환경이다.
- [에이전트 루프](/wiki/agent-loop/) — 관찰·추론·행동·결과 반영을 목표 달성까지 반복하는 실행 구조다.
- [에이전트 메모리](/wiki/agent-memory/) — 에이전트가 이전 상호작용과 작업 상태를 저장하고 이후 판단에 사용하는 구조다.
- [에이전트 목표](/wiki/agent-goal/) — 에이전트가 도달하거나 유지하려는 바람직한 상태를 성공 조건과 제약으로 표현한 것이다.
- [에이전트 벤치마크](/wiki/agent-benchmark/) — 에이전트 벤치마크는 계획·도구 사용·상태 관리가 필요한 과제와 성공 판정 환경을 묶어 에이전트 성능을 비교하는 평가 체계다.
- [에이전트 보안](/wiki/agent-security/) — 에이전트 보안은 자율 실행 시스템의 모델·메모리·도구·자격증명·통신과 공급망을 공격과 오용에서 보호하는 활동이다.
- [에이전트 샌드박스](/wiki/agent-sandbox/) — 에이전트 샌드박스는 에이전트가 실행하는 코드와 도구의 파일·네트워크·프로세스 접근을 격리하는 환경이다.
- [에이전트 성찰](/wiki/agent-reflection/) — 에이전트 성찰은 직전 추론 과정이나 결과를 평가해 오류, 누락과 더 나은 다음 행동을 찾아내는 절차다.
- [에이전트 숙고](/wiki/agent-deliberation/) — 에이전트 숙고는 행동을 즉시 실행하지 않고 대안·근거·위험을 비교해 선택을 정교화하는 의사결정 단계다.
- [에이전트 스웜](/wiki/agent-swarm/) — 에이전트 스웜은 다수의 비교적 자율적인 에이전트가 지역 정보와 단순한 상호작용 규칙으로 공동 문제를 푸는 구성이다.
- [에이전트 스크래치패드](/wiki/agent-scratchpad/) — 에이전트 스크래치패드는 한 과제를 푸는 동안 임시 계산, 도구 결과, 다음 행동 후보를 유지하는 작업 공간이다.
- [에이전트 실행기](/wiki/agent-executor/) — 에이전트 실행기는 계획에 적힌 작업을 실제 모델 호출, 도구 호출 또는 외부 작업으로 변환하는 구성 요소다.
- [에이전트 역할](/wiki/agent-role/) — 에이전트 역할은 다중 에이전트 시스템에서 한 에이전트가 맡을 책임, 사용 가능한 도구와 의사결정 범위를 정의한 규약이다.
- [에이전트 위임](/wiki/agent-delegation/) — 에이전트 위임은 상위 에이전트가 목표의 일부와 필요한 권한·제약을 다른 에이전트에게 맡기는 작업 분배 방식이다.
- [에이전트 의미 기억](/wiki/semantic-agent-memory/) — 에이전트 의미 기억은 특정 사건의 시간 순서와 분리해 일반화된 사실·개념·관계를 장기 보존하는 기억 계층이다.
- [에이전트 일화 기억](/wiki/episodic-agent-memory/) — 에이전트 일화 기억은 특정 과제에서 무엇을 관찰하고 어떤 행동을 했으며 결과가 어땠는지를 사건 단위로 보존한 기억이다.
- [에이전트 자기 교정](/wiki/agent-self-correction/) — 에이전트 자기 교정은 에이전트가 자신의 중간 추론이나 실행 결과를 기준·피드백과 대조해 오류를 찾고 다음 행동을 수정하는 절차다.
- [에이전트 자율성 수준](/wiki/agent-autonomy-level/) — 에이전트 자율성 수준은 사람이 매 단계 승인하는 방식부터 제한된 범위 안에서 스스로 계획하고 실행하는 방식까지의 권한 정도다.
- [에이전트 장기 기억](/wiki/long-term-agent-memory/) — 에이전트 장기 기억은 여러 세션에 걸쳐 재사용할 사실·선호·절차·과거 경험을 지속적으로 저장하는 기억 계층이다.
- [에이전트 재계획](/wiki/agent-replanning/) — 에이전트 재계획은 실행 중 관측이나 제약이 바뀌었을 때 남은 계획을 수정하거나 새로 만드는 복구 절차다.
- [에이전트 절차 기억](/wiki/procedural-agent-memory/) — 에이전트 절차 기억은 과제를 수행하는 방법, 도구 사용 순서, 성공·실패 조건을 재사용 가능한 절차로 보존한 기억이다.
- [에이전트 제어 루프](/wiki/agent-control-loop/) — 에이전트 제어 루프는 관찰, 상태 갱신, 계획, 행동, 결과 평가를 반복해 목표를 향해 진행하는 실행 순환이다.
- [에이전트 조정](/wiki/agent-coordination/) — 에이전트 조정은 여러 에이전트의 작업 순서, 자원 사용과 상호 의존성을 맞춰 충돌과 중복을 줄이는 제어 활동이다.
- [에이전트 종료 조건](/wiki/agent-termination-condition/) — 에이전트 종료 조건은 목표 달성, 실패 확정, 예산 소진 또는 사람 개입 필요성을 근거로 실행 루프를 멈추는 판정 규칙이다.
- [에이전트 추적 평가](/wiki/agent-trace-evaluation/) — 에이전트 추적 평가는 관측·계획·도구 호출·결과·상태 전환으로 이어지는 실행 기록을 단계별로 분석하는 평가 방법이다.
- [에이전트 하네스](/wiki/agent-harness/) — 에이전트 하네스는 언어 모델 주위에 프롬프트, 도구, 메모리, 정책과 평가기를 결합한 실행 골격이다.
- [에이전트 핸드오프](/wiki/agent-handoff/) — 에이전트 핸드오프는 한 에이전트가 진행 중인 작업의 책임과 필요한 문맥을 다른 에이전트에게 넘기는 전환 절차다.
- [에이전트 협업](/wiki/agent-collaboration/) — 에이전트 협업은 서로 다른 능력이나 정보를 가진 에이전트들이 공동 목표를 위해 산출물과 피드백을 주고받는 과정이다.
- [오케스트레이터 에이전트](/wiki/orchestrator-agent/) — 오케스트레이터 에이전트는 여러 작업자와 도구 사이의 의존 관계, 순서, 병렬 실행과 결과 통합을 조정한다.
- [워크플로 오케스트레이션](/wiki/workflow-orchestration/) — 여러 작업과 도구 호출의 의존 관계·상태·실패 처리를 정의하고 실행 순서를 조정하는 운영 방식이다.
- [웹훅](/wiki/webhook/) — 특정 이벤트가 발생했을 때 다른 시스템의 URL로 데이터를 보내는 자동 통지 방식이다.
- [인간 승인 게이트](/wiki/human-approval-gate/) — 인간 승인 게이트는 고위험·비가역 행동을 실행하기 전에 권한 있는 사람이 요청 내용을 검토하고 허용 여부를 결정하는 통제 지점이다.
- [인간 참여형 제어](/wiki/human-in-the-loop/) — 중요한 판단이나 실행 단계에 사람의 검토·승인·교정을 포함하는 설계다.
- [인식-계획-행동 순환](/wiki/perceive-plan-act-cycle/) — 환경을 관찰해 현재 상태를 구성하고, 목표에 맞는 계획을 세운 뒤 행동을 실행하며 결과를 다음 관찰에 반영하는 에이전트 제어 순환이다.
- [작업 기억](/wiki/working-memory/) — 작업 기억은 현재 과제를 해결하는 동안 필요한 목표·중간 결과·제약을 짧은 범위에서 유지하는 활성 정보 공간이다.
- [작업자 에이전트](/wiki/worker-agent/) — 작업자 에이전트는 명확한 입력과 완료 조건을 가진 제한된 하위 작업을 수행하는 역할형 에이전트다.
- [지속성 에이전트 상태](/wiki/persistent-agent-state/) — 지속성 에이전트 상태는 프로세스나 세션이 종료된 뒤에도 목표, 작업 진행, 승인과 기억을 다시 불러올 수 있게 저장한 상태다.
- [추론-행동 교차 수행](/wiki/reasoning-action-interleaving/) — 추론과 행동의 교차 수행은 내부 판단과 외부 도구 실행을 번갈아 수행하며 다음 결정을 관측에 맞춰 갱신하는 에이전트 패턴이다.
- [컴퓨터 사용 에이전트](/wiki/computer-use-agent/) — 컴퓨터 사용 에이전트는 화면을 관찰하고 마우스·키보드·운영체제 기능을 조작해 여러 응용 프로그램에 걸친 과제를 수행하는 에이전트다.
- [코드 실행 도구](/wiki/code-execution-tool/) — 코드 실행 도구는 에이전트가 프로그램 조각을 격리된 실행 환경에서 평가하고 표준 출력·오류·산출물을 돌려받게 하는 도구다.
- [탐색 기반 계획](/wiki/search-based-planning/) — 탐색 기반 계획은 상태를 노드, 행동을 전이로 보고 초기 상태에서 목표 상태까지의 경로를 탐색하는 계획 방식이다.
- [통제 이탈 에이전트](/wiki/runaway-agent/) — 폭주 에이전트는 잘못된 목표·종료 조건·피드백 고리 때문에 불필요하거나 위험한 행동을 반복하며 자원과 권한을 계속 소비하는 실패 상태다.
- [피어투피어 에이전트](/wiki/peer-to-peer-agents/) — 피어투피어 에이전트는 고정된 중앙 감독자 없이 동등한 참여자들이 직접 메시지와 작업을 교환하는 다중 에이전트 구성이다.
- [AI 에이전트](/wiki/ai-agent/) — 목표를 바탕으로 상태를 관찰하고 도구를 선택해 여러 단계의 작업을 수행하는 시스템이다.
- [API 행동 도구](/wiki/api-action-tool/) — API 행동 도구는 원격 서비스의 명세된 엔드포인트를 호출해 정보를 조회하거나 외부 상태를 변경하는 에이전트 도구다.
- [MCP 도구](/wiki/mcp-tools/) — MCP 도구는 모델이 외부 시스템의 계산이나 상태 변경 기능을 호출하도록 서버가 이름·설명·입력 스키마와 함께 공개하는 실행 인터페이스다.
- [MCP 리소스](/wiki/mcp-resources/) — MCP 리소스는 서버가 URI로 식별해 클라이언트에 제공하는 읽기 가능한 데이터와 문맥 객체다.
- [MCP 사용자 정보 요청](/wiki/mcp-elicitation/) — MCP 유도 입력은 서버가 작업 도중 사용자에게 추가 구조화 정보를 요청하는 기능이다.
- [MCP 샘플링](/wiki/mcp-sampling/) — MCP 샘플링은 서버가 호스트의 모델 호출 능력을 요청해 중첩된 언어 모델 생성을 수행하는 기능이다.
- [MCP 서버](/wiki/mcp-server/) — MCP 서버는 표준 프로토콜을 통해 도구, 리소스와 프롬프트 같은 기능을 MCP 클라이언트에 제공하는 프로그램이다.
- [MCP 전송 계층](/wiki/mcp-transport/) — MCP 전송은 JSON-RPC 메시지를 클라이언트와 서버 사이에 전달하는 연결 방식과 프레이밍 규칙이다.
- [MCP 클라이언트](/wiki/mcp-client/) — MCP 클라이언트는 MCP 호스트 안에서 특정 서버와 일대일 세션을 맺고 프로토콜 메시지를 주고받는 구성 요소다.
- [MCP 프롬프트](/wiki/mcp-prompts/) — MCP 프롬프트는 서버가 재사용 가능한 메시지 템플릿과 입력 인수로 공개하는 사용자 선택형 상호작용 구성 요소다.
- [MCP 호스트](/wiki/mcp-host/) — MCP 호스트는 하나 이상의 MCP 클라이언트를 내장해 사용자 애플리케이션과 외부 MCP 서버 사이의 연결·권한·문맥을 관리하는 프로그램이다.
- [ReAct 에이전트](/wiki/react-agent/) — 언어 모델이 추론 메모와 외부 행동, 관찰을 번갈아 생성하며 계획을 수정하고 도구를 사용하는 에이전트 패턴이다.
