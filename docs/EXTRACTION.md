# 콘텐츠 수집(추출) 방식

## 배경 (정찰 결과)

`https://eduverse-ai.app/learn`을 분석한 결과:

- **프레임워크**: Next.js App Router (Turbopack). SPA.
- **`/learn`은 단일 페이지**다. 코스별 하위 라우트(`/learn/ai-intro` 등)는 존재하지 않는다(전부 404). 7개 코스는 이 페이지 안에서 클라이언트가 렌더링한다.
- **초기 번들(15개 청크)에는 실제 커리큘럼이 없다.** UI 셸 + i18n 번역 문자열(ko/en/es/ja/zh) + FAQ 텍스트뿐이다.
- **RSC 페이로드에도 코스 데이터가 없다**(9KB 셸만 반환).
- 따라서 **44~55개 모듈의 본문·프롬프트는 로그인 후 `/api/`(robots.txt 차단 경로)에서 사용자 세션으로 동적 로드**된다. 홈의 진도 표시("0/44 · 0%")가 사용자별 백엔드 상태의 증거다.

**결론: 인증 없이 긁을 수 있는 실제 지식 콘텐츠는 없다.** 아래 세 가지 방식 중 하나가 필요하다.

---

## 방식 A — 운영자 데이터 export (권장) ⭐

운영자에게 이미 허락을 받았으므로, 가장 깨끗하고 완전하고 견고한 길이다.

운영자에게 다음 중 하나를 요청한다:
- 커리큘럼 **DB/JSON export** (코스·모듈·프롬프트 전체)
- 또는 읽기 전용 **내부 API 접근**(엔드포인트 + 토큰)

**장점**: 완전한 데이터(누락 없음), 다국어 전부 포함, 인증/레이트리밋/약관 마찰 없음, 사이트 UI 변경에 영향받지 않음. `scripts/import.mjs`가 이 export를 바로 [`content-model/schema.module.json`](../content-model/schema.module.json) 형태로 정규화한다.
**필요한 것**: 운영자가 export 파일 하나를 넘겨주면 됨. 형식은 무엇이든(그쪽 DB 스키마대로) 가능 — 매핑은 이쪽에서 작성한다.

## 방식 B — 인증 크롤 (세션 기반)

운영자 export가 어렵고, 당신이 **정상 학습 계정**을 가진 경우.

1. 브라우저(claude-in-chrome 확장 연결 + 로그인)로 `/learn`에 접속.
2. 로그인 상태에서 실제 호출되는 `/api/...` 엔드포인트와 응답을 네트워크 탭에서 관찰(방식 C의 기반).
3. 각 코스·모듈을 순회하며 렌더된 본문을 추출하거나, 관찰된 API를 세션 토큰으로 재생(replay)해 JSON으로 수집.

**장점**: 운영자의 추가 협조 없이 계정만으로 가능.
**단점**: 느리고, 사이트 UI/구조 변경에 취약, 레이트리밋 준수 필요. **운영자 사전 동의 범위 내에서만** 수행.
**필요한 것**: Chrome 확장 연결 + 로그인된 세션. (이 세션에서 실시간 브라우저 제어가 가능해야 함.)

## 방식 C — API 캡처 후 재생 (B의 효율화)

방식 B로 엔드포인트를 한 번 파악하면, 세션 토큰으로 API를 직접 호출해 전체 콘텐츠를 구조화된 JSON으로 빠르게 수집. DOM 스크래핑보다 정확·고속. 관찰된 엔드포인트는 `scripts/crawl/`에 문서화한다.

---

## 어떤 방식이든 공통 파이프라인

```
[원본 데이터] → scripts/import.mjs → content-model 스키마(JSON) → scripts/build-pages.mjs → 위키(MDX) → 정적 사이트
```

수집 방식이 A/B/C 중 무엇이든, 정규 스키마([schema.module.json](../content-model/schema.module.json)) 이후 단계는 완전히 동일하다. 그래서 스키마를 먼저 확정했다.
