# AI Learning Wiki 백과사전형 개편 기획

기준일: 2026-07-12  
상태: 구현 전 기획 확정안

## 1. 개편 목표

AI Learning Wiki를 코스 중심의 학습 가이드에서 **검색과 하이퍼링크를 중심으로 자유롭게 탐색할 수 있는 AI·LLM 백과사전**으로 개편한다.

개편 후 서비스는 두 사용 방식을 동등하게 제공한다.

1. **백과사전 방식:** 코스를 선택하지 않고 검색, 분류, 문서 내부 링크, 관련 문서, 역링크를 따라 자유롭게 열람한다.
2. **학습 코스 방식:** 목표별 코스를 선택하면 백과 문서와 실습 가이드를 권장 순서로 묶어 보여주고 진도를 기록한다.

코스는 콘텐츠를 소유하는 상위 폴더가 아니라, 여러 백과 문서와 실습 문서를 순서대로 참조하는 **학습 경로**가 된다. 하나의 백과 문서는 여러 코스에서 재사용할 수 있다.

## 2. 현재 상태와 문제 정의

현재 데이터는 다음과 같다.

| 콘텐츠 | 수량 | 실제 성격 |
|---|---:|---|
| 학습 모듈 | 305 | 따라하기·미션·프롬프트 중심의 실습 가이드 |
| 개념 페이지 | 537 | 독립 설명이 아니라 관련 모듈을 나열하는 자동 역링크 페이지 |
| 프롬프트 | 1,173 | 모듈에 포함된 실전 템플릿 |

537개 개념 중 391개는 단 하나의 모듈에서만 사용된다. 현재 개념 페이지는 정의, 원리, 역사, 관련 용어, 출처를 갖춘 백과 문서가 아니므로 문서 수에 포함해 “537개 백과 문서”라고 표현하지 않는다.

현재 UI가 가이드처럼 보이는 원인은 다음과 같다.

- 첫 화면의 중심이 검색과 문서 탐색이 아니라 프로필 입력과 추천 카드다.
- 모든 콘텐츠가 코스와 학습 순서를 중심으로 분류된다.
- 개념 페이지가 독립 문서가 아니라 모듈 역링크 목록이다.
- 둥근 카드, 그림자, 글로우, 배지, 큰 CTA가 정보 구조보다 먼저 보인다.
- 문서 간 의미 관계가 명시적 링크가 아니라 태그와 코스 소속에 머문다.
- 백과 문서, 실습 가이드, 프롬프트가 URL과 화면 구조상 충분히 구분되지 않는다.

## 3. 제품 원칙

### 3.1 내용 우선

- 흰 배경, 얇은 회색 선, 파란 텍스트 링크를 기본으로 한다.
- 그라디언트, 글로우, 그림자, 장식 애니메이션, 모달 중심 탐색을 사용하지 않는다.
- 정보 의미가 없는 SVG 아이콘을 제거한다. 검색, 외부 링크 등 의미가 꼭 필요한 경우에도 텍스트를 우선한다.
- 호버는 링크 밑줄이나 배경색의 미세한 변화만 허용한다. 요소가 움직이거나 떠오르지 않는다.
- 둥근 카드 대신 문단, 목록, 표, 구획선, 제목 계층으로 정보를 조직한다.

### 3.2 백과와 학습 경로의 분리

- 백과 문서는 그 자체로 완결된 설명이어야 한다.
- 실습 가이드는 수행 절차, 미션, 프롬프트, 평가 기준을 담당한다.
- 코스는 백과 문서와 실습 가이드를 참조해 순서를 제공한다.
- 프롬프트는 독립 검색이 가능한 자료형이지만 관련 백과 문서와 실습 가이드로 연결된다.

### 3.3 링크가 기본 탐색 수단

- 본문에서 처음 등장하는 핵심 용어를 해당 백과 문서에 연결한다.
- 각 문서는 선행 개념, 관련 문서, 함께 보는 실습, 이 문서를 포함하는 코스, 역링크를 제공한다.
- 검색 결과는 정확한 문서명과 별칭을 우선하고, 그다음 본문과 태그를 검색한다.
- 코스를 선택하지 않아도 모든 백과 문서와 프롬프트에 접근할 수 있다.

## 4. 개편 후 콘텐츠 구조

### 4.1 백과 문서(Article)

안정 URL: `/wiki/{slug}/`

백과 문서의 표준 구성은 다음과 같다.

1. 문서명, 영문명, 약어, 별칭
2. 한 문단 정의
3. 개요
4. 배경 또는 역사
5. 작동 원리
6. 핵심 구성 요소 또는 파라미터
7. 예시
8. 장점과 한계
9. 관련 개념
10. 함께 보는 실습과 코스
11. 참고 문헌과 공식 출처
12. 최근 검토일과 문서 상태

주제에 맞지 않는 절은 생략할 수 있지만, 정의·관련 개념·출처는 필수다.

### 4.2 실습 가이드(Guide)

안정 URL: `/guide/{course-or-domain}/{slug}/`

현재 305개 모듈의 주된 이관 대상이다. 학습 목표, 따라하기, 프롬프트, 미션, 평가 기준을 유지한다. 백과 설명을 장황하게 반복하지 않고 핵심 개념 문서로 연결한다.

### 4.3 코스(Path)

안정 URL: `/course/{id}/`

코스는 문서 자체가 아니라 다음 항목을 참조하는 순서 목록이다.

- 백과 문서
- 실습 가이드
- 프롬프트 묶음
- 점검 또는 미션

각 단계에는 선택 이유, 예상 시간, 선행 단계, 필수·선택 여부를 기록한다. 동일한 백과 문서를 여러 코스에서 사용할 수 있다.

### 4.4 프롬프트(Prompt)

안정 URL: `/prompt/{id}/`

템플릿, 변수, 사용 조건, 작성 예시, 예상 출력, 주의사항을 독립적으로 검색한다. 관련 백과 문서와 가이드에 양방향 링크를 둔다.

### 4.5 분류와 특수 페이지

- `/category/{slug}/`: 분야별 분류
- `/glossary/`: 가나다·영문 알파벳 용어 색인
- `/special/all-pages/`: 전체 문서
- `/special/recent/`: 최근 추가·수정 문서
- `/special/random/`: 무작위 백과 문서
- `/search/?q=`: 통합 검색

기존 `/concepts/*`, `/courses/*` 주소는 새 주소로 리디렉션하거나 이전 주소 안내를 제공한다.

## 5. 메인 화면 정보 구조

위키백과형 밀도와 탐색 방식을 참고하되 AI Learning Wiki의 코스 기능을 함께 제공한다.

### 5.1 데스크톱 구조

```text
┌────────────────────────────────────────────────────────────────────┐
│ AI Learning Wiki        [ 전체 문서 검색................ ] [검색] │
├──────────────┬─────────────────────────────────────────────────────┤
│ 주 메뉴      │ AI Learning Wiki                                    │
│ 대문         │ AI·LLM 백과 문서 / 실습 가이드 / 프롬프트 수치      │
│ 전체 문서    ├───────────────────────┬─────────────────────────────┤
│ 최근 변경    │ 분야별 백과 탐색      │ 오늘의 문서·최근 갱신        │
│ 무작위 문서  │ AI 기초 / 모델 구조   │ 제목 + 2~3문단 + 관련 링크   │
│ 용어 색인    │ 학습·추론 / API ...   │                             │
│              ├───────────────────────┴─────────────────────────────┤
│ 학습         │ 목표별 학습 코스                                     │
│ 코스         │ [처음 시작] [업무] [빌더] [엔지니어] ...             │
│ 프롬프트     │ 선택한 코스의 권장 순서: 1. 문서  2. 실습  3. ...    │
│              ├─────────────────────────────────────────────────────┤
│ 안내         │ 새 문서 / 많이 연결된 문서 / 프롬프트 바로가기      │
└──────────────┴─────────────────────────────────────────────────────┘
```

### 5.2 메인 화면 구획

1. **상단:** 텍스트 워드마크, 전역 검색창, 검색 버튼
2. **좌측 메뉴:** 대문, 전체 문서, 최근 변경, 무작위 문서, 용어 색인, 코스, 프롬프트, 문서 안내
3. **소개 구획:** 백과 문서·실습 가이드·프롬프트의 실제 수량과 마지막 갱신일
4. **분야별 탐색:** 10~14개 대분류와 대표 문서 링크
5. **오늘의 문서:** 독립 백과 문서의 일부와 관련 문서
6. **코스 선택:** 8개 코스를 텍스트 탭 또는 단순 목록으로 제공
7. **권장 순서:** 선택한 코스의 첫 단계부터 순서대로 표시
8. **최근 갱신:** 새로 추가되거나 검토된 백과 문서 목록

코스를 선택하지 않은 초기 상태에서도 분야별 탐색, 전체 문서, 검색, 오늘의 문서를 바로 사용할 수 있어야 한다.

### 5.3 모바일 구조

- 상단에 워드마크와 검색을 유지한다.
- 좌측 메뉴는 페이지 상단의 단순한 메뉴 열기 버튼으로 접는다.
- 본문 구획은 한 열로 표시한다.
- 코스 순서는 표 대신 번호 목록으로 표시한다.
- 별도의 모달은 사용하지 않고 문서 흐름 안에서 메뉴가 펼쳐진다.

## 6. 백과 문서 화면

```text
문서명
영문명 · 약어 · 다른 이름
한 문단 정의
────────────────────────────────────
목차                 오른쪽: 문서 정보 표 또는 목차
1. 개요
2. 작동 원리
3. 주요 파라미터
4. 한계
5. 관련 문서
6. 참고 문헌
────────────────────────────────────
분류 / 포함 코스 / 역링크 / 최근 검토일
```

화면 원칙:

- 본문 폭은 읽기 좋은 범위로 제한하되 지나치게 좁히지 않는다.
- 제목, 소제목, 문단, 목록, 표, 코드만으로 계층을 만든다.
- 링크 색상은 일관된 파란색을 사용한다.
- 문서 우측에는 필요한 경우에만 정보 표나 목차를 둔다.
- 학습 완료 버튼은 백과 문서에 띄우지 않는다. 코스 화면의 순서 목록 안에서만 진도를 표시한다.
- “이 문서를 가리키는 문서”, “관련 문서”, “이 문서를 포함하는 코스”를 하단에 제공한다.

## 7. 시각 디자인 기준

### 유지

- 반응형 레이아웃
- 키보드 접근성
- 명확한 검색과 링크
- 밝은·어두운 테마를 유지할 경우 동일한 정보 밀도

### 제거

- splash hero
- 장식용 SVG 아이콘
- 카드 상승 호버 효과
- 그림자와 글로우
- 큰 둥근 모서리
- 알약형 배지 남용
- 모달 기반 선택 화면
- 고정된 플로팅 완료 버튼
- 의미 없는 영문 kicker 문구

### 기본 디자인 토큰

| 항목 | 기준 |
|---|---|
| 배경 | 흰색 또는 매우 옅은 회색 |
| 본문 | `#202122` 계열 |
| 보조 글자 | `#54595d` 계열 |
| 링크 | `#3366cc` 계열 |
| 경계선 | `#a2a9b1` 또는 더 옅은 회색 |
| 강조 배경 | 매우 옅은 회색·청색, 정보 의미가 있을 때만 |
| 모서리 | 0~3px |
| 그림자 | 사용하지 않음 |
| 애니메이션 | 사용하지 않음 |

로고도 별도 장식 SVG 대신 텍스트 워드마크를 우선한다.

## 8. 데이터 모델 개편

### 8.1 백과 문서 스키마

```json
{
  "id": "transformer",
  "title": { "ko": "트랜스포머" },
  "englishTitle": "Transformer",
  "aliases": ["Transformer architecture"],
  "summary": { "ko": "..." },
  "sections": [
    { "id": "overview", "title": { "ko": "개요" }, "body": { "ko": "..." } }
  ],
  "categories": ["model-architecture"],
  "prerequisites": ["neural-network", "embedding"],
  "related": ["attention", "self-attention", "encoder-decoder"],
  "seeAlso": ["large-language-model"],
  "sources": [
    { "title": "...", "url": "...", "type": "paper" }
  ],
  "status": "reviewed",
  "volatility": "evergreen",
  "reviewedAt": "2026-07-12"
}
```

필수 추가 개념:

- `aliases`: 검색과 리디렉션용 별칭
- `categories`: 대분류·하위 분류
- `prerequisites`: 선행 개념
- `related`, `seeAlso`: 의미 관계
- `sources[]`: 복수 출처와 자료 유형
- `status`: `stub`, `draft`, `reviewed`
- `volatility`: `evergreen`, `periodic`, `fast-changing`
- `reviewedAt`: 최신성 검토일

### 8.2 코스 스키마

```json
{
  "id": "ai-engineer",
  "title": { "ko": "AI 엔지니어" },
  "audience": { "ko": "..." },
  "steps": [
    { "type": "article", "ref": "token", "required": true },
    { "type": "article", "ref": "transformer", "required": true },
    { "type": "guide", "ref": "ai-engineer/api-first-call", "required": true },
    { "type": "prompt-set", "ref": "api-debugging", "required": false }
  ]
}
```

추천 엔진은 코스 폴더의 파일 순서가 아니라 이 참조 그래프를 읽는다.

### 8.3 프롬프트 분리

현재 모듈 내부 `prompts[]`는 단계적으로 독립 프롬프트 레코드로 분리한다. 기존 모듈은 프롬프트 ID만 참조하며, 동일 프롬프트가 여러 문서에 중복 저장되지 않게 한다.

6. 학습·사후학습·파인튜닝
7. 추론·서빙·최적화
8. 임베딩·검색·RAG
9. API·SDK·도구 호출
10. 에이전트·자동화·MCP
11. 멀티모달·음성·이미지·영상

각 대분류는 개요 문서, 핵심 문서, 하위 분류, 관련 코스를 가진다.

## 10. 콘텐츠 확장 목표

문서 수보다 분류체계의 빈칸과 연결 품질을 우선한다. 장기 목표는 다음과 같이 잡는다.

| 단계 | 검토 완료 백과 문서 | 목적 |
|---|---:|---|
| 핵심판 | 150 | AI·LLM을 이해하는 데 반드시 필요한 용어 완성 |
| 표준판 | 500 | 실무·개발·모델 구조·안전 분야의 주요 개념 포괄 |
| 확장판 | 1,000+ | 세부 알고리즘, 파라미터, 구현 기술, 모델 생태계까지 확장 |

현재 537개 개념 슬러그는 곧바로 백과 문서로 승격하지 않는다. 다음 절차를 거친다.

1. 별칭과 중복 개념 병합
2. 너무 넓거나 모호한 태그 제거
3. 표준 문서명 결정
4. 분류와 선행 관계 지정
5. 독립 설명과 출처 작성
6. 링크·역링크·고립 문서 검사
7. 검토 완료 후 백과 문서 수에 포함

### 핵심판 우선 문서 예시

- 인공지능, 머신러닝, 딥러닝, 신경망
- 파라미터, 하이퍼파라미터, 가중치, 편향
- 토큰, 토크나이저, 어휘 집합, 컨텍스트 윈도우
- 임베딩, 벡터, 코사인 유사도
- 트랜스포머, 어텐션, 셀프 어텐션, 인코더, 디코더
- 대규모 언어 모델, 소규모 언어 모델, 혼합 전문가 모델
- 사전학습, 지도 미세조정, RLHF, DPO, LoRA, 증류, 양자화
- 추론, temperature, top-k, top-p, repetition penalty, seed
- API, REST, SDK, 스트리밍, 구조화 출력, 도구 호출
- RAG, 청킹, 리랭킹, 벡터 데이터베이스
- 에이전트, 계획, 메모리, 오케스트레이션, MCP
- 환각, 프롬프트 인젝션, 가드레일, 평가, 벤치마크

## 11. 콘텐츠 품질 기준

백과 문서 공개 조건:

- 제목과 별칭이 표준화되어 있다.
- 첫 문단만 읽어도 용어를 독립적으로 이해할 수 있다.
- 광고성·벤더 편향 없이 중립적으로 작성되어 있다.
- 최소 하나의 1차·공식 출처가 있다. 논쟁적이거나 빠르게 변하는 주제는 복수 출처를 사용한다.
- 관련 개념과 선행 개념이 연결되어 있다.
- 출처 없는 가격, 순위, 최신 모델 성능을 고정 사실처럼 쓰지 않는다.
- 빠르게 변하는 문서는 기준일과 검토 주기를 표시한다.
- 문서 상태가 `reviewed`일 때만 공식 백과 문서 수에 포함된다.

자동 검사 항목:

- 깨진 내부 링크와 존재하지 않는 참조
- 문서명·별칭·리디렉션 충돌
- 고립 문서
- 순환 리디렉션
- 출처 없는 문서
- 검토 기한이 지난 빠른 변경 문서
- 한 문서에서 정의되지 않은 핵심 용어 과다 사용

## 12. 구현 단계

### W0. 정보 구조와 스키마 확정

- 백과 문서, 가이드, 코스, 프롬프트 스키마 분리
- URL, 리디렉션, 별칭 규칙 확정
- 14개 대분류와 핵심판 150개 문서 목록 확정

완료 조건: 샘플 백과 문서 10개가 새 스키마 검증을 통과한다.

### W1. 위키형 공통 레이아웃

- splash hero와 장식 카드 제거
- 텍스트 워드마크, 전역 검색, 좌측 메뉴 구현
- 문서용 본문·목차·정보 표·참고 문헌 레이아웃 구현
- 플로팅 완료 버튼과 장식 효과 제거

완료 조건: 메인, 백과 문서, 가이드, 코스 화면이 동일한 위키 탐색 체계를 사용한다.

### W2. 메인 화면과 특수 페이지

- 분야별 탐색, 오늘의 문서, 최근 갱신 구현
- 전체 문서, 용어 색인, 무작위 문서 구현
- 메인 코스 선택과 권장 순서 구현

완료 조건: 코스 선택 없이 검색 또는 두 번 이내 클릭으로 모든 문서에 접근할 수 있다.

### W3. 문서 그래프와 통합 검색

- 제목·별칭·본문·프롬프트 통합 검색
- 선행·관련·역링크·포함 코스 생성
- 고립 문서와 깨진 링크 검사

완료 조건: 대표 용어 30개 검색에서 정확한 문서가 첫 결과로 나온다.

### W4. 기존 305개 가이드 이관

- 기존 모듈 URL을 `/guide/` 체계로 이관
- 개념 설명 중복을 백과 링크로 치환
- 기존 주소 리디렉션 제공
- 프롬프트 관계 유지

완료 조건: 기존 305개 가이드와 1,173개 프롬프트가 유실 없이 접근된다.

### W5. 코스 추천 구조 개편

- 코스가 백과·가이드·프롬프트를 참조하도록 변경
- 메인 화면과 코스 화면에 권장 순서 제공
- 진도는 코스 화면 안에서만 표시

완료 조건: 서로 다른 목표가 서로 다른 첫 학습 순서를 제공하고, 같은 백과 문서를 중복 생성하지 않는다.

### W6. 핵심 백과 150개 제작

- 핵심 용어 목록을 묶음별로 작성·검토
- 출처, 별칭, 관계, 분류 입력
- 537개 기존 개념 슬러그를 병합·리디렉션·보류로 분류

완료 조건: 150개 문서가 `reviewed`이며 출처·관련 문서·분류를 모두 갖춘다.

### W7. 확장과 운영

- 표준판 500개, 확장판 1,000개 이상으로 단계적 확대
- 최근 변경, 검토 만료, 통계 페이지 운영
- 빠른 변경 문서의 주기적 검토

## 13. 개편 수용 기준

- 첫 화면 최상단에 전역 검색이 보인다.
- 코스를 선택하지 않아도 백과 문서 전체를 탐색할 수 있다.
- 메인 화면에서 8개 코스와 각 코스의 권장 순서를 볼 수 있다.
- 독립 백과 문서와 실습 가이드가 URL·화면·검색 결과에서 구분된다.
- 문서 본문에서 핵심 용어가 다른 백과 문서로 연결된다.
- 모든 백과 문서에 관련 문서, 분류, 출처, 최근 검토일이 있다.
- 장식용 SVG, 글로우, 그림자, 이동 호버, 모달 탐색, 플로팅 완료 버튼이 없다.
- 모바일에서도 검색과 문서 본문이 첫 번째 정보 우선순위를 유지한다.
- 기존 305개 가이드와 1,173개 프롬프트가 유실되지 않는다.
- 리디렉션을 포함한 내부 링크 검사가 오류 없이 통과한다.

## 14. 이번 기획에서 하지 않는 것

- 150개 이상의 백과 본문을 한 번에 자동 생성하지 않는다.
- 기존 537개 개념 슬러그를 검토 없이 독립 백과 문서로 간주하지 않는다.
- 사용자 편집, 토론, 계정, 문서 이력 시스템은 이번 개편의 필수 범위에 넣지 않는다.
- 장식 요소를 대체하기 위한 새로운 일러스트나 아이콘 세트를 만들지 않는다.
- 기존 실습 데이터를 삭제하거나 백과 문서로 억지 변환하지 않는다.

첫 구현은 W0부터 W2까지 진행하여 위키형 골격과 10개 샘플 백과 문서를 완성한 뒤, 문서 구조를 검증하고 W3 이후의 대량 이관으로 넘어간다.
