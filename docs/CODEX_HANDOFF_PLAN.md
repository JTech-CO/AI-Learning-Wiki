# Codex 이관 및 완성 계획

기준일: 2026-07-12  
대상: EduVerse 기반 AI Learning Wiki

## 1. 목표

EduVerse 운영 측과 합의된 범위의 학습 데이터를 정규화하고, 자체 제작 데이터와 결합해 다음을 제공한다.

- AI 개념·도구·실습·프롬프트를 한곳에서 검색하고 서로 연결할 수 있는 위키
- 목표, 현재 수준, 가용 시간에 따라 학습 순서가 달라지는 개인화 로드맵
- 학습 진도, 실습 결과, 자기 점검을 이어서 사용할 수 있는 학습 경험
- 원본 수집부터 검증, 사이트 빌드, 배포까지 다시 실행 가능한 파이프라인

현재 구현은 이 중 **정적 위키와 콘텐츠 모델의 골격**까지 갖췄다. 개인화 기능은 아직 구현되지 않았다.

## 2. 현재 저장소 감사 결과

### 기술 구조

```text
EduVerse 화면/운영자 export
  -> 원본 캡처(raw)
  -> 정규화 모듈(content-model/data/*.module.json)
  -> 페이지 생성(scripts/build-pages.mjs)
  -> Astro Starlight + Pagefind(dist)
```

- 프런트엔드: Astro 7 + Starlight
- 정규 데이터 계약: `content-model/schema.module.json`, `schema.course.json`
- 생성기: `scripts/build-pages.mjs`
- 이전 수집 보조 서버: `scripts/crawl/collector.py`
- Git 상태: `main`, 아직 커밋 없음. 전체 파일이 untracked 상태다.

### 실제 파싱 진척

`content-model/data`에 JSON 170개가 있다. 모두 JSON 파싱에 성공하며 ID·코스/순번 중복과 빈 본문은 발견되지 않았다.

| 코스 | 기준 개수 | 현재 | 남음 | 상태 |
|---|---:|---:|---:|---|
| 시작 코스 | 8 | 8 | 0 | 완료 |
| AI 입문 | 44 | 44 | 0 | 완료 |
| AI 실무 | 48 | 48 | 0 | 완료 |
| AI 빌더 | 44 | 44 | 0 | 완료 |
| AI 엔지니어 | 49 | 26 | 23 | 진행 중 |
| 자동화 개발 | 42 | 0 | 42 | 대기 |
| AI 금융 | 55 | 0 | 55 | 대기 |
| AI 트렌드 | 15 | 0 | 15 | 대기 |
| **합계** | **305** | **170** | **135** | **55.7%** |

마지막 정규 데이터는 **AI 엔지니어 26번 `임베딩과 코사인 유사도`**다. 다음 재개 지점은 라이브 화면에서 엔지니어 코스를 다시 열어 순번과 제목을 대조한 뒤 **27번부터**다.

사용자가 기억한 166개는 엔지니어 22번까지의 합계와 정확히 일치한다. 그 뒤 23~26번 4개가 저장되어 현재는 170개다.

### 반드시 먼저 해소할 불일치

1. 이전 `scripts/crawl/PLAN.md`는 총 311개(트렌드 29개)라고 적혀 있다.
2. 현재 `courses.json`과 라이브 학습 화면은 메인 297개 + 시작 8개 = 총 305개를 가리킨다.
3. 정규 JSON은 170개지만 생성된 위키 페이지는 168개 기준이며 엔지니어 24번까지만 있다.
4. `dist`는 2026-07-09 빌드라 정규 JSON보다 더 오래됐다.
5. README와 설계 문서는 아직 “실제 데이터 확보 전” 상태를 설명한다.

따라서 `content-model/data`를 현재 작업의 원본으로 보존하고, 페이지와 `dist`를 원본으로 역수정하지 않는다.

### 데이터 품질상 확인된 공백

- 170개 모두 한국어만 있다. 현재 다국어 메뉴는 실제 번역 완성도를 나타내지 못한다.
- `source.url`이 있는 모듈은 10개뿐이고 `capturedAt`, `updatedAt`은 전부 비어 있다.
- 스키마 파일은 있지만 모든 데이터에 강제 적용하는 validator/CI가 없다.
- 170개 모듈에 복붙 프롬프트 681개가 있으나, 스키마상 `text` 하나뿐이라 **템플릿과 채워진 예시를 구분할 수 없다.** “예제로 안내한 프롬프트가 예제 영역에 없는” 문제를 구조적으로 막지 못한다.
- 원문 캡처(`content-model/raw`)가 남아 있지 않아 정규화 결과를 원문과 자동 대조할 수 없다.
- `build-pages.mjs`는 생성 디렉터리를 지우고 다시 쓰므로, Git 기준점 없이 실행하면 기존 생성물을 안전하게 비교·복원하기 어렵다.

## 3. 작업 원칙

1. **원본 캡처와 AI 정규화를 분리한다.** 화면에서 읽은 전문을 먼저 raw 파일로 저장하고, 그 다음 정규 JSON을 만든다.
2. **한 모듈이 끝날 때마다 체크포인트를 남긴다.** 장시간 세션이나 도구 중단이 발생해도 마지막 완료 지점 다음부터 재개한다.
3. **사이트 화면, raw, 정규 JSON, 생성 페이지를 서로 다른 계층으로 취급한다.** 생성물을 원본처럼 수정하지 않는다.
4. **프롬프트 템플릿과 예시를 추측해 섞지 않는다.** 원문에 예시가 없으면 `examples: []`로 명시한다.
5. **인증정보·세션 토큰·Supabase 키를 저장하거나 재사용하지 않는다.** 합의된 화면 수집 또는 운영자 export만 사용한다.
6. **한국어 완성본을 먼저 출시한다.** 번역되지 않은 언어 메뉴는 숨기고, 다국어는 별도 검수 단계를 통과한 뒤 연다.

## 4. 단계별 완성 로드맵

### 0단계 — 이관 안정화

- 현재 170개 JSON과 프로젝트 파일을 최초 Git 기준점으로 보존한다.
- 운영 측 합의 범위, 허용된 데이터·수집 방식·내부/외부 공개 범위를 저장소 문서에 기록한다.
- README, ARCHITECTURE, EXTRACTION, 크롤 계획의 오래된 개수와 상태를 현재 기준으로 갱신한다.
- `progress.json`을 추가해 코스별 기대 개수, 완료 순번, 마지막 검증 시각, 다음 재개점을 기계가 읽을 수 있게 한다.

완료 조건: 새 세션이 문서와 `progress.json`만 읽고도 질문 없이 엔지니어 27번부터 재개할 수 있다.

### 1단계 — 검증 가능한 콘텐츠 파이프라인

- JSON Schema validator를 추가한다.
- 다음 검사를 하나의 명령으로 묶는다.
  - JSON/schema 오류
  - ID와 코스/순번 중복
  - 1부터 `moduleCount`까지의 누락
  - 빈 제목·본문·프롬프트·미션·루브릭
  - 파일의 디렉터리/ID/course 불일치
  - 잘못된 개념 링크와 생성 페이지 링크
  - 출처와 캡처 시각 누락
- 빌드 순서를 `validate -> build-pages -> astro build -> link/search smoke test`로 고정한다.
- 생성 페이지와 `dist`는 정규 JSON에서만 다시 만들 수 있게 하고 수동 편집을 금지한다.

완료 조건: 잘못된 샘플 데이터가 의도대로 빌드를 실패시키고, 현재 정상 데이터는 검증을 통과한다.

### 2단계 — 프롬프트/예제 모델 보강

`prompts[]`를 최소 다음 의미로 분리한다.

```json
{
  "title": { "ko": "..." },
  "template": { "ko": "복붙용 [변수] 포함 프롬프트" },
  "examples": [
    {
      "label": { "ko": "작성 예시" },
      "input": { "ko": "변수를 채운 실제 입력" },
      "output": { "ko": "기대 결과 또는 결과 형식" }
    }
  ],
  "notes": { "ko": "사용 조건과 주의점" }
}
```

- 기존 `text` 681개를 `template`로 무손실 이관한다.
- 원문에 실제 예시가 확인된 경우에만 `examples[]`를 채운다.
- 페이지 생성기에서 “복사”, “변수”, “작성 예시”, “기대 결과”를 별도 UI로 렌더링한다.

완료 조건: 모든 프롬프트 페이지에서 템플릿과 예시의 존재 여부가 명확하고, 빈 예시를 생성하거나 암시하지 않는다.

### 3단계 — 남은 135개 수집

우선순위는 다음과 같다.

1. 운영자 export가 가능하면 export를 raw 원본으로 보존하고 정규화한다.
2. export가 없으면 라이브 화면의 렌더된 레슨 모달을 순차 수집한다.
3. 각 모듈은 `raw 저장 -> 정규화 -> validator -> progress 갱신`의 원자 작업으로 처리한다.

작업 묶음:

| 묶음 | 범위 | 개수 |
|---|---|---:|
| A | AI 엔지니어 27~49 | 23 |
| B | 자동화 개발 1~42 | 42 |
| C | AI 금융 1~55 | 55 |
| D | AI 트렌드 1~15 | 15 |

AI 트렌드는 주기적으로 바뀌므로 고정 완료 데이터가 아니라 `capturedAt`과 갱신 정책이 있는 스냅샷으로 다룬다. 각 묶음이 끝날 때 코스별 순번·제목을 라이브 화면과 다시 대조하고 전체 검증을 실행한다.

완료 조건: 현재 라이브 매니페스트 기준 모든 순번이 존재하고, 누락·중복·스키마 오류가 0개다.

### 4단계 — 위키 탐색성과 콘텐츠 품질

- 홈에서 코스뿐 아니라 목표/직무/난이도/예상 시간별 진입점을 제공한다.
- 개념 사전의 자동 생성 제목을 한국어 표제어로 보강한다.
- 모듈 ↔ 개념 ↔ 프롬프트 ↔ 도구의 양방향 링크를 만든다.
- 검색 결과에 콘텐츠 유형, 코스, 난이도, 예상 시간을 표시한다.
- 오래된 모델명·가격·제품 기능처럼 변동 가능한 정보에는 확인일을 표시한다.
- 중복/유사 개념, 모델 편향, 출처 불명확 문장을 콘텐츠 QA 목록으로 관리한다.

완료 조건: 대표 검색어와 초보/실무/개발자 시나리오에서 3번 이내의 이동으로 필요한 레슨이나 프롬프트에 도달한다.

### 5단계 — 학습자 맞춤 기능

정적 문서만으로는 “학습자 맞춤형” 목표를 충족하지 못하므로 다음 앱 계층을 추가한다.

- 첫 방문 진단: 목표, 현재 수준, 관심 직무, 주당 학습 가능 시간
- 추천 엔진 v1: 규칙 기반으로 선행 모듈과 다음 학습 3개를 설명과 함께 제시
- 진도: 완료, 보류, 다시 보기, 실습 제출 여부
- 개인 로드맵: 주차별 계획과 예상 소요 시간
- 대시보드: 전체 진도보다 “지금 할 일”을 우선 표시
- 초기에는 `localStorage` 기반 익명 프로필, 이후 필요할 때만 계정 동기화

추천 규칙은 코드와 테스트로 관리하고, 생성형 AI가 임의로 선수 관계를 바꾸지 않게 한다. AI 설명/튜터 기능을 추가할 경우 위키의 근거 링크를 함께 보여준다.

완료 조건: 서로 다른 두 학습 프로필이 다른 첫 로드맵을 받고, 새로고침 후 진도와 다음 추천이 유지된다.

### 6단계 — 출시 QA와 운영

- 깨끗한 checkout에서 install/build가 재현되는지 확인한다.
- 모바일·키보드·스크린리더·색 대비를 점검한다.
- Pagefind 대표 질의와 링크 무결성 테스트를 자동화한다.
- 운영 측 합의 범위에 맞는 접근 제어와 저작권/출처 표기를 적용한다.
- 백업, 롤백, 오류 모니터링, 트렌드 갱신 주기를 문서화한다.
- CI에서 schema, content coverage, build, smoke test를 모두 통과해야 배포하도록 한다.

완료 조건: 배포 URL에서 핵심 사용자 흐름이 통과하고, 동일 커밋을 다시 빌드해 같은 콘텐츠 결과를 만들 수 있다.

## 5. 전체 완료 정의

다음 항목이 모두 충족될 때 프로젝트를 “완성”으로 본다.

- 라이브 기준 305개 또는 이후 갱신된 공식 매니페스트 전체가 수집·검증됨
- 누락, 중복, JSON/schema 오류, 깨진 내부 링크가 모두 0개
- 각 모듈에 출처 방식과 캡처 시각이 기록됨
- 프롬프트 템플릿과 실제 예시가 구조적으로 구분됨
- 한국어 검색, 코스 로드맵, 개념 역링크가 정상 동작함
- 학습 프로필에 따라 다음 학습 경로가 달라지고 진도가 유지됨
- 깨끗한 환경에서 한 명령으로 검증·빌드·배포 가능한 상태
- 운영 범위, 데이터 갱신, 트렌드 유지보수, 롤백 절차가 문서화됨

## 6. 바로 이어서 할 순서

1. 현재 상태를 최초 Git 기준점으로 보존한다.
2. `progress.json`과 validator를 먼저 만든다.
3. 프롬프트 스키마 변경과 기존 681개 무손실 마이그레이션을 끝낸다.
4. 생성 페이지를 170개 데이터와 동기화하고 로컬 빌드로 회귀를 확인한다.
5. 라이브 코스 목록을 다시 읽어 엔지니어 27번의 제목을 확정한 뒤 남은 수집을 재개한다.
6. 콘텐츠 완성 후 탐색성, 개인화, 출시 QA 순으로 진행한다.

이 순서를 지키면 이전처럼 브라우저나 장시간 세션이 중단되어도 데이터 손실 없이 정확한 다음 순번에서 다시 시작할 수 있다.
