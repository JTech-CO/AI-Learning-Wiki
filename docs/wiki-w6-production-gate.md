# W6 검토 확대와 1,400개 제작 게이트

W6는 14개 주 분류에서 세 번째 핵심 문서를 문장 단위로 검토해 누적 게시 준비 문서를 42개로 늘리고, W0의 1,400개 표제어를 실제 제작 상태에 연결한다. 문서 수만 늘리기 위해 초안이나 출처 후보를 게시 상태로 취급하지 않는다.

## 게시 준비 범위

- W4·W5·W6 승인 원장에 본문 해시와 문장 해시가 잠긴 문서만 `published`다.
- 각 분류의 게시 준비 문서는 정확히 3개이며, 누적 42개다.
- W6 신규 묶음은 독립 출처 계열 3개 이상, 공식·논문·표준 출처 1개 이상, 백과 계열 1개 이상을 갖는다.
- 일반 빌드는 승인 원장을 다시 만들지 않는다. 본문이나 출처 순서가 바뀌면 검증이 실패하며 명시적인 재검토가 필요하다.

## 제작 큐 상태

1. `research-queued`: 신규 후보 1,250개. 본문 작성, 출처 관련성 확인, 문장 검토가 모두 남아 있다.
2. `source-remediation`: 기존 문서 가운데 출처 계열·백과·공식 자료 또는 도달성 보강이 필요한 상태다.
3. `claim-review-queued`: 출처 게이트는 통과했지만 문장 단위 승인 원장이 아직 없는 상태다.
4. `published`: 출처 게이트와 문장 단위 검토를 모두 통과한 상태다.

56개 조사 배치는 1,400개 표제어를 한 번씩만 포함한다. 제작 큐는 분류별 100개, 기존 150개, 신규 후보 1,250개, 게시 준비 42개라는 수량을 매 빌드에서 검증한다. 신규 후보는 승인 원장 없이 게시 상태로 이동할 수 없다.

## 다음 실행 순서

남은 기존 108개는 `source-remediation`과 `claim-review-queued` 사이에서 출처를 보강한 뒤 분야별 묶음으로 승인한다. 신규 1,250개는 core, standard, brief 순으로 작성하되 W1 조사 카드의 실제 문서·논문·공식 명세를 읽고 관련성을 확인한 뒤 같은 문장 단위 게이트를 적용한다.
